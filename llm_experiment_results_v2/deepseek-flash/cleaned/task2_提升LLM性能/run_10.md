结论：不训练模型也能“大幅提升”的方向不是调权重，而是做 **推理时系统工程**：检索增强、结构化提示、工具调用、自检/投票、缓存/路由、评测闭环。提升幅度取决于任务；对知识时效、私域数据、精确计算、格式约束、复杂推理类任务，收益通常最大。

最划算的组合可以概括为：

> **性能 ≈ 模型能力 × 上下文质量 × 工具能力 × 验证选择机制 ÷ 噪声与成本**

## 1. 最优先做：轻量 RAG
适合：私域知识、最新信息、客服问答、文档分析、政策法规、产品手册。

低成本做法：
- 文档切块：按标题/段落切，保留元数据与来源。
- 混合检索：BM25/关键词 + 向量检索，先召回再重排。
- 查询改写：把用户问题改成 1—3 个检索式。
- 只取最相关 3—8 个片段，宁少勿多，避免噪声污染。
- 强制引用来源；找不到证据就拒答或追问。
- 加轻量 rerank，比盲目扩大上下文更有效。

收益：显著减少幻觉，提升事实性和领域回答质量。  
注意：RAG 不是把所有文档塞进去，噪声越多效果可能越差。

## 2. 结构化提示与上下文工程
适合：几乎所有任务，成本最低。

建议模板：
1. 角色：你是谁、服务谁。  
2. 任务：要完成什么。  
3. 输入：资料、约束、边界。  
4. 步骤：先拆解，再检查，再输出。  
5. 输出格式：JSON/Markdown/表格/字段说明。  
6. 成功标准：准确性、完整性、长度、风格。  
7. 不确定策略：缺信息时先追问，禁止编造。  

高性价比技巧：
- 给 2—5 个高质量 few-shot 示例。
- 用分隔符隔离“指令”和“资料”。
- 对复杂任务先让模型列计划，但最终答案不要暴露冗长思维链。
- 要求“先自查，再给最终答案”。
- 对格式敏感任务使用 JSON Schema、正则、函数调用约束。

## 3. 自一致性 + 验证器
适合：分类、抽取、数学、逻辑、代码、事实问答。

低成本做法：
- 对难题采样 3—5 个答案，投票或让评审模型选最佳。
- 简单题只跑 1 次；难题才多采样，控制成本。
- 代码任务直接跑单元测试。
- JSON 任务用 schema 校验。
- 事实任务做引用核验：答案每句话能否被证据支持。
- 用便宜模型生成草稿，用强模型做“评审/修正”。

收益：通常比单纯换更强模型更便宜，尤其适合高价值低并发场景。

## 4. 工具调用：把不擅长的外包出去
LLM 不擅长精确计算、实时信息、数据库查询、文件操作。能外包就外包：
- 搜索：时效信息。
- 计算器/代码解释器：数值、数据处理。
- 数据库/API：业务数据。
- 日历/邮件/文档工具：执行任务。
- OCR/表格解析：非结构化输入。

原则：**模型负责理解与编排，工具负责精确与最新。**

## 5. 缓存、路由与级联
用来降成本，从而允许你在关键环节多调用几次。
- 语义缓存：相似问题直接复用答案。
- 提示缓存：固定长系统提示/文档前缀复用。
- 难度路由：简单问题走小模型，复杂问题走大模型。
- 级联回退：小模型先答，置信度低或校验失败再升级大模型。
- 批处理：离线任务合并请求。

这不会直接提升单次上限，但会显著改善“单位成本下的效果”。

## 6. 建一个小评测集
没有评测，提示词优化就是玄学。
最低成本做法：
- 收集 30—100 个真实问题，标注期望答案/评分标准。
- 指标：准确率、引用正确率、格式通过率、拒答正确率、平均成本、延迟。
- 每次改提示/RAG/投票策略都跑一遍。
- 按错误类型分类：缺知识、检索错、推理错、格式错、过度自信、指令不服从。
- 只针对最大错误类型加机制。

## 推荐落地顺序
1. **先评测**：30—100 条样本，找最大短板。  
2. **加结构化提示 + few-shot + 输出校验**：成本最低，立刻见效。  
3. **知识不足就上 RAG**：混合检索 + 重排 + 引用 + 拒答。  
4. **精确任务上工具**：计算、代码、数据库、搜索。  
5. **高价值难题加自一致性和验证器**：只对难题多采样。  
6. **最后加缓存/路由/级联**：降成本，扩大调用预算。  

## 一句话方案
如果你的目标是“低成本、不训练、尽量大幅提升”，优先做：

> **轻量 RAG + 结构化提示 + 输出校验 + 难题自一致性/评审 + 工具调用 + 缓存路由 + 小评测闭环。**

多数场景下，这套组合比单纯换更大模型更便宜，也更容易针对业务快速迭代。注意：如果任务本身已接近模型能力上限，提升会有限；但对知识时效、私域数据、精确计算、格式约束和可验证推理，收益通常很明显。
