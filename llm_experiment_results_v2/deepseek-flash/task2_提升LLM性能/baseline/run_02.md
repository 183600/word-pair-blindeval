# [v2:deepseek-flash] 任务2 提升LLM性能 | 条件: baseline | 第 2 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 15.54s | tokens: 41/2506

---

先给结论：**不训练模型时，提升来自“推理系统工程”：更好的上下文、检索、工具、验证、采样与路由**。其中 ROI 最高的是：**小评测集 + 提示契约 + RAG/工具 + 自一致性/验证器 + 缓存与路由**。但“性能”必须按任务定义；没有一种方法在所有任务上都大幅提升。

## 1. 先建一个 30–100 条的小评测集
不做训练也可以做“数据驱动调优”。收集真实请求，定义指标：正确率、引用准确率、格式合规率、延迟、token 成本。每加一招都跑同一套 eval，否则很容易“感觉变好”。

## 2. 低成本高收益组合，按优先级

### ① 提示契约 + Few-shot + 结构化输出
强制模型输出 JSON/Markdown 模板，明确：
- 任务边界、可用信息、禁止编造
- 输出字段和校验规则
- 2–5 个高质量示例
- 不确定时如何回答/要求澄清

适合所有任务，成本几乎为 0，格式和稳定性提升明显。

### ② RAG：检索增强生成
对知识型、文档型、客服、代码库问答，**RAG 通常比换更大模型更划算**。低成本做法：
1. 查询改写/多查询
2. 混合检索：BM25 + 向量检索
3. 用现成 reranker 重排 top 20 → top 3–5
4. 上下文压缩：只放相关句段
5. 要求逐条引用来源
6. 检索不到就拒答或澄清

不需要训练 LLM；embedding/reranker 用现成模型即可。

### ③ 推理时扩展：CoT、自一致性、Best-of-N + 验证器
适合数学、逻辑、代码、规划等。
- 简单题：单次回答
- 难题：采样 3–10 个答案，投票或让验证器选最佳
- 代码/数学：用执行器、单测、计算器验证
- 让 LLM 自己先写检查清单，再回答，再按清单自检

注意：Self-Consistency 成本是 N 倍。低成本策略是**只对高不确定/高价值 query 启用**，用 logprobs、规则或小模型判断难度。

### ④ 工具调用 / ReAct
让模型调用搜索、计算器、数据库、代码解释器、业务 API、单测。对事实、计算、实时信息、代码执行类任务，工具带来的是“质变”，不是单纯 prompt 能比。

### ⑤ 验证器与重试
生成后做：
- JSON Schema 校验
- 正则/业务规则校验
- 引用是否支持结论
- 代码是否通过测试
- 多候选交叉验证

失败时把错误信息回填给模型重试 1–2 次。成本低，可靠性提升大。

### ⑥ 模型路由 / 级联 / 小模型预筛
不是所有请求都值得用大模型：
- 小模型处理简单分类、抽取、改写、格式化
- 大模型只处理难题或小模型置信度低的请求
- 多模型投票/辩论只用于高风险请求

这能在总成本不大涨的情况下提升平均质量。

### ⑦ 缓存与上下文管理
- 语义缓存：相似问题直接命中历史答案
- KV cache、prompt caching
- 上下文裁剪/摘要，避免无关长文档
- 批处理、并行请求
- 量化/更小模型服务简单步骤

这些主要降成本，为高价值请求释放预算。

## 3. 一个可直接落地的低成本架构

```text
用户问题
→ 语义缓存命中？→ 返回
→ 查询改写
→ 混合检索 + rerank（需要知识时）
→ 难度/置信度判断
   ├─ 简单：单次 LLM + 结构化输出
   └─ 困难：多候选采样 + 验证器/工具/投票
→ Schema/规则/引用校验
   ├─ 失败：带错误信息重试 1–2 次
   └─ 成功：返回并缓存
```

核心原则：**简单请求走便宜路径，困难请求才增加推理计算**。

## 4. 不同任务的最优组合

| 任务 | 首选方案 |
|---|---|
| 文档/知识问答 | RAG + 查询改写 + rerank + 引用 |
| 客服/业务流程 | 提示契约 + 结构化输出 + 工具 API + 校验重试 |
| 数学/逻辑 | CoT + Self-Consistency + 计算器/验证器 |
| 代码 | 检索相关代码 + 代码解释器 + 单测 + Best-of-N |
| 信息抽取 | Few-shot + JSON Schema + 规则校验 |
| 高风险决策 | 多模型投票/辩论 + 外部证据 + 人工复核 |
| 长文档 | 分块检索 + 摘要树 + 上下文压缩 |

## 5. 推荐实施顺序
1. **建 eval 集**，记录 baseline。
2. **改提示契约 + 结构化输出**：几乎零成本。
3. **加 RAG/工具**：按任务决定，通常收益最大。
4. **加验证器与重试**：提升可靠性。
5. **对难题加自一致性/Best-of-N**：用路由控制成本。
6. **加缓存、模型路由、上下文压缩**：把成本压回来。
7. **持续看指标**：准确率、格式合规率、引用准确率、P95 延迟、每请求成本。

## 6. 注意事项
- “大幅提升”通常有任务边界：RAG 对知识问答可很大；工具对计算/代码可很大；提示工程对格式和稳定性提升大，但不能让模型学会新知识。
- 多采样、多 agent、反思会显著增加 token 和延迟，必须做**自适应计算**。
- RAG 的瓶颈常在检索和切分，不在 LLM。
- 自检/反思可能“自信地犯错”，最好有外部验证器或规则。
- 不要一次性堆满所有技巧；逐项 ablation，保留有效组合。

一句话：**用评测集找短板；知识问题上 RAG，计算/实时问题上工具，推理问题上采样+验证，成本问题用路由和缓存。** 这是当前不额外训练、低成本提升现有 LLM 最稳的路线。
