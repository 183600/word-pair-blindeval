# [v2:deepseek-flash] 任务2 提升LLM性能 | 条件: baseline | 第 4 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 13.42s | tokens: 41/1975

---

不能靠“改一句提示词”就把所有任务大幅提升；但**不训练模型**时，收益最大的方向是：把 LLM 从“单次闭卷生成”改造成“带检索、工具、验证、路由和缓存的推理系统”。低成本的关键是：**只在必要样本上增加推理计算**。

下面按性价比排序。

## 1. 先做评测集，否则不知道是否提升
先构造 100～500 条真实任务金标准，记录：
- 准确率/通过率
- 格式合规率
- 幻觉率
- 平均 token 成本和延迟
- 失败类型

后续所有技巧都围绕失败类型上。没有评测的“提示词优化”大多是玄学。

## 2. 最高性价比：上下文与输出约束
### 结构化提示
固定角色、任务、输入、约束、输出 schema：
```text
你是...。只根据给定资料回答。
必须输出 JSON：{answer, evidence, confidence}
若资料不足，输出 insufficient=true。
```
适合抽取、分类、客服、报告生成。

### 动态 few-shot
不要固定示例，而是用向量检索选出与当前问题最相似的 3～5 个高质量示例插入提示。通常比手写长 prompt 更稳。

### 输出约束/解析器
用 JSON Schema、正则、枚举、函数调用约束输出；失败自动重试或修复。能显著降低下游系统错误。

### 上下文压缩
长文档先检索、重排、摘要，再喂给模型。避免“塞满上下文”导致注意力稀释和成本上升。

## 3. 检索增强 RAG：低成本大幅降低幻觉
最小方案：
1. 文档切块 300～800 token，带标题/来源元数据；
2. 向量检索 top 20；
3. cross-encoder/轻量 reranker 取 top 5；
4. 提示中要求引用证据；
5. 无证据时拒答。

提升点：
- **HyDE**：先让模型生成假设答案再检索；
- **多查询检索**：把问题改写成 3 个查询；
- **混合检索**：BM25 + 向量；
- **父子块**：小块检索、大块喂入；
- **引用校验**：答案中每个关键结论必须有 evidence id。

这是很多企业场景中“提升最大、训练成本最低”的手段。

## 4. 推理时增强：只在难题上多花算力
### Self-consistency
同一问题采样 3～5 次，投票选多数答案。适合数学、分类、判断。成本线性增加，所以只对高不确定样本用。

### Best-of-N + 验证器
生成多个候选，用规则/小模型/LLM verifier 打分选最优。验证器比生成器便宜很多。

### 自检与修复
流程：
1. 生成初稿；
2. 检查是否满足约束、是否有证据；
3. 只对失败项重写；
4. 再次校验。

比全量重试便宜。

### 分解任务
复杂任务拆成：计划 → 检索 → 执行 → 校验。适合多步推理、报告、数据分析。

### 多智能体/辩论谨慎用
debate、多角色评审能提升，但成本高。低成本替代：**单模型多轮自检 + 规则验证 + 小模型评审**。

## 5. 工具调用：把模型不擅长的交给程序
优先接入：
- 计算器/代码执行器
- SQL/API 查询
- 搜索
- 日历/CRM/工单系统
- 规则引擎
- 文档解析器

原则：**确定性计算不要交给 LLM 心算；实时数据不要靠模型记忆。**  
这通常比换更大模型更有效。

## 6. 路由：让小模型做简单事，大模型做难题
用分类器/小模型/规则先判断任务难度：
- 简单：小模型 + 模板
- 中等：小模型 + RAG
- 困难/高风险：大模型 + 多候选 + 验证器
- 不确定：升级人工或大模型

可显著降低成本，同时把预算集中到困难样本。路由依据可用：问题长度、检索置信度、输出置信度、格式校验结果、历史失败类型。

## 7. 缓存与复用
- **精确缓存**：相同输入直接返回。
- **语义缓存**：相似问题复用答案，需阈值和失效策略。
- **检索缓存**：热门查询缓存检索结果。
- **提示前缀缓存**：复用长系统提示和文档前缀。
- **工具结果缓存**：API/SQL 查询缓存。

客服、FAQ、代码助手场景收益很大。

## 8. 组合式最小可行方案
对大多数业务，先上这个 stack：

```text
用户问题
→ 任务分类/路由
→ 查询改写
→ 混合检索 + rerank
→ 结构化提示 + 动态 few-shot
→ LLM 生成 JSON
→ 规则/小模型校验
→ 失败则检索补充/重试/升级大模型
→ 引用证据输出
→ 缓存结果
```

通常能带来：幻觉下降、格式合规上升、人工返工减少、长尾任务通过率提升。是否“大幅”取决于任务，但这是低成本最高概率路径。

## 9. 成本控制策略
- 只对高不确定样本做 self-consistency / best-of-N；
- 用规则和小模型做第一道验证；
- 用 reranker 减少喂入 token；
- 用语义缓存；
- 失败重试限制 1～2 次；
- 长文档先摘要/检索，不整篇塞入；
- 用便宜模型做改写、分类、抽取、校验，大模型只做最终难例。

## 10. 推荐实施顺序
1. 建评测集和失败分类；
2. 上结构化输出、动态 few-shot、上下文压缩；
3. 上 RAG：混合检索 + rerank + 引用；
4. 上规则/小模型验证器；
5. 对高不确定样本加 self-consistency 或 best-of-N；
6. 上路由和缓存；
7. 每周根据失败样本迭代检索库、示例库、校验规则。

## 关键提醒
- **不要迷信复杂 multi-agent**：多数场景不如“检索 + 验证 + 路由”稳。
- **提示词不是数据库**：事实性问题必须外挂知识。
- **验证器比生成器更重要**：低成本提升往往来自“能发现并纠正错误”。
- **必须做 A/B 测试**：采样温度、候选数、rerank 数量都要按任务调。
- **高风险场景保留人工兜底**：医疗、法律、金融、生产变更等不要让模型自动决策。

一句话总结：**不训练模型时，最大提升来自“外部知识 + 工具 + 验证闭环 + 自适应推理预算 + 路由缓存”，而不是单纯换更长的提示词。**
