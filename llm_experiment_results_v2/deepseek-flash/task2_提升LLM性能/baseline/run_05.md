**耗时:** 12.36s | tokens: 41/1833

---

没有“零成本、无训练、普遍大幅提升”的万能方法；但如果你**不微调模型**，只改推理/系统层，确实能用较低成本获得明显收益。关键不是让模型“更聪明”，而是给它：**外部知识、可执行工具、验证机制、任务路由和缓存**。

## 最推荐的组合：RAG + 工具调用 + 自我验证 + 路由/缓存

对大多数企业/应用场景，收益最高的不是复杂 Prompt，而是这套系统：

1. **RAG 检索增强**
   - 适合：知识问答、文档分析、客服、规章制度、代码库问答。
   - 低成本做法：现成 embedding + 向量库 + BM25 混合检索 + 小 reranker。
   - 技巧：查询改写、父子块、按文档类型分块、强制引用来源。
   - 收益：显著减少幻觉，提升事实性；通常比换更大模型更划算。

2. **工具调用**
   - 让模型调用计算器、代码执行、数据库、搜索、API、日历等。
   - 适合：数学、日期、统计、实时信息、业务操作。
   - 原则：**模型负责规划和表达，工具负责精确计算和事实查询**。
   - 收益：在计算/实时数据/操作任务上提升通常很大。

3. **验证器 / 批判-重写**
   - 流程：生成答案 → 用规则/检索证据/另一个小模型检查 → 不通过则重写。
   - 低成本检查项：
     - 是否有引用且引用支持结论
     - JSON schema 是否合法
     - 数字是否来自工具
     - 是否回答了用户问题
   - 只在低置信度或高风险样本上启用，避免全量增加成本。

4. **路由**
   - 简单问题走小模型/短提示；复杂问题走大模型/多步推理。
   - 分类器可用规则、embedding 相似度或小模型。
   - 收益：成本大降，同时把大模型算力集中在难例上。

5. **缓存**
   - 对高频问题、检索结果、embedding、工具结果做缓存。
   - 语义缓存要谨慎，设置相似度阈值和失效策略。
   - 收益：延迟和成本直接下降，尤其客服/FAQ。

## 按任务类型选“大幅提升”手段

| 任务 | 首选低成本方法 | 说明 |
|---|---|---|
| 知识问答/文档 | RAG + 引用 + 重排 | 最有效，优于单纯长上下文 |
| 数学/逻辑 | CoT + self-consistency + 代码工具 | 多采样提升但成本上升，只对难例用 |
| 分类/抽取 | 结构化 Prompt + JSON schema + 规则校验 | 先约束输出，再重试 |
| 客服/业务办理 | RAG + 工具 + 权限/流程校验 | 不要让模型直接编业务规则 |
| 长文档 | 分块摘要 + 检索 + 引用定位 | 避免一次性塞满上下文 |
| 代码 | 检索代码库 + 执行测试 + 错误回灌 | 测试就是验证器 |
| Agent | 工具白名单 + 状态机 + 失败重试 | 少用自由多智能体，成本高且不稳 |

## 最小低成本落地架构

```text
用户请求
  → 任务路由（简单/复杂/需检索/需工具）
  → 查询改写
  → 混合检索 + rerank
  → Prompt 组装：角色 + 任务 + 证据 + 输出格式
  → LLM 生成
  → 规则/schema/引用/工具结果验证
  → 不通过：重试或降级
  → 缓存结果
```

推荐默认 Prompt 结构：

```text
你是[角色]。只根据给定资料和工具结果回答。
若资料不足，明确说“不足以回答”，并说明缺少什么。
必须给出处：[来源编号]。
输出格式：[JSON/表格/要点]。
不要编造数字、日期、链接和引用。
```

对困难样本再用：

```text
先列出关键约束和所需证据；
再给出答案；
最后自检：每个结论是否有证据支持？是否有遗漏约束？
```

## 成本最低、收益最大的实施顺序

1. **建 50–200 条真实评测集**
   - 不做评测的“优化”很容易自我感觉良好。
   - 指标：准确率、事实错误率、引用正确率、格式合法率、平均延迟、单次成本。

2. **先加结构化输出和规则校验**
   - JSON schema、必填字段、枚举值、正则、长度限制。
   - 成本几乎为零，对抽取/分类/工单类任务提升明显。

3. **加 RAG**
   - 先做 BM25 + 向量混合检索，不要一开始上复杂图谱。
   - 强制引用，证据不足拒答。

4. **加工具**
   - 只接最影响正确性的 1–3 个工具：搜索、SQL、计算、业务 API。

5. **加验证与重试**
   - 先规则校验，再小模型校验；只对失败样本重试。

6. **加路由和缓存**
   - 高频 FAQ 直接缓存；简单任务走小模型。

7. **最后才考虑多采样/自我一致性**
   - 对数学、复杂推理等高价值难例使用 3–5 次采样投票。
   - 不要全量用，成本会线性增加。

## 常见误区

- **盲目让模型“一步一步思考”**：对简单任务增加成本和延迟，未必提升。
- **全量多智能体/多轮辩论**：成本高、延迟大，收益不稳定。
- **无限塞长上下文**：检索不准时，长上下文会引入噪声。
- **只换更大模型**：如果瓶颈是知识缺失或工具缺失，换模型收益有限。
- **没有评测集**：无法判断是否真的提升。

## 一句话结论

低成本、不训练、尽量大幅提升现有 LLM 的最优路线是：**用评测集定位瓶颈，然后优先上“RAG + 工具 + 结构化输出 + 验证重试 + 路由缓存”**。其中知识类任务收益最大来自 RAG，计算/实时类来自工具，稳定性来自验证和格式约束，成本下降来自路由与缓存。多智能体和多采样投票不是首选，只对高价值难例使用。
