# [v2:deepseek-flash] 任务2 提升LLM性能 | 条件: baseline | 第 7 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 12.57s | tokens: 41/1822

---

先明确结论：**不存在“零成本、无需训练、通用大幅提升”的银弹**。但如果你说的“提升”是**在具体业务任务上提升准确率/可用性**，那么不改模型权重，靠“提示工程 + 检索 + 工具 + 验证 + 路由”通常能拿到明显收益；多数场景相对提升 5%～30% 很现实，部分任务可更高。关键是别追求通用能力暴涨，而是做**任务级系统优化**。

## 最高性价比路线：按成本从低到高

### 1. 先评测和定位失败，不要盲调
先抽 50～200 条真实任务，标出失败类型：知识缺失、指令不遵守、格式错、计算错、长上下文遗漏、推理跳步、幻觉、工具不会用。  
没有失败分类，后面所有优化都容易无效。

### 2. 结构化提示 + 动态 few-shot
在 prompt 中固定：
- 角色与目标
- 输入信息使用规则
- 必须遵守的约束
- 2～5 个高质量示例
- 输出格式
- 不确定时如何处理
- 禁止编造的边界

更有效的是**动态 few-shot**：用检索把最相似的历史好例/错例拼进上下文，而不是固定示例。成本低，收益通常立竿见影。

### 3. 轻量 RAG：混合检索 + 重排 + 引用
很多“模型变笨”其实是知识缺失或上下文没给对。低成本方案：
- 文档切分不要太碎，保留标题和层级
- BM25 + 向量检索混合
- 对 TopK 做轻量重排
- 只放最相关片段，压缩上下文
- 要求回答引用来源，降低幻觉
- 对表格/FAQ/制度类任务尤其有效

不需要训练，只需建索引。

### 4. 分解任务 + 工具调用
让模型不要硬算、硬记、硬猜：
- 数学/统计走计算器或代码执行
- 企业数据走 SQL/API
- 最新信息走搜索
- 格式转换走脚本
- 复杂问题先拆子问题再汇总

这往往比换更大模型更划算。核心是：**模型负责理解与规划，确定性工具负责执行**。

### 5. 加验证器和失败重试
低成本验证器包括：
- 规则校验：JSON schema、字段完整性、数值范围、引用是否存在
- 小模型分类器：判断答案是否离题/是否含幻觉风险
- LLM judge：只对难例或高风险输出做二次检查
- 代码/单元测试：对生成代码直接执行验证

流程可以是：生成 → 校验 → 失败则带错误信息重试一次。只在失败时增加成本。

### 6. 模型路由/级联
不要所有请求都上最贵模型：
- 简单问题走小模型
- 置信度低、格式失败、复杂推理再升级大模型
- 按任务类型路由到专用 prompt/工具链
- 高风险任务强制大模型+验证器

这能同时提升平均效果和降低成本。

### 7. 只在关键任务用 Self-Consistency / 投票
多次采样投票有效，但成本高。低成本用法：
- 只对高价值、难例、答案可自动验证的任务投票
- 2～3 次采样即可
- 先让小模型生成，多个答案不一致时再上大模型裁决

不要全量使用。

### 8. 上下文工程和缓存
- 压缩历史对话，只保留目标、约束、已确认事实
- 对长文档先摘要/检索再回答
- 语义缓存高频问题
- 批处理离线任务
- 固定前缀缓存，减少重复 token

这些主要降成本，也间接减少长上下文导致的性能下降。

### 9. 输出约束与结构化接口
用 JSON Schema、函数调用、模板化输出、枚举选项，减少格式错误和自由发挥。对抽取、分类、工单、客服等任务收益很大。

## 推荐的最小落地组合

如果只做一套低成本方案，我建议：

> **结构化 prompt + 动态 few-shot + 混合 RAG + 规则/工具验证 + 失败重试 + 难例路由大模型**

这套通常比单纯换 prompt 稳定得多，而且不需要训练。

## 优先级排序

1. 评测集与失败分类：必须做  
2. 结构化 prompt/动态示例：最低成本  
3. RAG/上下文压缩：知识型任务优先  
4. 工具调用：计算、数据、代码类任务优先  
5. 验证器+重试：高风险任务优先  
6. 路由/级联：有成本压力时做  
7. 投票/多智能体：最后考虑，通常不低成本

## 预期与边界

- 对**封闭业务任务**：常见 10%～30% 相对提升，部分可更高。
- 对**开放通用能力**：不改权重很难“大幅”提升。
- 最大收益通常来自：**给对上下文、用对工具、加验证、失败重试、按难度路由**。
- 最大坑是：只改一句“请认真思考”，或盲目上多智能体，成本和延迟上去但收益不稳定。

一句话：**低成本大幅提升的本质，是把 LLM 从“单次裸答”改造成“有上下文、有工具、有校验、有兜底的任务系统”。**
