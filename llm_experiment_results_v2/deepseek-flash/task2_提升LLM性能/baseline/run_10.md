# [v2:deepseek-flash] 任务2 提升LLM性能 | 条件: baseline | 第 10 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 18.19s | tokens: 41/2990

---

先说结论：**不训练模型、低成本，不可能让通用能力全面“大幅提升”；但针对具体业务任务，可以通过“上下文工程 + 检索 + 工具 + 验证 + 路由缓存”的组合，显著提升准确率、稳定性和可用性。** 最高性价比通常不是继续调 prompt，而是把模型不擅长的部分外包出去。

## 1. 先做评测集，否则都是盲调
准备 50–200 条真实任务样本，覆盖正常、边界、对抗情况，记录：
- 准确率/通过率
- 幻觉率
- 格式错误率
- 平均延迟和 token 成本

每次改动只对比评测结果。没有 eval，很容易“感觉变好”。

## 2. 最低成本四件套：优先做这四件事

### A. 上下文工程
- 明确角色、目标、约束、输出格式。
- 关键指令放开头和结尾，减少被长上下文淹没。
- 用分隔符区分“指令 / 资料 / 用户输入”。
- 提供 3–5 个高质量 few-shot 示例。
- 要求：**不确定就拒答或标注低置信度**。
- 输出用 JSON Schema、字段模板、固定格式约束。

### B. RAG 检索增强
适合知识问答、客服、文档分析、企业内部知识。
低成本关键点：
- 文档切块 300–800 tokens，保留 10%–20% overlap。
- 混合检索：BM25 + 向量检索。
- 先召回 top 20–50，再用 reranker 精排到 3–8 条。
- 去重、压缩上下文，别把整篇文档塞进去。
- Prompt 明确：“只依据给定资料回答；资料不足则说不知道。”
- 强制引用来源，便于校验。

### C. 工具调用
模型不擅长精确计算、实时信息、数据库查询、代码执行。
给它接：
- 计算器
- 代码执行器
- 搜索引擎
- 数据库/API
- 企业内部系统查询

原则：**能查就别让模型背，能算就别让模型心算。**

### D. 验证与重试
低成本可靠性提升非常明显：
- JSON/正则/类型校验。
- 代码跑单元测试。
- 数学题二次验算。
- 关键答案要求引用证据。
- 失败后自动重试 1–2 次，并把错误反馈给模型。
- 用规则/小模型做 critic，不要默认上多智能体。

## 3. 推理增强：只在高价值难例上用
- **任务分解**：先计划，再执行，最后检查。
- **Self-consistency 自洽投票**：温度设 0.5–0.8，采样 3–5 次，多数投票。成本增加，只用于难题。
- **Best-of-N + verifier**：生成多个候选，用规则、小模型或测试用例选最优。
- **ReAct**：适合多跳检索和工具调用任务。
- **检查器模式**：生成器答，验证器查；验证器可用小模型或规则。

不要默认所有请求都上 CoT/多轮反思，简单任务直接答更便宜也更稳。

## 4. 工程层降本增效
- **模型路由/级联**：小模型先答，置信度低或任务复杂时升级大模型。
- **缓存**：精确缓存 + 语义缓存常见问题；利用 prefix/KV cache。
- **上下文压缩**：长会话定期摘要，只保留任务状态和关键事实。
- **约束解码**：JSON grammar、regex、枚举约束，减少格式错误。
- **批处理与并行**：离线任务批量跑，在线任务并行检索。
- **自动 prompt 优化**：DSPy、APE、OPRO 等可在不训练模型权重的情况下搜索模板，但必须有评测集。

## 5. 按任务选组合

| 场景 | 推荐组合 |
|---|---|
| 知识问答/客服 | 混合 RAG + rerank + 引用 + 拒答 + 缓存 |
| 数学/代码 | CoT + 工具执行 + 单测/验算 + 自洽投票 |
| 信息抽取 | JSON Schema + few-shot + 校验重试 |
| 复杂 Agent | 计划器 + 工具执行器 + 验证器 + 记忆压缩 |
| 分类/打标 | 标签说明 + few-shot + 投票/校准 + 小模型路由 |
| 长文档分析 | 分段摘要 + 检索定位 + 引用 + 最终综合 |

## 6. 推荐落地顺序
1. 建评测集。
2. 优化 system prompt 和输出格式。
3. 接 RAG 或工具。
4. 加格式校验、事实校验、失败重试。
5. 加模型路由和缓存降本。
6. 只对难例加自洽投票、Best-of-N、多步验证。
7. 持续做回归评测。

## 7. 主要坑
- RAG 不是万能的，检索噪声会让效果变差，必须 rerank/压缩/引用。
- 自洽投票、多智能体、多轮反思会显著增加成本，不要全局默认开启。
- Prompt 再强也补不了缺失知识、实时信息和精确计算，必须靠检索和工具。
- 注意 prompt injection、工具权限、数据脱敏和日志审计。
- “大幅提升”通常是任务级提升；通用能力提升有限，要围绕具体任务设计。

一句话：**先评测，再做“上下文 + RAG + 工具 + 验证 + 路由缓存”；这通常是不训练模型时 ROI 最高的路线。**
