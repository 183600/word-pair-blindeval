# [v2:deepseek-flash] 任务2 提升LLM性能 | 条件: baseline | 第 6 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 20.35s | tokens: 41/3275

---

先说结论：**没有一种 Prompt 能让所有 LLM 普遍“大幅变强”**。不额外训练时，最大收益通常来自把“裸调用模型”升级成：**检索 + 工具 + 上下文工程 + 测试时计算 + 验证 + 路由缓存** 的系统。是否“大幅”取决于任务和原 baseline；若原来只是裸 Prompt，提升往往很明显。

## 高性价比方法排序

| 方法 | 适用场景 | 做法 | 成本/收益 |
|---|---|---|---|
| **RAG 检索增强** | 私域知识、时效信息、长文档问答 | Query 改写 → 混合检索 BM25+向量 → rerank → 压缩上下文 → 要求引用证据；无证据就答不知道 | 高收益，中等成本 |
| **工具调用** | 计算、代码、数据库、搜索、业务操作 | 用 function calling / ReAct / Plan-Execute 调计算器、代码执行、搜索、API、测试 | 很高收益，低成本 |
| **上下文工程** | 几乎所有任务 | 明确角色/目标/约束/输出格式；给少量高质量 few-shot；先复述任务再答；分步拆解；强制 JSON/schema | 零训练，高收益 |
| **结构化输出 + 校验重试** | 抽取、分类、表单、API | JSON Schema、正则、function calling；程序校验失败自动重试或修正 | 低成本，显著降错 |
| **Self-Consistency / Best-of-N** | 数学、推理、选择题、稳定答案 | 采样 3~5 次，多数投票；或生成 N 个候选，用规则/测试/检索/LLM judge 选最佳 | 中低成本，推理提升明显 |
| **分解 + 验证器** | 多步复杂任务 | Planner 拆解 → Executor 执行 → Verifier 检查；代码用测试，数学用程序，事实用引用 | 中成本，高价值任务很有效 |
| **模型路由/级联** | 成本敏感、流量大 | 小模型先答；置信度低/规则失败/高价值请求升级到大模型；难题才集成 | 降本同时提效 |
| **记忆与状态管理** | 长对话、Agent | 会话摘要、向量记忆、scratchpad、状态机；避免把所有历史塞进上下文 | 低成本，减少上下文污染 |
| **缓存** | 高重复流量 | Prompt caching、语义缓存、结果缓存 | 主要降本降延迟 |
| **评估集驱动** | 所有优化 | 建 50~200 条 golden set，按事实性/格式/延迟/成本 A/B | 避免瞎叠技巧 |

## 按任务直接组合

- **知识问答/客服**：RAG + query 改写 + rerank + 引用 + 无证据拒答 + 规则校验  
- **数学/逻辑**：CoT + 代码解释器/计算器 + self-consistency + 程序验证  
- **代码**：仓库检索 + 运行测试/编译 + 错误反馈重试 + 只提交通过测试的版本  
- **抽取/分类**：JSON Schema + few-shot + 约束解码 + 程序校验 + 失败重试  
- **复杂研究/分析**：检索 + 分解计划 + 多源引用 + verifier + 只对难题多采样  
- **高并发生产**：小模型草稿 → 规则/置信度筛选 → 大模型审校/重答 → 缓存

## 低成本落地顺序

1. **先建小型评估集**，记录失败类型：缺知识、算错、格式错、推理不稳、上下文太长。
2. **改 Prompt 和输出格式**：约束、few-shot、schema、拒答规则。零成本先做。
3. **缺知识就上 RAG**；需精确计算/执行就上工具。
4. **对高价值或高不确定任务**加 self-consistency / verifier；不要全量上，成本会爆。
5. **加路由和缓存**：简单请求走小模型/缓存，难题才升级。
6. **持续 A/B**，只保留真正提升指标的组件。

## 注意事项

- 长 Prompt、无关检索、过多反思可能**降低**性能。
- Self-Refine 无外部反馈时容易“越改越错”，最好接规则、测试、检索证据。
- 多数投票只适合答案可比较的任务，开放生成不适合。
- LLM-as-judge 有偏置，最好用规则/测试/多模型 judge 组合。
- 不额外训练不等于零工程；真正大幅提升通常来自系统设计，而不是一句神奇 Prompt。

最推荐的组合拳：**RAG + 工具 + 结构化输出 + 难题多采样/验证 + 模型路由 + 缓存**。这通常是在不训练权重的前提下，低成本提升现有 LLM 生产力的最稳路径。
