先说结论：不改模型权重、不额外训练，想“大幅提升”不能靠单个提示词神技，而要把一次 LLM 调用升级成一套**可检索、可分解、可验证、可回退、可调度**的系统。提升的是“任务级有效性能”，不是模型本体智商。对知识密集、时效性强、计算/代码、长文、格式要求高的任务，收益通常最大；对模型本身完全不具备的能力，只能有限改善。

### 性价比最高的组合拳

1. **先建小型评测集**  
   收集 50—200 条真实任务，记录标准答案或验收规则。没有评测，就无法判断“提升”还是“错觉”。按错误类型分类：知识缺失、计算错误、格式错误、漏步骤、幻觉、理解偏差。

2. **上下文工程**  
   明确角色、目标、输入、约束、输出格式、失败时怎么回答。提供 1—3 个高质量示例。要求“只依据材料回答；无依据就说不知道；给出引用位置”。这通常成本最低、收益最快。

3. **混合 RAG**  
   文档切片 + 向量检索 + 关键词检索（BM25）+ 重排模型。检索后让模型只基于证据回答，并附引用。对时效知识和企业私有知识，往往比换更大模型更有效。

4. **验证器 + 重试修复**  
   用规则校验格式、字段、长度、单位、引用；再用 LLM 做事实/逻辑/约束复核。不通过就进入“修复循环”：指出错误、要求只改错误、再次校验。适合抽取、JSON、报表、客服回复。

5. **自洽采样投票**  
   对难题采样 3—5 次，投票或找共同结论。不要所有请求都开，按任务难度动态启用。数学、分类、判断类收益较明显。

6. **工具外挂**  
   把模型当“规划器”，不要当数据库和计算器。接搜索、计算器、代码执行、数据库/API、日历、表格解析。精确计算、实时信息、业务操作交给确定性工具。

7. **路由与级联**  
   简单任务走小模型/短提示，复杂任务走大模型/完整流程；先快后慢，低置信度再升级。加缓存、批处理、超时降级。这样能在成本可控下提升整体效果。

8. **结构化输出与护栏**  
   强制 JSON Schema、枚举、正则、字段校验；失败自动重问。高风险操作加权限、沙盒、审计、回滚。格式稳定本身就会显著提升可用性。

9. **工作流化**  
   典型流程：理解意图 → 检索资料 → 分解任务 → 调用工具 → 生成草稿 → 校验 → 修订 → 输出。多代理不是必须，通常单模型多阶段更便宜；只在强依赖并行专家时用多代理。

10. **运行监控与错题本**  
    记录失败案例、提示版本、检索结果、耗时成本。每周把高频错误转成规则、示例、检索改进或验证器。持续迭代比一次性“神提示”更可靠。

### 按任务可直接套用的配方

- **问答/客服**：混合 RAG + 引用 + “无依据不答” + 低置信度转人工。  
- **抽取/分类**：JSON Schema + few-shot 示例 + 规则校验 + 自动修复循环。  
- **数学/数据**：分解 + 工具计算 + 自洽投票 + 结果反算校验。  
- **代码任务**：计划 + 生成 + 单元测试执行 + 根据报错修复。  
- **长文报告**：分段摘要 + 全局提纲 + 证据表 + 逐节生成 + 一致性检查。  
- **高风险决策**：多源检索 + 正方/反方评审 + 置信度 + 人工审批，不让模型单独拍板。

### 一个低成本 MVP

先用 1—2 天做这四件事：  
1）整理 100 条真实测试题；  
2）所有输出改结构化模板；  
3）加混合检索和引用；  
4）加“验证器 + 失败重试”。  
多数场景下，这四步就能带来明显提升；之后再按错误类型加自洽投票、工具、路由和缓存。

避坑：不要盲目堆长提示和多个代理；检索噪声会反噬；CoT 不是万能；没有评测的“感觉变好”不可靠；模型没有的能力不能靠提示凭空造出来。核心原则是：**模型负责理解和生成，系统负责记忆、证据、计算、校验和兜底。**
