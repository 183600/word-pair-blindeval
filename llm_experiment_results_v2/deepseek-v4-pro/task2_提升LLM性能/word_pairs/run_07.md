- **镜子/回声** → 多路径采样、自检、投票

低成本、不需要额外训练，大幅提升现有 LLM 性能，核心思路只有一句：**把“模型单独想”改成“模型多路径想 + 外部证据 + 强约束输出 + 系统缓存路由”。**

下面按投入产出比排序，给出可落地方法。

---

### 1. 推理时多路径采样与自检：让模型多“回音”几次

这是最直接、成本最低的性能提升方式之一。

- **自一致性投票**：同一问题让模型生成 3–5 个答案，温度调高一点，比如 0.5–0.8，然后投票或让模型自己选最优。  
- **先给步骤再给结论**：要求模型“先列出推理步骤，再给出最终答案”，能显著提升数学、逻辑、规划类任务。  
- **自我校验**：让模型生成答案后，再追加一句：“请检查上面的答案是否有逻辑漏洞、事实错误或遗漏条件。”  
- **只对困难问题开启**：简单问题不开启多路径，难问题才开启，控制成本。

---

### 2. 检索增强：给模型一座“桥梁”

很多性能问题不是模型能力不够，而是它缺少当前任务所需的外部事实。

- **RAG 检索**：把外部知识库、文档、FAQ 先做向量化，查询时取 top-k 片段插入上下文。  
- **要求引用原文**：让模型回答时标注依据哪个片段，避免胡编。  
- **时效性问题接搜索 API**：不要依赖模型内部记忆，而是实时搜索后回答。  
- **成本**：主要是向量库和检索 API，远低于训练。

---

### 3. 工具调用与代码执行：让模型“借力”

- **数学、统计、日期计算**：不要让模型心算，要求它写 Python 代码并执行。  
- **数据库查询**：给模型一个 SQL 工具，让它查询后回答。  
- **表格、文件解析**：用代码解释器处理 CSV、JSON、Excel。  
- **外部 API**：天气、汇率、地图、翻译等，直接调用工具。

这能让很多原本容易出错的任务提升到接近规则系统的准确率。

---

### 4. 强约束输出与格式控制：装好“航标”

- **结构化输出**：要求输出 JSON、XML，并使用 JSON Schema 约束解码，避免格式错误。  
- **低温度采样**：需要稳定输出时，temperature 设为 0.1–0.3，top_p 设为 0.9。  
- **负面约束**：明确写“不要解释，不要额外文字，只输出 JSON”。  
- **输出后规则校验**：检查括号闭合、字段名、日期格式、代码块完整性；失败就自动重试一次，并把错误信息回传。  
- **重复惩罚**：设置 repetition_penalty 1.05–1.15，减少绕圈话。

这几项成本几乎为零，但对格式遵循、稳定性、可解析性提升非常明显。

---

### 5. 提示词工程：精选“拼图碎片”

- **高质量 few-shot 示例**：准备 10–50 条高质量示例库，按相似度检索 3–5 条插入提示。  
- **示例要覆盖边界情况**：不只给成功案例，也展示“如果用户这样说，你应该这样处理”。  
- **重要信息放开头和结尾**：模型对首尾更敏感，中间信息容易忽略。  
- **角色设定**：例如“你是一名资深后端工程师，必须给出可直接执行的步骤，不要给教科书式解释。”  
- **输出模板**：直接给出答案结构，让模型填空，而不是自由发挥。

---

### 6. 缓存与路由：复用“炉火余烬”

- **语义缓存**：对相似问题做向量检索缓存，命中后直接返回，避免重复推理。  
- **模型路由**：简单问题用小模型，难问题路由到大模型，可以降低 50%–80% 成本。  
- **长文档分块**：不要一次塞入超长上下文，先分块、检索相关片段再注入。  
- **前缀缓存**：对固定的系统提示、few-shot 示例使用 KV cache 复用，加速推理。

---

### 7. 多模型协作：让模型互相“照镜子”

- **小模型起草，大模型精修**：用便宜模型生成草稿，再用强模型润色、纠错。  
- **双模型辩论**：两个模型对同一问题给出答案后互相批评一轮，再输出最终答案。  
- **LLM-as-judge**：用另一个模型对候选答案打分，选最高分。  
- **多代理分工**：一个模型负责检索，一个负责推理，一个负责校验。

这些方法会增加调用次数，但不需要训练，且对复杂任务提升明显。

---

### 8. 推理与系统层降本：不损性能的“杠杆”

- **量化推理**：使用 AWQ、GPTQ、FP8 等量化方案，降低显存和推理成本，精度损失很小。  
- **投机采样**：小模型起草，大模型验证，可加速 2–3 倍。  
- **批处理请求**：聚合并发请求，提高吞吐。  
- **KV cache 复用**：对固定前缀复用缓存，减少重复计算。

---

### 落地顺序建议

1. **先做提示工程和格式约束**：零成本，一两天就能明显提升。  
2. **再做多路径投票 + 自检**：成本低，对推理类任务提升大。  
3. **接入 RAG 和工具**：解决事实性和计算类错误。  
4. **上缓存与路由**：降低成本，同时保持性能。  
5. **最后考虑多模型协作**：在关键业务上进一步提升。

如果基线是“零提示直接问”，这一套组合通常能带来显著提升；如果基线已经过高度优化，提升幅度会变小，但成本通常还能继续降。
