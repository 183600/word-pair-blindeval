# [v2:deepseek-v4-pro] 任务2 提升LLM性能 | 条件: baseline | 第 1 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 64.9s | tokens: 94/4294

---

不训练、低成本地提升现有 LLM 的性能，核心是“推理时优化”：改输入、改解码、给外部工具/知识、用工作流放大模型能力。这些方法不会改变模型权重，但组合使用通常能明显提升复杂推理、知识问答、代码/数学、格式遵循等任务表现。

下面按实用优先级分类。

---

## 1. 提示词与上下文工程

这是成本最低、见效最快的一类。

### 1.1 系统提示词优化
- 明确角色、目标、边界、输出格式。
- 示例：
  > 你是一名资深软件工程师。回答必须给出可运行代码，并解释关键步骤。不要输出与问题无关的内容。

### 1.2 Few-shot 示例
- 给 2–5 个高质量示例，尤其覆盖边界情况。
- 示例顺序很重要，把最难的示例放后面。
- 示例要一致，避免互相矛盾。

### 1.3 思维链 CoT
- 简单加一句往往就能提升推理：
  > 请一步步思考，最后给出最终答案。
- 对复杂任务，用“先计划，再执行，最后检查”的模板。

### 1.4 上下文结构优化
- 使用 XML/Markdown/JSON 分隔不同信息块。
- 重要信息放在开头和结尾，避免长上下文“中间遗忘”。
- 删除无关信息，减少噪声。

### 1.5 输出格式约束
- 明确要求 JSON、Markdown、表格等格式。
- 给出输出 schema 示例。
- 负面约束也很有效：
  > 不要使用缩写；不要编造数据；如果不知道，回答“不知道”。

---

## 2. 解码与采样策略

不训练，只改推理参数，也能影响质量。

### 2.1 温度 / top_p / top_k
- 事实抽取、代码生成、数学题：低温度，如 0.1–0.3。
- 创意写作、头脑风暴：高温度，如 0.7–1.0。
- 需要稳定输出时，关闭采样或使用贪心解码。

### 2.2 自一致性 Self-Consistency
- 对同一个问题采样 5–10 次，投票或取平均。
- 对数学、逻辑、分类、选择题提升明显。
- 成本增加 N 倍，但无需训练。

### 2.3 Best-of-N + 打分器
- 采样多个候选答案。
- 用规则、代码测试、或 LLM-as-judge 打分。
- 选择最优答案，比单次生成可靠很多。

### 2.4 约束解码
- 使用 JSON mode、正则约束、语法约束。
- 可大幅减少格式错误，提升可解析性。
- 常见框架：Guidance、Outlines、vLLM 的结构化输出、OpenAI JSON mode。

### 2.5 重复惩罚与停止词
- 设置合理的重复惩罚，避免循环输出。
- 设置停止词，防止模型继续编造。

---

## 3. 检索增强 RAG 与外部工具

模型知识是固定的，外部信息能让它处理实时、私有、专业问题。

### 3.1 RAG
- 流程：检索 → 重排 → 压缩 → 注入上下文。
- 检索到的文档片段要干净、相关，避免噪声。
- 提示中要求引用来源：
  > 根据以下资料回答，并标注来源编号。如果资料中没有，回答“资料不足”。

### 3.2 工具调用
- 让模型使用计算器、代码解释器、搜索引擎、数据库、API。
- 数学题不让模型直接算，让它写代码计算。
- 实时问题让它调用搜索工具，而不是靠记忆。

### 3.3 代码执行反馈
- 生成代码后，实际运行测试。
- 把报错信息喂回给模型，让它修复。
- 对代码生成任务提升非常大。

---

## 4. 推理时工作流 / Agent

把一个大任务拆成多步，让模型多次调用自己。

### 4.1 ReAct
- 让模型按“思考 → 行动 → 观察”循环。
- 适合需要工具调用的任务。
- 示例：
  > 你可以使用搜索工具和计算器。请按 Thought/Action/Observation 循环解决问题。

### 4.2 Plan-and-Solve
- 先让模型制定计划，再逐步执行。
- 适合多步骤复杂任务。
- 示例：
  > 先列出解决步骤，然后逐步执行。每步说明结果。

### 4.3 自我反思 / 自我修正
- 生成答案后，再让模型检查：
  > 请检查你的答案是否有错误、遗漏或逻辑问题，然后给出最终修正版。
- 可重复 1–2 轮，但注意成本。

### 4.4 多角色 / 多智能体辩论
- 一个模型生成，另一个模型批判，第三个综合。
- 适合开放问题、方案设计、复杂决策。
- 成本较高，但无需训练。

### 4.5 任务拆分
- 长文档总结：分段总结，再合并总结。
- 多文档对比：先逐个分析，再统一对比。
- 避免一次性塞入过多信息。

---

## 5. 工程与成本优化

这些方法主要降低延迟和成本，间接让你能在同样预算下做更多采样或跑更大模型。

### 5.1 提示缓存
- 系统提示、长上下文、few-shot 示例尽量复用。
- 很多推理服务支持前缀缓存，能显著降低 token 成本。

### 5.2 语义缓存
- 对相似问题直接返回缓存结果。
- 适合高频客服、常见问答场景。

### 5.3 量化部署
- 使用 AWQ、GPTQ、GGUF 等量化。
- 精度损失通常不大，但推理速度大幅提升。
- 同样成本下可以采样更多次，提升投票质量。

### 5.4 高吞吐推理框架
- vLLM、SGLang、TensorRT-LLM。
- 支持连续批处理、KV cache、结构化输出。
- 提高并发吞吐，降低单位成本。

### 5.5 模型路由 / 级联
- 简单问题用小模型，复杂问题用大模型。
- 先让小模型回答并打分，置信度低再升级大模型。
- 成本低，质量接近大模型。

---

## 6. 推荐组合配方

根据不同任务，直接套用：

| 任务类型 | 推荐组合 |
|---|---|
| 数学/逻辑推理 | CoT + 自一致性 + 代码计算器 |
| 知识问答 | RAG + 引用来源 + 自检 |
| 代码生成 | 代码执行反馈 + 测试用例 + 修复 |
| 信息抽取/分类 | 结构化输出 + 多次采样投票 |
| 开放写作 | 高温度采样 + Best-of-N + LLM 打分 |
| 复杂决策 | Plan-and-Solve + 多角色辩论 |

---

## 总结

不训练时，提升最大的通常是：

1. **思维链 + 自一致性**
2. **RAG 注入外部知识**
3. **工具调用，尤其是代码执行**
4. **结构化输出约束**
5. **自我修正 / 多步工作流**

这些方法不需要改权重，成本主要是推理 token 增加。建议先建一个小型评测集，逐项实验，找出对当前任务提升最大的组合。
