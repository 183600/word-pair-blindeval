# [v2:deepseek-v4-pro] 任务2 提升LLM性能 | 条件: baseline | 第 2 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 47.08s | tokens: 94/3109

---

不需要额外训练，提升现有 LLM 表现的核心思路是：**把模型当作推理引擎，通过更好的输入、采样策略、外部工具和系统设计来榨出性能**。下面按成本从低到高排列，都是实战中有效的方法。

---

## 一、零额外成本：提示工程 + 推理参数优化

### 1. 提示词结构化
把指令写清楚，包含：角色、目标、步骤、约束、输出格式。

**示例：**
```text
你是一名资深数据分析师。
任务：分析以下销售数据，找出异常点。
步骤：
1. 先列出数据中的关键指标；
2. 计算环比变化；
3. 指出变化超过20%的异常项；
4. 用 JSON 输出结论。
约束：不要编造数据，数据中没有的字段不要推断。
```

### 2. 思维链（Chain-of-Thought, CoT）
让模型“先思考再回答”，显著提升数学、逻辑、多步推理任务。

**示例：**
```text
请一步一步思考，先分析问题，再给出最终答案。
```

### 3. Few-shot 示例
给 2~5 个高质量示例，让模型模仿格式和推理深度。无需训练，但效果接近小样本微调。

### 4. 角色设定与受众对齐
指定专家角色、目标受众、语言风格，能减少无效输出，提高专业度。

### 5. 推理参数调优
- **降低 temperature**（如 0.1~0.3）：提高稳定性，适合事实问答、分类、抽取。
- **提高 temperature**（如 0.7~0.9）：提高多样性，适合创意生成。
- **限制 max_tokens**：避免冗长输出，减少截断。
- **设置 stop 序列**：防止模型继续胡言乱语。

---

## 二、低额外成本：多次采样 + 自我验证

### 1. 自一致性（Self-Consistency）
同一问题采样 3~5 次（temperature 0.7），取出现频率最高的答案。对数学、代码、逻辑题提升明显。

> 成本增加 3~5 倍，但无需训练，实现简单。

### 2. 自我反思（Self-Reflection）
让模型先回答，再检查自己的答案。

**示例：**
```text
请回答问题。回答后，请检查：
1. 是否有事实错误？
2. 逻辑是否自洽？
3. 是否遗漏了重要条件？
如果有问题，请修正。
```

### 3. 多角色辩论
让模型扮演两个角色互相质疑，最后总结。适合开放性问题、风险评估。

### 4. 多次生成 + 外部验证器
本地写规则或小模型对输出打分，选最优结果。例如用关键词匹配、正则、语法检查。

---

## 三、外部增强：RAG、工具调用、结构化输出

### 1. RAG（检索增强生成）
将知识库/文档切块存入向量数据库，查询时检索 top-k 片段注入上下文。  
**效果：** 大幅减少幻觉，提升事实准确性。  
**成本：** 低，向量检索非常快。

**适用任务：** 企业知识问答、文档总结、客服。

### 2. 工具调用（Function Calling）
让模型调用计算器、代码执行环境、搜索 API、数据库等外部工具。

**示例：** 数学题让模型生成 Python 代码并执行，而不是直接算。  
**效果：** 数学、日期计算、API 调用成功率大幅提升。

### 3. 结构化输出约束
使用 JSON Schema、正则约束解码，保证输出格式合法。减少解析失败，提升可用性。

**示例：** 要求模型输出：
```json
{"name": "", "date": "", "summary": ""}
```
并在系统提示中强调“必须严格符合 JSON 格式”。

### 4. 程序辅助推理（Program-aided Reasoning）
让模型生成代码或伪代码解决问题，而不是直接推理。适合复杂计算、数据转换。

## 四、系统级优化：缓存、路由、后处理

### 1. 语义缓存
对相似问题（用 embedding 相似度）返回缓存答案，降低延迟和成本，尤其适合高频 FAQ。

### 2. 模型路由
简单任务用小模型（如 GPT-4o-mini），复杂任务用大模型。对现有模型体系，可大幅降低平均成本。

### 3. 上下文压缩与记忆管理
长对话中定期摘要历史，删除无关信息，避免上下文超载导致性能下降。

**示例：** 每超过 4 轮对话，让模型总结前文为 200 字摘要。

### 4. 输出后处理验证
对模型输出进行规则校验（格式、范围、禁用词），失败则重试或修正。例如：
- 检查 JSON 是否可解析；
- 检查日期是否合法；
- 检查数字是否在合理区间。

## 五、组合策略（按任务类型推荐）

| 任务类型 | 推荐组合 |
|---------|---------|
| 事实问答 | RAG + 低 temperature + 提示“基于资料回答，不知道就说不知道” |
| 数学/代码 | CoT + 工具调用/代码执行 + 自一致性 |
| 复杂推理 | CoT + 自一致性 + 自我反思 |
| 长文档分析 | 上下文压缩 + 分块处理 + 摘要聚合 |
| 结构化抽取 | JSON Schema 约束 + 后处理验证 + few-shot |
| 开放创意 | 高 temperature + 多样采样 + 外部评分器选优 |

## 关键提醒

- **不需要额外训练**，以上方法全部是推理时或系统级优化。
- “大幅提升”是任务相关的：在数学、逻辑、事实问答上，CoT、自一致性、RAG 往往提升显著；在创意生成上，主要靠提示词和采样策略。
- 多次采样、多智能体辩论会增加调用成本，但相比训练成本仍然极低。
- 建议先尝试**零成本方法**（提示工程、参数优化），再逐步增加外部模块。
