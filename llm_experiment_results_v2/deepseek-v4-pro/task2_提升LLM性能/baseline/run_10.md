# [v2:deepseek-v4-pro] 任务2 提升LLM性能 | 条件: baseline | 第 10 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 61.67s | tokens: 94/4044

---

可以，不微调、不训练，通过**提示工程、推理时策略、检索增强、工具调用、解码约束和系统优化**，就能明显提升现有 LLM 的任务表现。核心思想是：

> 模型权重不变，但改变输入质量、推理路径、外部信息、输出约束和采样策略，把算力从“训练”转移到“推理时”。

下面按“性价比从高到低”整理。

---

## 一、提示工程：最直接、几乎零成本

### 1. 加入高质量少样本示例

给模型 2～8 个高质量示例，通常能大幅提升稳定性与准确率。

- 示例要覆盖不同情况，格式统一。
- 标签要与任务一致。
- 示例顺序会影响结果，重要示例放前面。
- 对于分类、抽取、格式转换任务尤其有效。

例如：

```text
请将以下句子分类为“正面/负面”。

示例：
句子：这个产品非常好用。 -> 正面
句子：质量太差了，我很失望。 -> 负面

现在请分类：
句子：物流很快，但包装有点破损。 -> ?
```

---

### 2. 思维链：让模型先推理再回答

对于数学、逻辑、代码、复杂决策，使用思维链能显著提升准确率。

```text
请一步步思考，先写出推理过程，再给出最终答案。
```

更进阶的做法：在少样本示例中也展示“推理过程 + 最终答案”，让模型模仿。

---

### 3. 角色设定与受众设定

明确角色、专业水平、输出风格。

```text
你是一位资深数据科学家。请用通俗语言向非技术管理者解释以下概念。
```

角色设定会激活模型内部更相关的知识分布，常常比直接提问效果好。

---

### 4. 结构化输出约束

指定输出格式，减少歧义和不完整输出。

- 要求 JSON、Markdown 表格、列表。
- 使用 OpenAI JSON mode、Function Calling、JSON Schema。
- 本地模型可用 `guidance`、`Outlines`、`LMQL` 等做约束解码。

结构化输出可以避免大量后处理失败，提升端到端成功率。

---

### 5. 上下文排序与压缩

长上下文场景：

- 重要信息放开头和结尾。
- 中间部分容易被忽略。
- 对检索到的文档做压缩、重排，只保留最相关片段。

---

## 二、推理时扩展：用多次采样换取质量

这类方法会用更多推理算力，但相比训练成本仍然很低，且效果提升非常明显。

### 1. Self-Consistency 自一致性投票

对同一问题采样 N 次，取出现频率最高的答案。

- 温度调到 0.5～0.9，生成 5～10 个回答。
- 对最终答案投票。
- 数学、逻辑、代码、事实问答非常有效。
- 成本是原来的 N 倍，但可以通过减少输出长度、使用小模型验证来控制。

```text
请回答以下数学题：
问题：一个水池有两个进水管，A管单独注满需要3小时，B管单独注满需要6小时，两管同时开需要多久？

请独立生成 5 个不同推理路径的答案，并最终投票。
```

实际实现时，可以直接并行调用 5 次 API，然后投票。

---

### 2. Best-of-N 采样 + 验证器

采样多个候选答案，然后用规则、测试用例、奖励模型或轻量模型打分，选择最佳。

- 代码生成：生成 10 个候选，运行单元测试，选通过且最短的。
- 翻译：用 COMET 或另一个 LLM 打分。
- 摘要：用 ROUGE 或 LLM 评分。

即使没有训练，也可以用现有评价指标或简单规则做验证器。

---

### 3. 反思与自我修正

让模型先生成答案，再自我批评，最后修订。

```text
请回答以下问题。
回答后，请检查你的答案是否存在错误、遗漏或逻辑问题，并给出修改版。
```

也可以分多轮：

- 第一轮：生成答案。
- 第二轮：让模型扮演批评者，找出错误。
- 第三轮：根据批评修改。

对于代码、数学、写作质量提升明显。

---

### 4. 多智能体辩论

让两个或多个模型角色持不同立场辩论，最后由裁判模型总结。

- 成本较高，但适合复杂决策、开放问题。
- 可以用同一个模型的不同提示实现，不需要多个模型。

---

## 三、检索增强：补足知识和时效性

很多错误不是模型能力不够，而是缺少正确信息。RAG 是低成本、高收益的方法。

### 1. 向量检索 + 文档注入

把企业文档、知识库、产品手册切成块，存入向量数据库。

用户提问时：

1. 检索最相关片段。
2. 把片段拼入提示。
3. 让模型基于片段回答，并标注来源。

这能显著减少幻觉，提升知识密集型任务准确率。

---

### 2. 联网搜索

使用搜索 API，把搜索结果注入上下文。

适合时效性问题、新闻、最新文档。

---

### 3. 混合检索 + 重排

- 同时使用关键词检索和向量检索。
- 使用重排模型或 LLM 对候选片段打分。
- 只保留 top 3～5 片段，减少噪声。

---

## 四、工具调用与代码执行

让模型调用外部工具，弥补自身计算和操作能力不足。

### 1. 计算器 / 代码解释器

模型算术容易出错，可以让它生成代码并执行。

```text
请用 Python 计算以下表达式，并给出结果：
...
```

OpenAI Code Interpreter、本地沙盒执行都可以。

---

### 2. 数据库 / API 调用

让模型生成 SQL、调用 API、查询结构化数据。

- 生成 SQL 后实际执行，如果报错就把错误信息反馈给模型重试。
- 这比让模型直接“记住”数据可靠得多。

---

## 五、模型路由与集成

### 1. 模型路由

简单任务用小模型，复杂任务用大模型。

- 先用小模型判断难度。
- 难度低：小模型直接回答。
- 难度高：路由到大模型。

这样在成本几乎不变的情况下，整体质量可以接近大模型。

---

### 2. 多模型集成

用不同模型生成答案，然后投票或由裁判模型选择。

- 不同模型有不同错误分布，集成后可以互补。
- 成本为多个模型之和，但可以用较小模型参与集成。

---

## 六、解码策略与约束

这些方法几乎零额外成本，但能改善输出质量。

### 1. 调整采样参数

- 确定性任务：温度调低，例如 0～0.3。
- 创意任务：温度调高，例如 0.7～1.0。
- 减少 top_p 到 0.9 以下，避免低概率 token 噪声。

---

### 2. 使用停止词

设置合理停止序列，避免模型继续生成无关内容。

---

### 3. 约束解码

强制输出符合 JSON、正则表达式、语法结构。

- OpenAI JSON mode、Function Calling。
- 本地模型：`guidance`、`Outlines`、`SGLang`、`XGrammar`。

这能减少格式错误，提高端到端成功率。

---

## 七、系统与工程优化：降低成本，间接提升质量

这些方法不直接提升准确率，但能降低推理成本、提高吞吐，使你有更多预算做多次采样、更长上下文或更大模型。

### 1. 量化

使用 AWQ、GPTQ、GGUF 等量化模型，降低显存占用和延迟。

### 2. 投机解码

用小模型生成草稿，大模型验证，可提升 2～3 倍吞吐，几乎不损失质量。

### 3. 连续批处理

使用 vLLM、SGLang、TensorRT-LLM 等推理框架，提高 GPU 利用率。

### 4. 提示缓存

缓存系统提示、少样本示例等固定前缀，减少重复计算和成本。

---

## 八、推荐组合方案

### 通用高质量方案

```text
系统提示 + 少样本示例 + 思维链 + 结构化输出 + 自一致性投票
```

- 成本：约 3～5 倍单次推理。
- 提升：通常显著提升复杂任务准确率。

---

### 知识密集型任务

```text
检索增强 + 联网搜索 + 引用来源 + 少样本示例
```

- 成本：检索和搜索 API 费用。
- 提升：减少幻觉，提升时效性。

---

### 代码 / 数学任务

```text
思维链 + 代码执行验证 + Best-of-N 采样 + 单元测试
```

- 成本：多次采样 + 执行环境。
- 提升：从“能生成代码”到“能生成可运行且正确的代码”。

---

### 客服 / 结构化任务

```text
约束解码 + 工具调用 + 模型路由 + 提示缓存
```

- 成本：较低。
- 提升：格式合规率接近 100%，整体延迟降低。

---

## 九、成本控制建议

1. 不要对所有请求都做自一致性，只对高难度任务启用。
2. 用小模型做验证器、路由器和重排器。
3. 限制输出最大 token 数。
4. 缓存固定前缀。
5. 使用量化、投机解码降低单次成本。
6. 从 N=3 或 N=5 开始，不需要 N=50。

---

## 总结

不训练、低成本提升现有 LLM 性能的核心路径是：

```text
好提示 + 少样本示例 + 思维链
    ↓
结构化输出 / 约束解码
    ↓
检索增强 / 工具调用
    ↓
自一致性投票 / Best-of-N / 反思
    ↓
模型路由 / 工程优化
```

这些方法可以组合使用，通常能在数学、代码、知识问答、格式准确性、复杂决策等任务上带来明显提升，而成本远低于微调或重新训练。
