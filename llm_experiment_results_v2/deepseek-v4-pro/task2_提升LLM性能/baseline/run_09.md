# [v2:deepseek-v4-pro] 任务2 提升LLM性能 | 条件: baseline | 第 9 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 49.03s | tokens: 94/3123

---

在“不额外训练/不微调”的前提下，提升现有 LLM 性能主要靠**推理时技术、外部知识/工具、更好的提示与解码策略、系统级集成**。这些方法成本低、见效快，尤其适合 API 模型或本地开源模型。

下面按“收益/成本”从高到低整理。

---

## 1. 提示工程与上下文学习（最直接）

### 1.1 Few-shot / 示例选择
给模型几个高质量示例，往往比长篇指令更有效。  
- 用检索从历史正确样本中找相似示例（示例检索）。
- 示例要覆盖边界情况、输出格式、推理步骤。
- 对开源小模型，示例数量可增至 8–20 个。

### 1.2 Chain-of-Thought（思维链）
让模型“先推理再回答”，显著提升数学、逻辑、多步任务。  
- 指令中加：`请一步一步思考，先给出推理过程，再给出最终答案。`
- 零样本 CoT：`Let's think step by step` 中文可用 `让我们一步步分析`。

### 1.3 角色与格式约束
明确角色、受众、输出格式、长度限制、禁止事项。  
例如：
```
你是资深算法工程师。请用 JSON 输出，包含 reason 和 answer 两个字段。
```

### 1.4 结构化提示模板
将任务拆成：背景、目标、约束、示例、输出格式。  
减少歧义，提升稳定性。

---

## 2. 解码策略优化（零成本，但影响大）

| 场景 | 推荐参数 |
|------|----------|
| 事实问答/代码 | temperature=0.0–0.2，top_p=0.9，do_sample=False（贪心） |
| 创意写作 | temperature=0.8–1.0，top_p=0.95 |
| 数学/逻辑 | temperature=0.3–0.7 + 多次采样投票 |
| 避免重复 | repetition_penalty=1.05–1.2 |
| 长文本生成 | 设置 max_new_tokens，避免截断 |

**注意**：很多开源模型在 temperature=0 时反而输出退化，可微调至 0.1–0.3。

---

## 3. 多次采样与自一致性（Self-Consistency）

对同一问题采样多个答案（3–10 次），投票或取多数。  
- 适合数学、代码、分类、选择题。
- 成本成倍增加，但可并行调用；本地小模型成本极低。
- 实现简单：
```python
answers = [model.generate(prompt, temperature=0.5) for _ in range(5)]
final = majority_vote(answers)
```

更高级：**Best-of-N**——采样 N 个，用奖励模型/规则/LLM 打分选最优。

---

## 4. 检索增强生成（RAG）

不训练模型，但注入外部知识，大幅提升事实性、领域知识、长尾问题。

### 低成本方案
- 向量库：Chroma、FAISS、Qdrant、Milvus Lite
- 嵌入模型：`bge-small-zh`、`m3e-small`、`text-embedding-3-small`
- 文档切分：按语义/标题/重叠切块
- 检索后重排：用交叉编码器（如 `bge-reranker-base`）提升相关性

### 使用技巧
- 检索 Top-K 后，按相关性截断，避免噪声
- 在提示中明确：`仅根据以下资料回答，若资料不足请说“不知道”`
- 对多文档问答，先让模型提取相关片段，再综合

---

## 5. 工具调用 / 函数调用

让 LLM 调用外部工具，弥补计算、实时信息、数据库查询等短板。  
- 计算器：数学题交给 Python 计算
- 代码解释器：生成并执行代码
- 搜索 API：实时信息
- 数据库查询：结构化数据

实现：在提示中定义可用函数 JSON schema，让模型输出函数调用，解析后执行再回填结果。  
开源模型可用 `function-calling` 微调版，或通过 ReAct 模式手工实现。

---

## 6. 自我验证与反思（Self-Refine / Reflexion）

让模型对自己的答案进行批评、修正：
```
请检查上述答案是否有逻辑错误、计算错误或遗漏条件，并给出修正版。
```
- 一次生成 + 一次验证，可显著减少低级错误。
- 多轮反思（2–3 轮）效果更好，但成本增加。

适合：数学、代码、写作、合同审查等。

---

## 7. 多模型/多路径集成

### 7.1 模型路由
简单任务用小模型，困难任务用大模型。  
- 用分类器或规则判断难度。
- 成本降低 50–80%，性能几乎不降。

### 7.2 LLM 级联
先用小模型生成，若置信度低再调用大模型。  
- 置信度可通过 logprob、自一致性投票、验证器判断。

### 7.3 多模型投票/辩论
两个模型互相批评，或三个模型投票。  
- 例如：模型 A 回答，模型 B 找漏洞，模型 A 修正。
- 能提升复杂推理和事实准确性，成本成倍。

---

## 8. 约束解码与结构化生成

强制模型输出合法 JSON、正则、代码，减少格式错误。  
- 库：`Outlines`、`Guidance`、`LMQL`、`SGLang`
- 用途：信息抽取、API 调用、代码生成、分类

例如用 Outlines 强制输出 JSON：
```python
import outlines
model = outlines.models.transformers("mistralai/Mistral-7B")
generator = outlines.generate.json(model, schema)
```
这能显著提升任务成功率和稳定性。

---

## 9. 上下文工程与记忆管理

### 9.1 动态上下文选择
- 长对话中只保留最近 N 轮 + 摘要 + 关键事实
- 使用向量记忆检索历史相关信息

### 9.2 上下文压缩
- 对长文档先用小模型总结/抽取，再交给主模型
- 减少无关信息干扰，提升注意力集中度

### 9.3 明确引用来源
- 让模型回答时引用提供的片段编号，减少幻觉

---

## 10. 自动提示优化（不训练模型，只优化提示）

用框架自动搜索最佳提示词和示例：
- **DSPy**：把提示视为可优化参数，通过多次调用模型优化指令/示例，不更新权重
- **PromptBench / EvoPrompt**：进化算法搜索提示
- **APE**：自动提示工程

成本：需要多次模型调用，但比训练便宜得多。

---

## 11. 推理加速与量化（降低成本，间接提升可用性）

虽然量化本身不提升质量，但降低推理成本/延迟，使你能：
- 运行更大模型
- 使用更多采样、自一致性、集成
- 在本地免费运行

推荐：
- 量化：GGUF（llama.cpp）、AWQ、GPTQ、bitsandbytes
- 推理引擎：vLLM、SGLang、TensorRT-LLM、llama.cpp
- 批处理：连续批处理提升吞吐 5–10 倍

---

## 12. 输出后处理与验证

- 规则校验：格式、长度、必填字段、数值范围
- 语法检查：代码用 linter/编译器
- 事实核查：用搜索 API 或知识库验证关键实体
- 重写润色：用另一个模型/同一模型对输出进行润色

## 推荐组合（按任务类型）

| 任务 | 推荐方案 |
|------|----------|
| 数学/逻辑 | CoT + 自一致性（采样 5–10 次投票）+ 计算器工具 |
| 代码生成 | 约束解码 + 代码执行验证 + 自我修复 |
| 知识问答 | RAG + 引用来源 + 自我验证 |
| 信息抽取 | 约束 JSON 解码 + Few-shot 示例 |
| 长文档总结 | 分块总结 + 上下文压缩 + 多轮综合 |
| 对话系统 | 动态记忆 + 检索历史 + 角色设定 |
| 创意写作 | 高 temperature + Best-of-N 择优 |
| 多步骤任务 | ReAct + 工具调用 + 自我反思 |

---

## 注意事项

1. **不训练无法改变模型固有知识**。如果模型基础能力差，这些方法提升有限，但组合使用通常能带来 10%–40% 的任务性能提升，部分任务甚至翻倍。
2. **成本与收益平衡**：自一致性、多智能体辩论会增加调用次数。建议先在小样本上验证。
3. **开源小模型 + RAG + 工具** 往往能接近甚至超过未优化的大模型，成本极低。
4. **缓存**：对相同/相似请求缓存结果，避免重复调用。
