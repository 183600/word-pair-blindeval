# [v2:deepseek-v4-pro] 任务2 提升LLM性能 | 条件: baseline | 第 4 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 68.07s | tokens: 94/4556

---

可以，不微调模型也能明显提升现有 LLM 的表现。核心思路是：**推理时增强 + 外部能力扩展 + 更好的解码策略**。下面按“成本从低到高、见效从快到慢”整理。

---

## 一、零成本：提示工程和上下文学习

这些方法只改 prompt，不花额外训练成本，但效果往往很显著。

### 1. 明确角色、目标和约束
不要让模型猜你要什么。

差的提示：
> 帮我写个方案

更好的提示：
> 你是一名资深 B2B SaaS 产品经理。请为一个面向中型企业的数据分析平台写一份上线发布方案。要求：  
> - 结构包含背景、目标、关键动作、时间表、风险  
> - 语言简洁，不超过 800 字  
> - 用 Markdown 输出

### 2. 给 Few-shot 示例
给 2~5 个高质量示例，能大幅提升分类、抽取、结构化输出、风格模仿等任务效果。

示例：
> 输入：这个手机续航太差了  
> 输出：{"sentiment": "negative", "aspect": "battery"}  
>   
> 输入：屏幕很清楚，但有点贵  
> 输出：{"sentiment": "mixed", "aspect": "screen,price"}  
>   
> 现在输入：物流很快，包装也很好

示例要贴近任务、格式一致。用检索选择相似示例效果更好，这就是“动态 few-shot”。

### 3. 思维链 Chain-of-Thought，CoT
对推理、数学、逻辑、复杂决策类任务，让模型“先想后答”。

可以简单加一句：
> 请一步一步思考，先分析再给出最终答案。

更稳定的是要求它输出推理过程：
> 先列出已知条件，再列出求解步骤，最后给出答案。

零样本 CoT 在很多推理任务上能带来几个点到十几个点的提升。

### 4. 结构化输出约束
让模型输出 JSON、XML、Markdown，或者指定字段，能减少解析失败、提高可用性。

例如：
> 请只输出 JSON，不要输出其他内容。格式如下：  
> {"summary": "...", "keywords": ["..."]}

### 5. 任务分解
复杂任务不要让模型一次完成。

可以这样设计：
> 请先制定一个计划，列出步骤。  
> 然后逐步执行，每步给出结果。  
> 最后汇总成最终答案。

这比直接让它写长篇内容质量更高。

## 二、低成本：采样与解码策略

这些方法会增加一些推理成本，但不需要训练。

### 1. 调整 temperature 和 top_p
- 精确任务，例如分类、抽取、数学、代码：用 `temperature=0` 或接近 0，贪婪解码。
- 创意任务，例如写作、头脑风暴：可以用 `temperature=0.7~0.9`，但配合多候选。

很多人在 API 里默认用高 temperature，导致精确任务不稳定。调低 temperature 是最便宜的提升。

### 2. Self-Consistency，自洽性
对推理类任务特别有效：

1. 让模型用 CoT 生成 5~10 条推理路径；
2. 对最终答案进行多数投票。

例如数学题，单次 CoT 正确率可能 70%，self-consistency 可以提升到 80%+。代价是多次采样，token 成本增加，但不需要训练。

### 3. Best-of-n 采样
生成多个候选答案，然后用规则、打分模型或人工选择最佳。

如果任务有明确评价标准，例如代码是否能运行、答案是否符合格式，可以自动筛选。

### 4. 多模型集成或辩论
用两个模型互相评审：
- 模型 A 生成答案；
- 模型 B 批评/打分；
- 让模型 A 根据反馈修改。

即使只有一个模型，也可以让它自己“扮演批评者”来改进。

## 三、无训练扩展：RAG 与工具调用

如果任务需要外部知识、实时信息、精确计算，LLM 本身可能不够。这时可以通过外部模块扩展能力。

### 1. RAG，检索增强生成
适用：知识问答、企业文档、专业领域、实时信息。

做法：
1. 把文档切块，向量化，存入向量库；
2. 用户提问时检索 top-k 相关片段；
3. 把片段拼进 prompt，并要求模型只根据资料回答。

示例 prompt：
> 请根据以下资料回答问题。如果资料中没有答案，请说“资料中未提及”。  
> 资料：  
> ...  
> 问题：...

RAG 能显著降低幻觉，提升知识密集型任务表现。构建成本低，不需要训练。

### 2. 工具调用 / Function Calling
让模型调用外部工具，弥补计算、搜索、代码执行等短板。

常用工具：
- 计算器：精确数学计算；
- 搜索引擎 / API：实时信息；
- 代码解释器：执行代码、处理数据；
- 数据库 / SQL：查询结构化数据。

例如让模型做复杂日期计算，不如让它调用 Python 函数。

### 3. ReAct / Agent 模式
让模型按照“思考 → 行动 → 观察 → 再思考”循环工作。

示例：
> 你可以使用以下工具：  
> - search(query)：搜索互联网  
> - calculator(expression)：计算数学表达式  
>   
> 请先思考下一步该做什么，然后调用工具，观察结果，继续推理，直到给出最终答案。

这种模式对多步问题、信息检索、数据分析非常有效。

## 四、自我改进与多智能体工作流

不需要训练，但可以通过多轮推理提升质量。

### 1. Self-Refine
让模型生成答案后，再让它自己批评并修改。

分三步：
1. 生成初稿；
2. 让它列出初稿的问题；
3. 根据问题重写。

例如：
> 请指出上面答案中的错误、遗漏和逻辑不通之处，然后给出改进后的版本。

### 2. 验证器过滤
如果任务有可自动验证的标准，可以生成多个候选，再自动筛选：
- 代码：运行测试用例；
- 数学：用计算器验证；
- 事实：用检索结果核对。

### 3. 多智能体协作
一个模型负责生成，一个模型负责批评，一个模型负责修改。可以用同一模型扮演不同角色，也可以混合不同模型。

## 五、系统层优化：降低推理成本和延迟

这些方法主要提升“性能/成本”比，让同等成本下能跑更多推理。

### 1. 量化与推理加速
- 使用 AWQ、GPTQ、GGUF 等量化方案；
- 使用 vLLM、TensorRT-LLM、llama.cpp 等推理框架；
- 开启 FlashAttention。

这不会降低输出质量太多，但能大幅降低显存占用和推理成本。

### 2. 推测解码 Speculative Decoding
用小模型快速生成候选 token，由大模型验证。可以保持大模型输出质量，同时加速 2~3 倍。

### 3. KV Cache 前缀缓存
如果大量请求共享相同前缀，例如相同的 system prompt 或 RAG 文档，可以缓存 KV cache，减少重复计算。

### 4. 批处理与连续批处理
提高吞吐，降低单位 token 成本。尤其适合离线批量任务。

---

## 六、实践配方：不同任务怎么组合

| 任务类型 | 推荐组合 |
|---------|---------|
| 推理/数学 | CoT + Self-Consistency + 计算器工具 |
| 知识问答 | RAG + 引用要求 + 低 temperature |
| 代码生成 | 多候选 + 运行测试 + Self-Refine |
| 分类/抽取 | Few-shot + 结构化输出 + 低 temperature |
| 写作/创意 | 大纲-草稿-自我批评 + 多候选重排 |
| 长文档分析 | 任务分解 + 分段处理 + 汇总 |

---

## 注意事项

1. **这些方法不能给模型增加它原本没有的知识**。如果模型本身能力很弱，提升有限。
2. **多次采样会增加 token 成本**，建议只在关键任务上使用 self-consistency 或 best-of-n。
3. **提示过长会稀释注意力**。保留关键信息，去掉噪音。
4. **如果任务需要大量新领域知识或风格**，最终可能仍需要微调或换更强模型。但在此之前，先试这些方法，通常能低成本拿到明显提升。

最推荐先试的三招：  
- 低 temperature + 清晰结构化提示  
- CoT + Self-Consistency  
- RAG / 工具调用  

这三类组合起来，在很多场景下能带来“看起来像换了个更强模型”的提升。
