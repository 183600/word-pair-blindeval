# [v2:deepseek-v4-pro] 任务2 提升LLM性能 | 条件: baseline | 第 8 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 49.02s | tokens: 94/3142

---

低成本、不额外训练提升现有 LLM 性能，核心思路是把“算力/知识/结构”从训练阶段转移到**推理阶段、上下文阶段、外部工具阶段**。下面按成本从低到高、实用性排序。

---

## 一、提示词与上下文工程（几乎零成本）

### 1. 明确角色、受众和输出格式
不要只问问题，要给模型一个“身份”和“约束”。

**差：**  
`帮我写一份产品介绍`

**好：**  
`你是一名资深消费品文案，面向25-35岁女性用户，请用小红书风格写一份主打“温和清洁”的洗面奶产品介绍，200字以内，包含3个卖点，结尾引导购买。`

---

### 2. 提供高质量 Few-shot 示例
给模型看 2-5 个高质量示例，往往比长指令更有效。

- 示例要覆盖不同情况：正常、边界、错误案例
- 示例格式要和目标输出完全一致
- 示例顺序最好随机或按难度排列

示例：
```
输入：这款手机续航怎么样？
输出：用户询问续航，应回答电池容量、典型使用时长，并给出充电建议。

输入：它和iPhone比哪个好？
输出：用户在做对比，应中立对比关键参数，避免贬低竞品。
```

---

### 3. 使用思维链（Chain-of-Thought）
让模型先推理再回答，能显著提升数学、逻辑、多步推理任务。

**两种方式：**
- 零样本：在提示末尾加一句
  ```
  请一步一步思考，先分析问题，再给出最终答案。
  ```
- 少样本：给出包含推理过程的示例

---

### 4. 结构化提示：分隔符、标签、JSON
用清晰的标记划分信息，减少模型混淆。

```
请根据以下【文档】回答【问题】。

【文档】
{{文档内容}}

【问题】
{{用户问题}}

要求：
- 如果文档没有答案，回复“无法确定”
- 回答控制在100字以内
```

---

### 5. 重要信息放首尾
LLM 对开头和结尾的信息更敏感。  
把关键约束、背景放开头，把输出格式放结尾。

---

## 二、推理时策略（少量额外推理成本，但无需训练）

### 1. Self-Consistency 自一致性
同一问题用较高温度采样多次，然后对多个答案投票。

```
温度设为 0.7
采样 5 次
对答案做多数投票 / 聚类
```

数学题、逻辑题、分类任务提升明显。

---

### 2. Best-of-N + 评分选择
生成多个候选答案，然后用规则或 LLM 自己打分选出最优。

评分方式：
- 规则：格式是否正确、是否包含关键词
- LLM-as-judge：让模型扮演裁判，给多个答案打分

---

### 3. 自我反思 / 自我修正
先生成答案，再让模型批判自己，然后改进。

```
第一轮：请回答以下问题……
第二轮：请指出上面回答中的错误、遗漏和逻辑问题
第三轮：根据批评重新回答
```

---

### 4. 任务分解
把复杂任务拆成子问题，逐个解决。

```
请先把这个问题拆成3个子问题，然后依次回答，最后汇总。
```

---

## 三、检索增强生成 RAG（外接知识，无需训练）

很多性能不足不是模型笨，而是“缺知识”。  
把外部文档检索后拼进 prompt，成本很低。

### 做法：
1. 准备知识库：PDF、网页、数据库
2. 用 embedding 或关键词检索相关片段
3. 把检索结果放进 prompt，让模型基于材料回答

```
请根据以下资料回答问题，不要使用资料以外的知识。

【资料】
{{检索到的片段}}

【问题】
{{用户问题}}
```

### 动态 Few-shot 检索
从历史数据/标注集中检索与当前问题最相似的示例，比固定示例更有效。

---

## 四、工具调用与 Agent 工作流

让模型不要硬算、硬记，而是调用工具。

### 1. 调用计算器 / 代码解释器
数学计算、日期计算、数据处理，让模型生成代码或调用工具。

```
你可以使用 Python 来计算。请生成代码并执行，然后给出最终答案。
```

### 2. 搜索工具
给模型接入搜索 API，让它先搜索再回答。

---

### 3. ReAct 框架
让模型“思考-行动-观察”循环执行。

```
你可以使用以下工具：搜索、计算器。
格式：
思考：我需要先查什么？
行动：搜索("xxx")
观察：搜索结果如下……
```

---

## 五、多模型协作 / 集成

如果你能调用多个模型或多个配置，可以互相提升。

### 1. 多模型投票
不同模型或同一模型不同温度生成多个答案，投票。

### 2. 辩论机制
让两个模型/同一模型两个角色互相质疑，最后总结。

```
模型A：回答并给出理由
模型B：指出A回答的问题
模型A：修正回答
```

### 3. 级联路由
小模型先处理简单问题，没把握再转给大模型。  
成本低，质量接近大模型。

---

## 六、解码参数与结构化输出

### 1. 调整解码参数
- 事实问答/代码：`temperature=0` 或低温度，`top_p=0.9`
- 创意生成：`temperature=0.7-1.0`
- 减少重复：加 `repetition_penalty=1.05-1.1`
- 长回答：适当提高 `max_tokens`

### 2. 约束解码 / 结构化输出
强制模型输出 JSON、固定选项，减少格式错误。

工具：  
- OpenAI JSON mode  
- Guidance  
- Outlines  
- vLLM structured output

示例：
```
请从["正面","负面","中性"]中选择一个作为情感标签。
只输出一个词。
```

---

## 七、工程与上下文管理

### 1. 长上下文压缩
长对话、长文档可以先让模型摘要，再送入后续 prompt。

```
请先压缩以下内容，保留关键信息，再基于压缩内容回答。
```

### 2. 记忆管理
在多轮对话中，维护一个结构化记忆：

```
用户偏好：喜欢简短回答
历史问题：咨询过退货政策
当前意图：想退款
```

### 3. 缓存常见问题
相同或相似问题直接返回缓存结果，节省成本和延迟，不直接提升模型能力，但能提升系统整体性能。

---

## 八、一个可复用的组合流程

针对较难任务，可以串起来：

1. **检索**相关示例和资料  
2. 构建**结构化 prompt**：角色 + 资料 + 示例 + 输出格式  
3. 加一句 `请一步步推理`  
4. 温度 0.7 **采样 5 次**  
5. 用规则或 LLM **投票/打分**选最优  
6. 让模型**自我检查**一次  
7. 解析输出，失败则**重试**

这个流程通常能比默认单次生成提升明显，尤其在数学、逻辑、分类、抽取任务上。

---

## 需要注意

- 这些方法不会突破模型本身的能力上限，但往往能把“已有能力”更稳定地激发出来。
- “大幅提升”取决于任务：推理类、格式类、知识类提升明显；开放创作类提升有限。
- 多次采样、RAG、工具调用会增加少量推理成本，但相比训练成本可以忽略不计。
