## 回答 A

不更新模型权重、不做微调，通过**推理时策略、上下文工程、系统架构**等方法，可以在很多场景下显著提升现有 LLM 的表现。下面按“成本从低到高、见效快慢”分类整理。

---

## 一、提示词与上下文工程（成本最低）

### 1. 优化系统提示词
给模型明确角色、目标、输出格式和限制，往往能直接提升质量。

**示例：**
> 你是一名资深数据分析师。请阅读以下用户问题，先提取关键信息，再给出分析，最后用 JSON 格式输出：`{"analysis": "...", "conclusion": "..."}`。不要编造数据，信息不足时写“未知”。

### 2. 加入 Few-shot 示例
提供 2~5 个高质量示例，让模型模仿格式和推理方式。  
示例最好从真实数据中**检索相似样本**，而不是随机选。

### 3. 使用思维链（Chain-of-Thought, CoT）
在提示词中要求模型逐步推理，尤其适合数学、逻辑、代码等任务。

**示例：**
> 请一步一步思考，先列出已知条件，再推导，最后给出答案。

### 4. 任务拆解
把复杂任务拆成多个步骤，让模型分步完成，而不是一次性生成。

**示例：**
> 第一步：总结文章要点；第二步：分析优缺点；第三步：给出改进建议。

### 5. 负面约束
明确告诉模型“不要做什么”，能减少幻觉和格式错误。

**示例：**
> 不要使用“可能”“也许”等模糊词；不要输出表格以外的内容。

### 6. 上下文排序与压缩
LLM 对上下文开头和结尾的信息更敏感。  
- 把重要信息放在**开头或结尾**。  
- 长文档先做摘要或提取关键段落，减少噪声。

## 二、推理时解码与采样策略（提升输出质量）

### 1. 自一致性（Self-Consistency）
对同一问题采样 5~10 条推理路径，然后对最终答案投票。  
能显著提升数学、常识推理等任务的准确率，代价是推理成本增加。

### 2. Best-of-N 重排序
生成多个候选答案，然后用规则、奖励模型或另一个 LLM 打分，选最优答案。  
适合需要高质量单一输出的场景，如摘要、翻译、代码生成。

### 3. 自我反思与修正
让模型生成答案后，再让它检查并改进。

**示例：**
> 请检查你的答案是否有逻辑错误、事实错误或遗漏，然后给出修正版。

注意：反思可能引入新错误，建议限制迭代次数。

### 4. 计划-执行模式
先让模型列出计划，再按计划一步步执行。  
适合复杂任务、长流程任务。

### 5. 调整解码参数
- **降低 temperature**：提高稳定性，减少随机错误。  
- **调整 top_p**：控制多样性。  
- **设置停止序列**：防止生成冗余内容。  
- **增加重复惩罚**：减少循环重复。

### 6. 约束解码 / 结构化输出
强制模型输出合法 JSON、SQL、正则表达式等，避免格式错误。  
常用框架：llama.cpp、vLLM、Outlines、guidance、OpenAI JSON mode。

## 三、外部知识与工具（提升事实性与能力边界）

### 1. RAG（检索增强生成）
将外部知识库（文档、FAQ、数据库）向量化，查询时检索 Top-K 相关片段作为上下文。  
能大幅减少幻觉，提升事实准确性，成本低，无需训练。

**适用场景：** 客服问答、企业知识库、法律/医疗问答等。

### 2. 工具 / 函数调用
让模型调用外部工具来弥补自身弱点：
- 计算器：解决精确计算  
- 搜索引擎：获取最新信息  
- 代码解释器：执行代码验证  
- 数据库查询：获取结构化数据

**示例：** 用户问“2025年某股票涨幅”，模型调用搜索 API 获取数据，而不是凭记忆回答。

### 3. 知识库缓存
高频问题直接返回缓存答案，减少重复调用成本。

## 四、系统架构与工作流（提升整体系统性能）

### 1. 多模型路由
用低成本小模型处理简单请求，复杂请求才调用大模型。  
可以大幅降低成本，同时保持整体质量。

**示例：** 先用小模型判断意图，简单寒暄直接回复，复杂问题转大模型。

### 2. 多模型集成 / 投票
用不同模型（或同一模型不同采样）生成多个答案，投票或让一个 LLM 评估。  
不同模型有互补性，能提升鲁棒性。

### 3. 多智能体工作流
设计多个角色协作：
- 规划者：拆解任务  
- 执行者：生成内容  
- 批评者：检查问题  
- 修改者：优化输出

适合复杂任务，如报告生成、代码审查、内容创作。

### 4. 语义缓存
对相似请求做 embedding 相似度匹配，命中缓存则直接返回，降低延迟和成本。

### 5. 量化、投机解码、批处理
这些不提升输出质量，但能大幅提升推理速度和吞吐，降低部署成本。  
- 量化：INT8/INT4 加速推理  
- 投机解码：小模型起草，大模型验证  
- 批处理：合并请求提高 GPU 利用率

## 五、自动提示词优化

无需训练模型，通过搜索算法自动优化提示词。

### 常用工具：
- **DSPy**：自动优化提示词和示例选择。  
- **APE（Automatic Prompt Engineer）**：自动搜索最优提示。  
- 遗传算法 / 强化学习搜索提示词组合。

适合有明确评估指标的任务，如分类、抽取、问答准确率。

## 推荐组合方案

| 场景 | 推荐方法 |
|------|----------|
| 通用任务 | 优化提示词 + Few-shot + 结构化输出 |
| 数学/逻辑推理 | CoT + 自一致性 + 反思 |
| 事实性问答 | RAG + 工具调用 |
| 代码生成 | 约束解码 + Best-of-N + 测试用例过滤 |
| 生产系统降本 | 模型路由 + 语义缓存 + 量化/投机解码 |
| 复杂任务 | 多智能体工作流 + 计划-执行 + 反思 |

---

## 注意事项

- 这些方法不是万能的，提升幅度取决于任务类型和模型能力。  
- 增加采样、反思、多智能体会增加推理成本和延迟，需要设置预算。  
- 建议建立评估集，量化提升效果，而不是仅凭感觉判断。

**核心思路：不训练模型，而是通过更好的提示、更多的推理时计算、外部知识和工作流设计，把模型已有的能力更充分地发挥出来。**

## 回答 B

低成本、不需要额外训练、大幅提升现有 LLM 性能，核心思路是：**不改变模型权重，只改变输入、输出、解码和系统编排**。以下是主要方法：

### 1. 提示工程与上下文学习
- 优化系统提示、角色设定、语气风格。
- 给少样本示例，让模型模仿格式与推理方式。
- 明确输出格式：JSON、表格、列表、标题层级。
- 设置边界、禁忌、检查清单和成功标准。
- 让模型先分析问题，再给出答案。

### 2. 推理策略升级
- 使用思维链、逐步推理、任务分解。
- 复杂问题用“计划—执行—验证”流程。
- 采用自洽采样：多次采样，然后多数投票。
- 使用思维树、图搜索、回溯验证。
- 让模型自我反思、自我批评后再修正。

### 3. 检索增强与外部知识
- 接入向量库、知识图谱、文档检索。
- 将检索到的片段放入上下文，减少幻觉。
- 对长文档先摘要压缩、去重降噪再给模型。
- 常见问题缓存答案，降低重复计算。

### 4. 工具调用与结构化输出
- 让模型调用搜索、计算器、代码执行等工具。
- 约束输出为 JSON/XML/表格，减少格式错误。
- 用正则、语法约束、停止序列控制生成。

### 5. 解码参数调优
- 事实型任务：降低 temperature、top_p，减少随机性。
- 创意型任务：适当调高 temperature，增加多样性。
- 使用束搜索、重复惩罚、长度惩罚。
- 对低置信度输出触发重试或人工兜底。

### 6. 集成与投票
- 同一问题用不同提示模板生成多个答案。
- 对多个答案做一致性、相似度、质量评分。
- 多数投票或加权评分选出最终答案。

### 7. 上下文管理
- 长对话定期摘要压缩，保留关键状态。
- 关键信息前置，避免丢失重要约束。
- 分块处理长文本，再合并结果。

### 8. 自我改进循环
- 模型生成初稿后，再让自己评分、找错、修改。
- 设置验证清单，逐项检查完整性、正确性、逻辑性。
- 多轮迭代直到满足质量指标。

这些方法可以叠加使用。例如：  
**系统提示 + 少样本示例 + 检索知识库 + 思维链 + JSON 输出约束 + 低温解码 + 多次采样投票**，通常能在不训练模型的情况下，显著提升复杂任务的准确率、稳定性和可用性。
