## 一、提示与推理策略（零成本）

这些方法直接从“思维链 分解”“反思 自洽”“多路径 验证”等词获得灵感，只改变提示方式即可提升推理正确率。

### 1. 思维链与任务分解
不要只问结果，要求模型分步推理：
- 使用 `Let's think step by step`
- 使用“先分析问题，再给出答案”
- 将复杂任务拆成子任务，逐步执行  
对应“任务 分解”“子任务 规划”“中间 检查点”。

### 2. 自一致性采样
对应“自我 一致性”“多样本 采样”“投票 集成”：
- 让模型对同一问题生成多个答案
- 用投票或评分选择最一致的答案
- 可以设置温度为 0.7，采样 5-10 次，然后投票

### 3. 反思与自我修正
对应“反思 修正”“自我 改进”“自我 验证”：
- 让模型先生成答案，再让它自己检查错误
- 提示：“请检查你的答案是否符合题目要求，如果不符合请修正”
- 多轮自我修正可以显著降低简单错误

### 4. 约束与角色设定
对应“约束 角色”“系统 提示”“指令 跟随”：
- 在系统提示中明确角色、边界、格式要求
- 例如：“你是专业法律顾问，回答必须引用法条，不得推测”
- 约束输出长度、格式、语气，减少无效内容

### 5. 少样本示例
对应“少样本 few-shot”“示例 选择”“上下文 学习”：
- 提供 2-5 个高质量示例，让模型模仿
- 示例的顺序、格式、标签一致性会影响效果
- 示例应与当前任务高度相似

## 二、检索增强与外部记忆（低成本）

对应“记忆 检索”“知识图谱 向量库”“检索 增强”“引用 事实核查”等词。

### 6. RAG 检索增强生成
- 将企业知识库、文档切成块，存到向量库
- 用户提问时先检索相关片段，再拼接到 prompt 中
- 让模型仅根据检索到的资料回答，并要求引用来源
- 工具：LangChain、LlamaIndex、Milvus、FAISS、Pinecone

### 7. 引用与事实核查
对应“引用 溯源”“事实 核查”“来源 可靠”：
- 要求模型给出可验证的引用、链接或出处
- 对重要事实，在 prompt 中明确：“如果不确定，请回答‘不确定’”
- 后处理校验：用规则或搜索引擎验证关键实体和数字

### 8. 长期记忆与摘要压缩
对应“摘要 记忆”“滑动窗口 长期记忆”“上下文 压缩”：
- 长对话中，定期将上文进行摘要压缩
- 只保留关键决策、约束和事实
- 避免上下文窗口超限，同时保持连贯

## 三、结构化输出与工具使用

对应“结构化 输出”“格式 JSON”“函数 调用”“工具 调用”“代码 解释器”等词。

### 9. 强制结构化输出
- 要求模型输出 JSON、XML、Markdown 表格等格式
- 使用 JSON Schema 或函数调用功能约束字段
- 后处理自动解析、验证，失败后重试

### 10. 函数调用与计算器
- 对数学计算、日期计算等，不要让模型心算
- 使用函数调用执行 Python 代码或计算器
- 对应“代码 解释器”“计算器 数据库”

### 11. 工具链编排
- 将搜索、数据库、API、文件解析等工具接入模型
- 使用 ReAct 模式：推理并调用工具，观察结果后继续
- 这能大幅提升实时性和事实准确性

## 四、推理系统优化（低成本工程）

对应“缓存 量化”“批处理 并行”“投机解码 解码加速”“KV缓存 优化”等词。

### 12. 量化与推理加速
- 使用 4bit/8bit 量化的模型版本，如 GPTQ、AWQ、GGUF
- 使用 vLLM、TensorRT-LLM、llama.cpp 等推理引擎
- 这是加载阶段优化，不需要重新训练

### 13. 投机解码
- 用小模型快速生成草稿，大模型验证
- 可以提升 2-3 倍生成速度，不影响输出质量

### 14. 批处理与动态批处理
- 将多个请求合并成 batch 处理，提升吞吐
- 使用 vLLM 的 continuous batching

### 15. 缓存系统
对应“缓存 LRU”“语义缓存 精确缓存”“prompt缓存”：
- 精确缓存：相同 prompt 直接返回缓存结果
- 语义缓存：用向量相似度判断相似请求，返回缓存
- 减少重复调用，降低延迟和成本

## 五、多模型路由与集成

对应“路由 小模型”“大模型 兜底”“投票 集成”“加权 融合”等词。

### 16. 模型路由
- 简单任务用便宜的小模型，复杂任务用大模型
- 训练一个轻量分类器判断任务难度，或使用规则路由
- 可以节省大量成本，同时保证高难度任务质量

### 17. 模型集成
- 对关键任务，用多个模型或多个采样结果进行投票
- 加权融合：根据历史表现给不同模型权重
- 对应“多智能体 协作”“仲裁 投票”

### 18. 蒸馏到提示
- 用大模型生成高质量少样本示例或推理链
- 将这些示例固定到小模型的 prompt 中
- 不训练小模型，只利用大模型产生提示资产

---

## 六、自我验证、后处理与安全

对应“自我 验证”“规则 过滤”“注入 检测”“越狱 防御”“内容 过滤”等词。

### 19. 输出后处理
- 规则过滤：过滤违规词、敏感信息、重复内容
- 格式修复：JSON 解析失败时，自动重试或正则修复
- 实体校验：检查地名、时间、数字是否合理

### 20. 安全护栏
- 检测用户输入中的提示注入、越狱尝试
- 对输出进行内容安全过滤
- 使用现成工具：Llama Guard、NeMo Guardrails、regex 规则

### 21. 置信度校准
- 使用模型输出的 logprobs 判断置信度
- 低置信度回答触发人工审核或模型重答
- 提高可靠性，减少幻觉

---

## 七、评测与持续迭代

对应“评估 指标”“提示 评估”“监控 告警”“日志 追踪”等词。

### 22. 建立离线评测集
- 选取真实业务问题，标注标准答案
- 每次调整提示词或系统后快速回归测试
- 指标：准确率、ROUGE、BLEU、F1、人工评分

### 23. 错误分析
- 记录模型错误类型：幻觉、格式错误、逻辑断裂、知识缺失
- 针对错误类型改进 prompt 或增加检索内容
- 不需要重新训练，只需迭代提示和流程

### 24. 监控告警
- 监控延迟、错误率、成本、用户反馈
- 使用日志记录所有请求与响应，便于追踪和优化

## 总结

不需要额外训练即可大幅提升现有 LLM 性能，核心思路是：

1. **用更好的提示和推理策略挖掘模型已有能力**  
2. **用检索和外部工具补充模型知识边界**  
3. **用结构化输出和工具调用减少错误**  
4. **用缓存、量化、路由和推理优化降低成本与延迟**  
5. **用自我验证、集成和后处理提升可靠性**  
6. **用评测和监控持续迭代**

这些方法可以组合使用，通常能比单纯调 API 快几倍、准很多、成本更低。

## 六、自我验证、后处理与安全

### 19. 输出后处理
- 规则过滤：过滤违规词、敏感信息、重复内容
- 格式修复：JSON 解析失败时，自动重试或正则修复
- 实体校验：检查地名、时间、数字是否合理

### 20. 安全护栏
- 检测用户输入中的提示注入、越狱尝试
- 对输出进行内容安全过滤
- 使用现成工具：Llama Guard、NeMo Guardrails、regex 规则

### 21. 置信度校准
- 使用模型输出的 logprobs 判断置信度
- 低置信度回答触发人工审核或模型重答
- 提高可靠性，减少幻觉

## 七、评测与持续迭代

### 22. 建立离线评测集
- 选取真实业务问题，标注标准答案
- 每次调整提示词或系统后快速回归测试
- 指标：准确率、ROUGE、BLEU、F1、人工评分

### 23. 错误分析
- 记录模型错误类型：幻觉、格式错误、逻辑断裂、知识缺失
- 针对错误类型改进 prompt 或增加检索内容
- 不需要重新训练，只需迭代提示和流程

### 24. 监控告警
- 监控延迟、错误率、成本、用户反馈
- 使用日志记录所有请求与响应，便于追踪和优化

## 总结

不需要额外训练即可大幅提升现有 LLM 性能，核心思路是：

1. **用更好的提示和推理策略挖掘模型已有能力**
2. **用检索和外部工具补充模型知识边界**
3. **用结构化输出和工具调用减少错误**
4. **用缓存、量化、路由和推理优化降低成本与延迟**
5. **用自我验证、集成和后处理提升可靠性**
6. **用评测和监控持续迭代**

这些方法可以组合使用，通常能比单纯调 API 快几倍、准很多、成本更低。
