——从这些词中获得灵感：  
“根系/菌丝”对应知识互联与检索增强；“回声/峡谷”对应自反馈与反思循环；“齿轮/咬合”对应任务拆解与流程编排；“星火/原野”对应少样本示例激发；“镜面/梦境”对应让模型自我校验；“罗盘/磁暴”对应约束与纠偏。

以下是不需要额外训练、低成本大幅提升现有 LLM 性能的方法：

### 1. 提示层优化：性价比最高
- 使用结构化提示：角色、任务、背景、约束、输出格式、示例。
- 给 3–5 个高质量示例，示例质量比数量更重要。
- 要求思维链：让模型先分步推理，再给最终答案。
- 让模型先复述问题、列出假设、标注不确定项。
- 明确输出格式：JSON、Markdown、表格、列表等。

### 2. 知识注入：不训练也能增强
- 使用 RAG：检索外部知识后拼入 prompt，关键信息放在开头或结尾。
- 对长文档先抽取相关片段，再让模型基于片段回答。
- 用重排序模型提升检索精度，成本低但效果明显。
- 给模型提供工具说明，让它调用计算器、数据库、API 弥补精确知识不足。

### 3. 推理与自校验策略
- 自一致性：同一问题采样 5–7 次，温度略高，投票选择最一致答案。
- 反思循环：生成初稿后，让模型以批评者身份找错并修改。
- 多步规划：先列大纲、拆解任务，再逐步生成。
- 自我提问：让模型回答前先问“有没有反例？边界条件是什么？”

### 4. 解码与输出约束
- 事实类、推理类任务用低温度；创意类任务用较高温度。
- 调整 top_p、frequency_penalty、presence_penalty 减少重复。
- 使用 JSON mode 或约束解码，避免格式错误。
- 设置停止词，防止冗余输出和跑题。

### 5. 系统与工作流优化
- 缓存常见请求，使用语义缓存降低重复调用成本。
- 小模型路由：简单任务用小模型，复杂任务再用大模型。
- 多模型投票或集成，提升鲁棒性。
- 后处理校验：正则、schema 验证、规则过滤器，失败自动重试。

### 6. 组合优先级
如果只做一件事：**优化提示 + 少样本示例 + 思维链**。  
如果做两件：加入 **RAG 或外部知识**。  
如果做三件：加入 **自一致性/反思循环**。  
如果做四件：加入 **结构化输出、约束解码、缓存和路由**。

本质上是把模型已有的能力激发出来：更好的上下文、更多推理预算、更严的结构约束、更多次采样验证。这些方法不需要微调，成本远低于训练，但可能增加一些推理延迟和 token 消耗。
