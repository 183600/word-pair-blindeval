在不额外训练、不更新模型权重的前提下，大幅提升现有 LLM 性能，核心思路是：**优化提示、上下文、解码策略和推理时流程**。这些方法成本低、见效快，适合快速落地。

### 1. 提示层优化：成本最低，收益最直接

- **结构化提示**：明确角色、任务、步骤、输出格式、限制条件。  
  例如：“你是资深数据分析师。请按以下步骤处理：1. 理解问题；2. 提取关键变量；3. 给出结论。最终用 JSON 输出。”
- **少样本示例**：给 2–5 个高质量示例，模型通常比长段说明表现更好。  
- **思维链**：要求模型“先逐步推理，再给最终答案”，能显著提升数学、逻辑、复杂推理任务。  
- **自我一致性**：同一问题采样多次，用多数投票决定最终答案。  
- **反向约束**：明确告诉模型“不要做什么”，并给出错误示例，减少跑偏。

### 2. 检索增强生成：补知识，降幻觉

- 把外部文档、知识库切块并建立索引。  
- 查询时先检索相关片段，再拼接到上下文里。  
- 混合检索：向量检索 + 关键词检索，效果通常更好。  
- 对检索结果做重排，把最相关内容放在前面。

RAG 不需要训练，能显著提升专业领域问答、事实准确性和长文档理解。

### 3. 推理时计算放大：用算力换质量

- **Best-of-N**：生成多个候选回答，用规则、验证器或奖励模型选最优。  
- **多路径投票**：对多个采样结果投票，适合有明确答案的任务。  
- **自我反思/自我修正**：让模型先生成答案，再让它批评并修改自己的答案。  
- **任务分解**：把复杂任务拆成子任务，分别处理后再汇总，减少遗漏和混淆。

### 4. 解码与输出控制：少犯错就是提升

- 根据场景调整温度、top_p、top_k：  
  - 精确任务：低温度，如 0–0.3；  
  - 创意任务：高温度，如 0.7–1.0。  
- 使用结构化输出或约束解码，强制输出 JSON、XML、正则等格式，减少格式错误。  
- 设置合理的停止词、最大长度、重复惩罚。  
- 对输出做后处理校验：格式检查、事实核对、规则过滤。

### 5. 工程化组合：降本增效

- **模型路由**：简单任务用小模型，复杂任务用大模型，避免浪费。  
- **结果缓存**：相似查询直接复用结果，减少重复调用。  
- **工具调用**：让模型调用计算器、搜索 API、代码执行器，减少自身计算错误。  
- **多智能体/流水线**：规划、执行、检查分开，不同角色互相审查，能减少单模型盲区。

### 6. 上下文优化：让模型看见更关键的信息

- 删除无关内容，降低噪声。  
- 重要指令放开头或结尾，中间放参考资料。  
- 对长文档先摘要压缩，保留关键信息。  
- 动态选择示例：根据当前输入检索最相似的 few-shot 示例，而不是固定示例。

---

**优先级建议**：  
先做提示工程、结构化输出和思维链；然后上 RAG；再叠加 Best-of-N、投票、自我修正；最后用模型路由和缓存降低长期成本。  

这套组合不需要额外训练，基本只靠工程和推理阶段优化，通常能带来明显性能提升。
