## 回答 B（baseline）

# 低成本提升现有 LLM 性能的方法（无需训练）

## 一、提示词工程（成本最低，收益最直接）

**1. 思维链（Chain-of-Thought）**
- 加入"让我们一步步思考"，推理任务准确率可提升 10-40%
- 提供 few-shot 示例比 zero-shot 效果更稳定

**2. 结构化提示**
- 明确角色设定（"你是一位资深XX专家"）
- 用分隔符（```、XML标签）划分指令与数据
- 明确输出格式要求（JSON、表格、步骤列表）

**3. 自我反思 / Self-Refine**
- 让模型先输出答案，再让它"检查并改进自己的回答"
- 多轮自我批评可显著提升代码和写作质量

## 二、解码策略优化（零成本调参）

| 参数 | 建议 |
|------|------|
| temperature | 事实性任务调低（0-0.3），创意任务调高 |
| top_p | 配合 temperature 使用，常用 0.9-0.95 |
| repetition_penalty | 长文本生成时防止重复 |
| max_tokens | 给推理任务留足空间，避免截断思维链 |

## 三、采样与集成方法（多花推理成本换性能）

**1. Self-Consistency（自洽性）**
- 同一问题采样 5-10 次，取多数投票结果
- 数学/推理任务提升显著（GSM8K 上可提升 10%+）

**2. Best-of-N**
- 生成多个候选，用奖励模型或模型自身打分选最优

**3. 多模型集成**
- 让不同模型回答同一问题，再让其中一个汇总/仲裁

## 四、RAG（检索增强生成）

- 把知识库/文档切块 + 向量检索，喂给模型作为上下文
- 解决幻觉和知识过时问题，不需要微调
- 注意：chunk 大小、检索 top-k、重排序（rerank）对效果影响很大

## 五、任务拆解与工具调用

**1. 复杂任务拆成子任务**
- "规划 → 执行 → 验证"流水线，每步单独调用

**2. 外挂工具弥补短板**
- 计算交给代码解释器/计算器
- 搜索交给搜索引擎
- 精确查询交给数据库/SQL

## 六、上下文工程

- 重要信息放在**开头或结尾**（模型对中间位置记忆弱，"lost in the middle"）
- 精简无关上下文，避免噪声稀释注意力
- 长对话定期总结压缩

## 七、输出后处理

- 用规则/代码校验输出格式，不合法则重试
- 关键事实让模型引用来源，便于核验
- 数值结果用程序二次验证
