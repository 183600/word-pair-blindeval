# 低成本、无需训练即可大幅提升LLM性能的方法

从上面词对中提炼出**七大实战方向**：

## 1. 提示工程（性价比最高）
- **思维链（CoT）**：加一句"让我们一步步思考"，推理类任务准确率可提升10-30%
- **少样本示例**：给3-5个高质量输入输出示例，效果接近微调
- **角色设定+明确约束**：规定格式、长度、受众、禁止事项
- **结构化提示**：用XML/Markdown标签分隔指令、上下文、示例

## 2. 检索增强生成（RAG）
- 把知识库嵌入向量数据库，按需检索注入上下文
- 解决幻觉、知识过期、私有数据问题，**零训练成本**
- 配合查询改写、混合检索、重排序可再提升20%+

## 3. 采样与解码策略
- **自我一致性**：同一问题采样5-10次，多数投票取答案（推理任务显著提升）
- 调整temperature：事实任务用0-0.3，创意任务用0.7-1.0
- 设置合理的stop token和重复惩罚

## 4. 任务分解与多步推理
- 复杂任务拆成"规划→执行→检查"流水线
- 先生成大纲再填充内容（两阶段生成）
- 让模型先自我批评再修订（反思循环）

## 5. 工具调用（Agent化）
- 接计算器、代码解释器、搜索引擎，弥补模型算术/实时信息短板
- 函数调用让模型"会做"而不是"会说"

## 6. 上下文工程
- 关键信息放在开头和结尾（对抗"中间遗忘"）
- 压缩历史对话、剔除冗余，提高信息密度
- 用程序做后处理校验（JSON合法性、事实核对）

## 7. 系统级组合拳
- **模型级联**：简单问题用小模型，难题路由到大模型，成本降50%+
- **评估闭环**：建测试集→错误分析→针对性改提示，持续迭代
- **缓存复用**：相似查询直接命中缓存

**优先级建议**：提示工程 > RAG > 自我一致性 > 工具调用 > 系统优化。通常仅靠前两项就能让现有模型表现提升一个档次，且几乎零成本。

## 回答 B（baseline）

# 低成本提升 LLM 性能的方法（无需训练）

## 一、提示词工程（成本最低，见效最快）

**1. 思维链（Chain-of-Thought）**
- 加入"让我们一步步思考"，推理任务准确率可提升 10-30%
- 零样本 CoT 完全免费，效果立竿见影

**2. Few-shot 示例**
- 在提示中给 2-5 个高质量输入输出示例
- 对格式要求严格的任务效果极好

**3. 角色设定 + 明确指令**
- "你是一位资深XX专家"
- 把任务拆解成清晰的步骤说明，明确输出格式（如 JSON Schema）

**4. 自我反思/自我修正**
- 让模型先生成答案，再让它"检查并改进自己的回答"
- Self-Refine、Reflexion 等技巧，只需多调用一次

## 二、解码策略调优（零成本）

- **温度调低**（0~0.3）：事实性、代码任务更稳定
- **重复惩罚**：避免复读
- **Structured Output / 约束解码**：强制输出合法 JSON，消除格式错误
- **Best-of-N 采样**：生成多个答案，用规则或模型自评选最优

## 三、检索增强（RAG）

- 幻觉问题的首选方案：把相关知识检索出来塞进上下文
- 轻量做法：BM25/向量检索 + 重排序，不需要训练模型本身
- 对知识密集型任务提升巨大

## 四、上下文工程

- **关键信息放开头或结尾**（模型对中间内容注意力弱，"lost in the middle"）
- 清理无关上下文，减少干扰
- 长文档先让模型做摘要/提取，再回答

## 五、集成与投票

- **Self-Consistency**：同一问题采样多次，多数投票，推理任务提升显著
- 多模型集成：不同模型回答后互相评判

## 六、任务拆解（Agent 化）

- 复杂任务拆成"规划 → 执行 → 验证"多步
- 给模型工具（计算器、代码执行、搜索），把不擅长的部分外包
- 代码任务：让模型写代码并实际运行验证，失败则重试

## 七、系统层面优化

- **输出验证 + 自动重试**：用规则/解析器检查输出，不合法就带着错误信息重新生成
- **缓存常见查询**：降低成本同时可用更贵的模型处理难例
- **路由策略**：简单问题用小模型，难问题用大模型

## 性价比排序建议

| 方法 | 成本 | 典型收益 |
|------|------|---------|
| CoT / 提示词优化 | 几乎为零 | 高 |
| 解码参数调整 | 零 | 中 |
| Few-shot 示例 | 低 | 中高 |
| RAG | 中 | 高（知识任务）|
| Self-consistency | 中（多倍调用）| 高（推理任务）|
| 工具调用/代码验证 | 中 | 高（特定任务）|

**建议起点**：先花一天时间做提示词优化 + 解码调参 + 输出验证，通常能解决 50% 以上的问题，再按需叠加 RAG 和 self-consistency。
