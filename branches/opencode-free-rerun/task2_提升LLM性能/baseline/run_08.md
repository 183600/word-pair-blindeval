# 不训练也能大幅提升 LLM 效果的实用方法

## 一、提示词工程（成本几乎为零，收益最大）

**1. 结构化提示词**
- 明确角色、任务、约束、输出格式
- 用分隔符（```、XML 标签）区分指令和数据，避免注入混淆

**2. Few-shot 示例**
- 给 2~5 个高质量输入输出示例，效果常超过微调小模型
- 示例要覆盖边界情况，格式严格一致

**3. 思维链（Chain-of-Thought）**
- 加一句"让我们一步步思考"，推理类任务准确率可提升 10~30%
- 或明确要求"先分析，再给结论"

**4. 输出格式约束**
- 要求输出 JSON/表格，配合 schema 说明，减少解析错误

## 二、推理时计算（Inference-time Scaling）

**1. Self-Consistency（自一致性）**
- 同一问题采样 5~10 次（temperature 调高），投票取多数答案
- 数学、逻辑题效果显著

**2. 任务分解**
- 复杂任务拆成多步调用，每步输出作为下步输入
- 比单次长提示更稳定

**3. 自我反思/验证**
- 让模型生成答案后，再发一轮"检查上面的答案是否有误并修正"

## 三、RAG（检索增强生成）

- 把知识库/文档切块，用向量检索召回相关片段塞进上下文
- 解决幻觉和知识过时问题，无需重新训练
- 低成本方案：BM25 关键词检索 + 简单重排即可起步

## 四、参数与系统工程

| 手段 | 说明 |
|---|---|
| 调低 temperature | 事实性任务设 0~0.3，减少胡编 |
| 系统提示词兜底 | 写明"不知道就说不知道"可显著降幻觉 |
| 上下文管理 | 关键信息放开头或结尾（模型对中间内容容易遗忘） |
| 缓存 | 相同前缀/重复查询用缓存，省钱又提速 |
| 路由策略 | 简单问题用小模型，难题用大模型 |

## 五、工具增强（Agent 化）

- 计算交给代码执行器，搜索交给搜索引擎
- 模型只做规划和判断，绕开其算术/实时信息短板

## 性价比排序建议

1. **先做**：优化提示词 + few-shot + CoT（零成本，见效最快）
2. **再做**：RAG（解决知识类问题）
3. **最后**：self-consistency、多步分解、工具调用（成本略高但效果强）
