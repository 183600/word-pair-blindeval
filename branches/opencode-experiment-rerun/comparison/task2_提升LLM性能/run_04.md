## 回答 A（cleaned_word_pairs）

## 低成本、无需额外训练提升现有LLM性能的方法

**1. 提示工程（收益最大、成本最低）**
- **思维链（CoT）**：加一句"让我们一步步思考"，推理任务准确率显著提升
- **少样本示例**：给3-5个高质量输入输出示例，效果常接近微调
- **角色与约束**：明确角色（"你是资深工程师"）、输出格式（JSON Schema）、长度限制
- **自我反思**：让模型先回答，再自我检查修正（"请检查上述答案的错误"）
- **自我一致性**：同一问题采样多次，多数表决取答案

**2. 检索增强（RAG）**
- 外挂知识库，用向量检索注入相关上下文，解决幻觉和知识过时问题，无需重训
- 优化分块策略、混合检索（关键词+向量）、重排序（rerank）

**3. 推理策略优化**
- **任务分解**：复杂任务拆成多步子任务串行/并行处理
- **工具调用**：让模型调计算器、代码解释器、搜索引擎，弥补计算和事实短板
- **Best-of-N + 验证器**：生成多个候选，用规则或另一个模型打分选最优

**4. 解码与推理参数调优**
- 调整temperature、top_p；事实类任务用低温度
- 投机解码（小模型起草、大模型验证）加速2-3倍，等效降低成本
- KV缓存与前缀缓存复用重复上下文

**5. 系统层面**
- **级联路由**：简单问题走小模型，难题走大模型，成本降50%+
- **语义缓存**：相似问题直接返回缓存答案
- **输出结构化**：用约束解码保证格式正确，减少重试

**实践优先级建议**：先做提示工程+CoT（1天见效）→ 加RAG（1周）→ 自我一致性/工具调用 → 最后做级联和缓存等工程优化。通常这些组合能带来20-50%的有效性能提升，成本几乎为零。

## 回答 B（baseline）

# 不训练就能提升 LLM 性能的实用方法

## 一、推理时计算扩展（Test-Time Compute）

**1. 思维链（Chain-of-Thought）**
- 加一句"让我们一步步思考"即可显著提升推理类任务表现
- 零成本，效果立竿见影

**2. 自洽性采样（Self-Consistency）**
- 让模型生成多个答案，取多数投票结果
- 成本：多几次推理调用，但数学/逻辑任务准确率可提升 10%+

**3. 自我反思/自我修正（Self-Refine / Reflection）**
- 让模型先输出答案，再让它检查并修改
- 适合代码生成、写作类任务

**4. 思维树/最佳N选一（Best-of-N）**
- 生成多个候选，用模型自己或简单规则打分选最优

## 二、Prompt 工程优化

**1. Few-shot 示例**
- 给 3~5 个高质量示例，效果常超过微调
- 示例要覆盖边界情况

**2. 角色设定与结构化指令**
- 明确输出格式（如 JSON Schema）、约束条件
- 把复杂任务拆成多步、多个 prompt 链式调用

**3. 提示词自动优化**
- 用 DSPy、APE 等框架自动搜索最优 prompt，不需要训练模型本身

## 三、RAG（检索增强生成）

- 把知识库内容检索后塞进上下文，大幅减少幻觉
- 用向量数据库（FAISS/Milvus）+ 重排序（reranker）
- 对知识密集型任务提升巨大，成本远低于微调

## 四、解码策略调优

- 调整 temperature、top_p、重复惩罚
- 事实性任务用低 temperature，创意任务调高
- 使用约束解码（如 outlines、guidance）强制结构化输出

## 五、系统层面技巧

**1. 模型路由/集成**
- 简单问题用小模型，难问题用大模型（省钱又保质量）
- 多个模型输出互相验证

**2. 上下文管理**
- 重要信息放在 prompt 开头或结尾（模型对中间内容注意力弱）
- 清理无关上下文，减少干扰

**3. 输出验证与重试**
- 用代码校验输出格式，失败自动重试
- 简单工程手段能显著降低错误率

## 性价比排序建议

| 方法 | 成本 | 提升幅度 | 适用场景 |
|------|------|---------|---------|
| Prompt 优化 | 极低 | 中-高 | 所有 |
| CoT | 极低 | 中 | 推理任务 |
| RAG | 低 | 高 | 知识问答 |
| Self-Consistency | 中 | 高 | 数学/逻辑 |
| 多模型路由 | 中 | 中 | 通用系统 |

**核心思路：把"训练成本"转化为"推理成本"和"工程成本"，通常 80% 的提升来自 prompt + RAG + 多次采样这三板斧。**
