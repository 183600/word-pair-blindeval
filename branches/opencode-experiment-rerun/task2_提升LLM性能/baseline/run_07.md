# 不训练、低成本提升LLM性能的实用方法

## 一、Prompt工程（零成本，收益最快）

1. **Chain-of-Thought（思维链）**
   - 加一句"Let's think step by step"，推理任务准确率可提升10-40%
   - 复杂任务让模型先拆解、再执行

2. **Few-shot示例**
   - 给2-5个高质量输入输出示例，比微调便宜得多
   - 示例要覆盖边界情况，格式严格一致

3. **角色与约束设定**
   - 明确角色（"你是资深后端工程师"）
   - 明确输出格式（JSON schema、markdown模板）
   - 明确"不要做什么"（不要编造、不知道就说不知道）

4. **Self-Consistency（自一致性）**
   - 同一问题采样多次（temperature>0），投票取多数答案
   - 推理任务提升明显，成本只是多调几次API

## 二、推理时计算（Inference-time Compute）

1. **Best-of-N采样**：生成N个答案，用规则/奖励模型/另一个LLM选最好的
2. **自我反思（Reflexion/Self-Refine）**：让模型批判自己的输出再改进，一轮迭代常有明显提升
3. **任务分解**：把大任务拆成多个子任务分别调用，避免单次生成质量衰减
4. **Plan-and-Execute**：先让模型出计划，再逐步执行

## 三、RAG（检索增强生成）

- 幻觉问题的最大杀手，成本远低于微调
- 关键点：
  - **分块策略**比模型选择更重要（语义分块、保留上下文）
  - 混合检索（向量 + BM25关键词）
  - 加**重排序（rerank）**模型，小成本大收益
  - 检索不到时明确告诉模型"资料不足"

## 四、系统层面优化

1. **输出结构化**：用JSON mode / function calling约束输出，减少解析错误
2. **两阶段生成**：先生成草稿 → 再校验/润色（可用小模型起草、大模型精修省钱）
3. **缓存**：相似问题命中缓存，省成本又稳定输出
4. **路由策略**：简单问题用小模型，难题才上大模型（成本降50-80%）

## 五、上下文管理

- **把重要信息放开头或结尾**（模型对中间内容容易"丢失"）
- 精简上下文，无关信息会显著降低质量
- 长对话定期总结压缩历史

## 六、评估驱动迭代

- 建一个50-200条的小型评测集，每次改prompt/RAG都跑一遍
- 没有评估的优化都是碰运气——这是性价比最高的"投资"

## 优先级建议

| 方法 | 成本 | 典型收益 | 适用场景 |
|------|------|---------|---------|
| Prompt优化 | 极低 | 中-高 | 所有场景 |
| RAG | 低 | 高 | 知识型/幻觉问题 |
| Self-consistency | 中（多次调用） | 高 | 推理、数学 |
| 自我反思 | 中 | 中-高 | 写作、代码 |
| 模型路由 | 负（省钱） | 中 | 流量大的产品 |

**核心思路**：把"让模型一次答对"变成"设计一个系统让模型更容易答对"——工程化手段的性价比远超训练。
