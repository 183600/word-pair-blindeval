# [rerun:space-bunny-free] 任务2 提升LLM性能 | 条件: baseline | 第 6 次

**Prompt:** 怎么低成本不需要额外训练大幅提升现有LLM的性能

**耗时:** 18.0s | **tokens:** 200/2201(推理 206) | **finish:** stop

---

# 不训练权重，大幅提升现有 LLM 表现

核心思路：**把能力从"模型参数里"挪到"系统里"**。参数固定的模型，性能上限由输入、上下文、推理流程、输出验证、检索这几层决定，这几层的杠杆通常远大于换模型。

---

## 一、投入产出比最高的 5件事（按 ROI 排序）

| 优先级 | 手段 | 典型收益 | 成本 |
|---|---|---|---|
| 1 | **Prompt 重构**（角色+任务+约束+示例+格式） | 10–40% | 极低 |
| 2 | **少样本 ICL（few-shot）** | 5–20% | 极低 |
| 3 | **CoT / 推理链**（复杂任务必开） | 20–100%+（数学/逻辑类） | token↑2–5x |
| 4 | **Self-Consistency（多数投票/多次采样）** | +10–20% | token↑5–20x |
| 5 | **结构化输出 + Schema 校验 + 自动重试** | 错误率降 50–90% | 极低 |

---

## 二、Prompt 工程（不改权重，改一切）

**1) 用四段式模板，别裸问问题**

```
角色/上下文 →  任务定义（含否定边界）  →  示例2–5 条  →  输出格式契约
```

- 明确"不要做什么"往往比"要做什么"更有效（"不要推测、不用 markdown、不要编造来源"）。
- 示例选择遵循"多样性 > 数量"：覆盖边界 case、易错 case、格式 case，而不是 8 条同质样本。
- 把评判标准写进 prompt（"答案需包含数值、单位和适用条件，否则判为不合格"），让模型自检。

**2) 输出格式契约 + 强制解码**
- 用 JSON Schema / Grammar（structured output / constrained decoding）约束解码，而不是"请你输出 JSON"（后者会漂）。
- 强约束能直接把格式解析失败率从 5–20% 压到 ~0。

**3) 长上下文技巧**
- **指令前置/后置 + 关键信息重复一遍**（lost-in-the-middle 问题）。
- 对超长文档先做**地图式摘要**（先生成索引/摘要，再按需展开）。
- Prompt 压缩：用小模型把长示例/长文档压缩成"要点卡片"，保留指令原样。

---

## 三、推理时计算扩展（Test-Time Compute）——不训练也能变强

同一模型，多花推理算力换准确率：

1. **CoT**：默认关闭的模型，加 "一步一步推理" 收益巨大。
2. **Self-Consistency**：采样 k=5~20 次（temperature 0.7~1.0）取多数答案，或对数值/答案集取中位数/投票。数学、规划、多步推理提升最明显。
3. **Best-of-N + 判别器**：采样 N 个候选，用规则、规则引擎、小模型、或 LLM-as-judge 打分选最优。**验证比生成更容易**——这是最便宜的"能力外挂"。
4. **Self-Refine / Critique 轮次**：生成 → 自评/批评 → 改写，1–2 轮通常有效，超过 3 轮容易"越改越差"。
5. **树搜索**：Beam Search、Tree-of-Thought、MCTS 类（配合打分器）用于规划类任务。
6. **难例路由**：简单问题直答（省钱），难题才开 CoT+投票（保质），用长度/置信度/启发式分类器分流。

> 成本控制：把上述策略**条件触发**（只在分类器判定为难题时开启），平均成本通常只涨 1.5–3x。

---

## 四、RAG：给模型"开外挂知识"

- **检索质量 > 生成质量**：先优化召回（混合检索 BM25 + 向量 + 元数据过滤），再做重排（cross-encoder / LLM rerank）。Rerank 往往带来 10–30% 的端到端提升。
- **分块策略**：按语义/结构切（标题、段落、表格整体），chunk 200–500 token + 20% 重叠，比固定 256 字符切片好很多。
- **查询改写 / HyDE / 多查询扩展 / 指代消解**（把"它"还原成实体名），能显著提升召回。
- **引用与溯源**：要求答案带引用片段，便于校验；同时抑制幻觉。
- **"闭卷先答再检索"对比**能测出到底缺的是知识还是推理。
- 长文档/多跳场景可用 **GraphRAG / 层次摘要索引**。

## 五、工具与外部能力（最被低估的一层）

模型不该做它不擅长的事：

- **工具调用**：计算器（数值精确率从 ~70% 到 100%）、代码执行（自己写、自己跑、自己修循环）、SQL、API 调用、正则/字符串处理、日期时间、单位换算。
- **Agent脚手架**：ReAct 式循环 + 明确的停止条件、步数上限、错误回传；工具失败信息要**原样回喂**给模型。
- **代码生成 + 沙箱执行 + 单测过滤**：对结构化/数据类任务，正确率常比纯文本 CoT 高一个量级。
- **MCP / 外部检索**把最新知识和私有数据接入，无需训练。

> 经验法则：**凡是有确定答案的任务，先想"能不能不靠模型算"。**

---

## 六、多模型编排（路由 + 协作）

成本几乎不变，效果大涨：

- **级联**：小模型先答，置信度低/校验失败才升级到大模型。省50–80% 成本，且不损失质量。
- **难度路由**：按任务类型分配到最擅长的小模型。
- **多模型投票**：异构模型（不同厂商/不同尺寸）做集成，成本高但准确率显著提升。
- **大模型当"教师"，小模型当"学生"**（**蒸馏到输出层，不训练权重**）：小模型学大模型的 CoT 轨迹 + 多次采样做 best-of-N，逼近大模型 90%+ 效果。
- **判别器模型/专用打分器**比生成模型便宜得多，训练判别器比改生成器容易。

---

## 七、解码与推理服务优化（吞吐 / 时延 / 稳定性）

- 参数：`temperature / top_p / frequency_penalty / stop / max_tokens` 按任务类型分别调优（抽取类用 0，创作类用 0.7–1.0）。
- 投机解码（Speculative Decoding）：小模型起草、大模型验，**无损**加速 2–3x。
- KV Cache复用、前缀缓存（Prompt Cache）、连续批处理 → 同样效果、更低单价。
- 量化（FP8 / INT4 / AWQ）省显存、提吞吐；注意**逻辑推理任务对精度损失更敏感**，要做 A/B。
- 长上下文的 attention/缓存优化。

> 这些主要优化**成本和速度**，质量提升有限，但让你有预算去做上面那些"高 token 消耗"的质量手段。

---

## 八、结果后处理与校验层

- Schema 校验 + 规则校验（数值范围、单位、必填项、跨字段一致性）。
- **自动重试**：解析失败或校验失败时，把错误原因回喂重生成（1–2 次）。
- 去重、归一化、分类映射。
- 置信度校准 → 决定是否升级到大模型。

---

## 九、评测先行（不做 A/B 的优化都是玄学）

建立100–500 条**黄金集**（含难例和边界例），指标至少分：
- 端到端正确率 / F1 / 精确匹配
- 格式合法率
- 幻觉率、引用准确率
- 单次成本、单次延迟、P95

用**离线回放 + 线上 AB + 影子流量**三层验证。每次只改一层因素，避免归因混乱。

---

## 十、一个可落地的实施顺序（2–4 周）

1. 建评测集 + 打基线（3 天）
2. Prompt 重构 + Schema 约束输出（3 天）→ 通常立刻见效
3. 加 few-shot + CoT + 条件触发的 self-consistency（1 周）
4. 上 RAG（含 rerank）用于知识型任务（1–2 周）
5. 接工具/代码执行用于可验证任务（1 周）
6. 加后处理校验 + 级联路由降本（1 周）
7. 持续做 Best-of-N / 判别器 / 蒸馏

---

## 关键认知

- **不训练 ≠ 不改造**。90% 的收益来自**上下文工程 + 流程设计 + 外部验证**。
- **准确率提升的边际成本递增**：第一层几乎免费，第七层非常贵。所以务必**分层叠加、按需触发**。
- 少数场景（稳定的领域风格、极长尾格式）LoRA/QLoRA 微调反而更便宜——如果允许"极轻量训练"，30 行 PEFT 代码通常优于任何 prompt 技巧。但先做1–8步再考虑。
