# 低成本、不训练模型、显著提升 LLM 性能的方法

核心思路：**能力上限由基座决定，但实际表现 60~80% 来自"外面的工程"**。按投入产出比排序如下。

---

## 一、Prompt /上下文工程（ROI 最高）

| 手段 | 具体做法 | 典型收益 |
|---|---|---|
| **结构化指令** | 角色 + 任务 + 约束 + 输出格式 + 示例，分段写清 | 20~40% |
| **Few-shot** | 3~10 个高质量示例，覆盖易错边界；示例比描述有效 | 10~30% |
| **负向约束** | 明确"不要做什么"（不要编造、不要寒暄、只用给定材料） | 减少幻觉 |
| **思维链** | 对复杂推理显式要求"先分解再作答" | 数学/逻辑 +10~30% |
| **上下文压缩/排序** | 长文档放最前/最后（lost-in-the-middle），中间内容摘要化 | 长文任务 +5~15% |

---

## 二、解码层（Sampling）调参 —— 零成本

```python
# 追求正确性（推理/代码/数学）
temperature=0 或 0.2, top_p=0.95

# 追求多样性（创意/文案）
temperature=0.8~1.0, top_p=0.9
```

其他高价值开关：
- **停止序列 + 后处理校验**：JSON 输出后用 `json.loads` 校验，失败则重试（配约束解码/grammar）
- **结构化解码**：用 XGrammar / Outlines / guided decoding，**从概率上保证格式合法**，等于免费加了校验器
- **`min_p` 采样**（>0.02）：比 top_p 更稳的去尾部方案
- **预填充助手首段**（如直接填 `{"answer":`），稳定格式

---

## 三、推理时扩展（Test-time Compute）—— 最强"免费"增益

1. **Self-Consistency（自一致性）**
  同一问题采样 k=5~20 次（温度0.7），投票/取众数。数学、分类任务 **+5~20%**。成本 ×k。

2. **Best-of-N + 验证器**
  生成 N 个答案，用规则/打分模型/单元测试筛选，输出最优。代码任务可用编译器+测试用例直接过滤。

3. **Self-Critique / Reflexion**
  让模型自己输出后再自我检查并修正一轮；或"找出错误→只改错误处"的重写流程（无训练版 ReAct）。**+5~15%**

4. **多角色辩论 / 多视角**：同一问题用不同专家 Prompt 各答一遍，再让一个"裁判"模型综合。

5. **分解（Decomposition）**：把复杂任务拆成子问题链，逐步求解，避免一次性过载。

---

## 四、检索增强 RAG（替代训练，最实用）

Fine-tune 不如把知识塞进 context。要点：

- **混合检索**：BM25（关键词）+ Dense（向量）用 RRF 融合 → 通常 +10%
- **重排序**：cross-encoder rerank（bge-reranker 等）取 Top-20→Top-5 → **+10~20%**
- **查询改写/多查询扩展**：HyDE（先用 LLM 生成假想答案再检索）、问题分解
- **分块策略**：按语义/结构切分（512~1024 token + overlap），父子块（检索小块、送入大块）
- **引用约束 Prompt**："只依据以下材料回答，逐句标注出处，无依据则回答'材料不足'" → 大幅降幻觉
- **Graph RAG / 知识图谱**：多跳问答（人物-事件-关系）场景提升明显
- **SQL/代码式取数**：结构化数据让模型生成查询而不是猜数值（Text2SQL + 执行反馈）
- **向量库调优**：embedding 模型选择（HSEB/E5/BGE/v3）、加 metadata 过滤---

## 五、工具调用与 Agent 脚手架（换掉模型短板）

模型的弱点是记忆、精确计算、实时性、动作执行 —— 全部外包给工具：

- **搜索/浏览工具** → 消除知识截止限制和幻觉
- **代码解释器（Python）** → 数学、统计、数据分析准确率从 ~70% 直接到 ~95%
- **数据库 / API 工具** → 精确数值、实时数据
- **日历、文件系统、浏览器自动化**
- **函数调用 + 强制 schema**（配合约束解码）

配一个好的 Agent 循环（ReAct / Plan-and-Execute / 反思）往往比换更大的模型更有效。

---

## 六、路由与级联（小模型 + 大模型组合）

```
简单请求 ──→ 小模型/缓存复杂请求 ──→ 大模型
极难/失败 ──→ 更大模型 or 更大推理预算
```
- **级联**：先便宜模型跑，不确定度（logprob / 置信度）超阈值才升级 →成本降 50~80%，精度保持
- **Prompt 压缩模型**（LLMLingua-2）：把长上下文压缩 50~80% token，省钱 + 降 lost-in-middle
- **语义缓存**：相似问题直接命中答案 → 重复查询零成本
- **Prefix/KV Cache复用**：系统提示词和长文档前缀不变 → 延迟与成本大降

---

## 七、推理部署侧的"免费"提升

- **量化**：FP16→INT8/INT4（AWQ/GPTQ）**掉点很小（<1~2%）**，速度+内存大幅优化；可用量化腾出的显存**换更长上下文或更多采样路径**（如自一致性），反而提效
- **长上下文用完**：FlashAttention / PagedAttention / vLLM → 吞吐提升数倍，间接支持更多并行采样
- **投机解码**：小模型 draft + 大模型 verify，2~3× 提速- **换用推理模型（reasoning / thinking 类）**：如果场景允许更长输出，o 系列/R1 类模型在数学、代码、规划上远超普通模型，且**零训练成本**

---

## 八、输出后处理与校验（别小看）

- **Pydantic / JSON Schema 校验**，失败自动重试 2~3 次
- **代码类任务**：执行测试 → 失败则把报错回灌给模型修复（自动修复循环）
- **去重/归一化**：答案标准化后再比对（大小写、空格、日期格式），避免"假错误"
- **多答案投票 +仲裁模型**
- **正则/规则兜底**：金额、日期、编号类字段用正则校验

---

## 九、评估闭环（决定能不能持续提升）

没有评测 = 玄学调优。最低成本做法：

1. 建 **100~500 条**黄金样本（覆盖典型 + 边界 + 失败案例）
2. 每次改动跑批量评测，记录准确率 / 格式合法率 / 成本 / 延迟
3. 失败样本归类 → 针对性补 few-shot 示例 / 加检索 / 加规则**失败驱动迭代**：把每一个失败案例变成一个示例、一条规则或一个工具，比盲目换模型有效得多。

---

## 十、"不训练"但仍可改变模型行为的两条路

| 方法 | 是否需要训练 | 说明 |
|---|---|---|
| **Adapter/LoRA 微调** | 需要（但极便宜） | 若你预算允许，LoRA 用几千条数据几十分钟就能把准确率拉高 10~30%，仍是"最低训练成本"选项 |
| **Prefix-Tuning / Prompt Tuning / ICL（上下文学习）** | ICL 完全不需要 | 把"训练"结果固化为上下文里的示例，模型权重不变 |

---

## 落地优先级（建议顺序）

```
1. 建评测集（1~2天）              ← 没有这个后面都是盲改
2. Prompt 结构化 + Few-shot + 输出格式约束   ← 当天见效
3. 采样参数调优 + 结构化解码         ← 当天见效
4. 加 RAG（混合检索 + rerank）      ← 数天，收益最大
5. 加工具（代码/搜索/数据库）        ← 数天
6. Self-Consistency / Best-of-N     ← 成本换准确率
7. 级联路由 + 缓存 + 量化            ← 降本
8. Reflection / 验证器循环           ← 最后加，容易放大前面所有收益
```

---

## 一句话总结

> **不要训练模型，把训练该教会模型的东西搬到 context 里（RAG + Few-shot + 工具），把"想清楚"的时间搬到推理时（CoT + 自一致性 + 自我验证），把"不擅长"的部分外包给代码和检索，最后用一套评测集驱动迭代。**

这套组合在多数业务任务上能带来 **30~60% 的准确率提升**，成本增量通常只有原方案的 **2~5 倍**（且用级联+缓存+量化可以把成本压回原水平）。
