**耗时:** 10.8s | **tokens:** 200/1584(推理 163) | **finish:** stop

---

# 不训练也能大幅提升 LLM 性能:一套可落地的清单

核心判断:**90% 的"模型不够聪明"其实是上下文工程 + 推理策略 + 系统工程问题**,而不是权重问题。按 ROI 从高到低:

---

## 一、上下文工程(收益最大、成本最低)

| 手段 | 做法 | 典型收益 |
|---|---|---|
| **系统提示结构化** | 角色 + 任务边界 + 明确"不确定就说不知道" + 输出格式定义 + 少样本示例 | 格式合规率 +20~50% |
| **上下文裁剪/压缩** | 只给相关片段,去掉历史对话噪声、去掉与当前任务无关的文档 | 长文本任务准确率 +5~15% |
| **位置策略** | 关键指令放**结尾**(中间易被忽略, lost-in-the-middle),长文档"首尾加重" | 明显 |
| **结构化输入而非自然语言** | 把混乱文本转成 JSON/表格/Markdown 层级 | 抽取类任务 +10~30% |
| **上下文隔离** | 不同任务用不同 system prompt,别混用;子任务用子代理 | 减少串味 |

>关键点:把"隐含知识"换成"显式注入的证据"。模型知识没变,但你把答案喂给它了。

---

## 二、推理时计算(Inference-time Compute)

1. **CoT / Self-Consistency(自一致性)**
   采样 N 次投票或取最长一致链。数学/推理任务 **+10~30%**,成本仅 N 倍 token。
2. **Best-of-N + 验证器(Verifier)**
   用规则/单元测试/另一个模型打分筛最优输出。代码生成用"能否编译/跑通测试"筛,收益极大。
3. **Self-Refine / Reflexion**
   生成 → 批判 → 修正,2~3 轮。写作/分析类任务明显改善。
4. **Plan-then-Execute**
   先让模型输出步骤计划(可给人看/可检查),再逐步执行,避免一锅端。
5. **Tree/Graph of Thoughts、束搜索、分步拆解**
   用于复杂推理,把一步难题拆成多步简单题。
6. **思考预算控制**
   简单问题用"先判断难度,简单直接答,复杂才长思考"的分级策略,避免全量烧 token。

---

## 三、外部增强(把能力"外挂"进去)

- **RAG 检索增强**
  - 提升点:切分策略(parent-child / late chunking)、**混合检索**(BM25 + 向量 + rerank)、query 改写/多路 query、HyDE(先用模型生成假想答案再检索)、reranker(但 reranker 通常需要训练,可用交叉编码器或 LLM 打分替代)。
  - 效果:知识问答幻觉率可降一半以上,且**知识更新零成本**。
- **工具调用 / 函数调用**
  代码执行、SQL、搜索、计算器、API。让模型算而不是"想"、查而不是"记"。
- **Agent 化**
  多步任务用 ReAct 循环,能自主重试和纠错。
- **路由与级联(Cascade)**
  简单请求 → 小模型/缓存/关键词匹配;难题 → 大模型。
  同样效果下 **成本可降 50~90%**,同时**延迟大幅下降**。

---

## 四、提示自动优化(替代人工调 prompt)

- **DSPy**:用 few-shot 示例 + 自动优化指令与示例,从数据集编译出最优提示 —— 无需训练权重。
- **GEPA / MIPRO / OPRO**:语言模型作为优化器,迭代改写提示;GEPA 相对人工调优常有可观提升。
- **Automatic Prompt Engineer(APE)**
- **A/B + 评测闭环**:建100~300 条评测集,提示改动全部跑回归,**没有评测集的调优等于玄学**。

---

## 五、采样与输出控制

- 温度/top-p 按任务分层:抽取=0,创作=0.8,推理=0.3~0.6。
- 结构化输出(JSON Schema / grammar约束解码):消除格式重试。
- **Prefix Caching(提示缓存)**:固定长 system prompt + few-shot 放前面,命中率高的场景成本可降 70%+,延迟大降。
- **长上下文技巧**:文档地图 + 分段检索,优于"全文硬塞"。
- **停止序列/预填充**:预填答案开头(如 `{"result":`),强制模型走对路径。
- **Self-Ask / 少样本选择**:动态挑最相关的 3~5 个示例,而不是固定示例。

---

## 六、推理部署侧(同样"不训练")

- **量化**(INT8/INT4 / FP8):几乎无损,显存和速度大幅改善 → 允许开更高采样数、更长上下文。
- **投机解码(Speculative Decoding)**:小模型起草、大模型验证,**输出分布完全一致**,纯赚 2~3x 速度。
- **批处理/连续批处理、KV cache 复用、PagedAttention**
- **Self-host 开源模型 + 选对尺寸**:很多场景14B~32B 指令模型优于更大的通用模型,配合上面几招差距可抹平。
- **置信度门控**:logprob 低就升级到大模型或转人工。

---

## 七、七天落地顺序(推荐)

1. 建 200 条评测集(真实业务失败案例)← **前提,别跳过**
2. 改 system prompt:角色/边界/格式/拒答规则3. 上结构化输出 + 采样参数调优
4. 加 3~5 条动态精选示例
5. 难题开 CoT + Self-Consistency +验证器
6. 加 RAG(含 query 改写 + rerank)
7. 加工具调用与级联路由
8. 开启 prefix caching、量化、投机解码 → 省钱提速反哺质量
9. 用 DSPy/GEPA 做提示自动优化,回到第 1 步验证

---

## 一句话总结

**不训练时,提升 = 更好的上下文(RAG/工具) + 推理时计算(CoT+验证) + 采样多样性 + 系统工程(缓存/量化/路由)。**
投入顺序:评测集 → 提示与上下文 → 推理策略 → RAG/工具 → 路由降本 → 自动优化。
其中 RAG + 自一致性 + 级联路由这三招,通常能拿到 **最大收益/最低成本**的组合。
