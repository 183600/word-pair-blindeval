# 低成本、不训练模型、立刻提升现有 LLM 性能的方法

核心思路：**把能力从"模型权重"转移到"系统与提示"上**。下面按投入产出比排序。

---

## 一、提示工程（Prompt）— 收益最高，成本最低

|技巧 | 说明 | 典型提升 |
|---|---|---|
| **结构化提示** | 角色 + 任务 + 约束 + 输出格式 + 示例，分段写清 | 20–50% |
| **Few-shot 示例** | 3–10 个高质量样例（覆盖正例/边界/易错例），比纯零样本强很多 | 15–40% |
| **Chain-of-Thought / 推理链** | 让模型"先想后答"，复杂推理任务必需 | 30–100%（数学/逻辑类） |
| **输出格式锚定** | 给出明确的 schema（JSON/表格/字段），并加"只输出 JSON，不要解释" | 大幅减少解析失败 |
| **分隔符 & 指令位置** | 用 `###`、XML 标签包裹输入；长提示中**关键指令放结尾**（中间易被忽略） | 5–15% |
| **自检/反思步骤** | "写完后逐条核对是否满足所有约束，不满足则重写" | 10–30% |

**要点**：失败案例集 > 完美提示词。把线上 bad case 逐条沉淀成 few-shot 示例，是最快的收益来源。

---

## 二、上下文工程（Context Engineering）

- **只放相关信息**：上下文里 80% 的无关内容会显著稀释效果 → 先做检索/过滤/压缩
- **位置策略**：重要信息放**开头和结尾**（中间注意力弱，"lost in the middle" 现象）
- **长文档处理**：先做 map-reduce 式摘要/逐段抽取，再汇总，而不是一次性塞进 128k
- **压缩对话历史**：摘要 + 保留最近 N 轮 + 抽取关键事实到"记忆文件"
- **剔除干扰样例**：上下文里的错误示例会拉低准确率，宁缺毋滥

---

## 三、测试时计算（Test-Time Compute）— 不用训练也能"变强"

1. **Self-Consistency（自一致性）**：同一问题采样 k 次（temperature 0.7–1.0），投票/取多数答案。数学、分类任务可 +10–25%
2. **Best-of-N + 打分**：生成多个候选，用规则、模型或验证器打分后选最优
3. **Verifier / 反思重写**：初稿 → 批评模型找问题 → 修正。相当于免费造了个 critic
4. **分解任务**：复杂任务拆成多个更小的调用，每步验证，最后汇总

> 代价是 token 消耗上升 k 倍，但无需训练，是"用推理预算换准确率"的经典范式。

---

## 四、少样本学习代替微调

想微调但没数据/没算力？

- **In-Context Learning**：few-shot 示例本身就是"免训练微调"
- **合成数据蒸馏**：让强模型（GPT-4/Claude/Opus）批量生成高质量问答对/指令数据 → 用于强模型自己的 few-shot 或作为检索内容
- **知识抽取代替参数注入**：把领域文档做成"可检索知识"而非训进模型

---

## 五、RAG（检索增强生成）— 注入知识与实时性

不训练就能让模型知道私域/最新知识：

```
Query改写/多查询扩展 → 混合检索(BM25 + 向量) → Rerank → 拼接 Top-k
```
关键增益点（按影响排序）：
1. **Reranker**（bge-reranker / cross-encoder）— 通常 +10–20%，最容易被忽略
2. **Chunk 策略** — 按语义/结构切分，重叠 10–20%，加"标题+摘要"前缀
3. **混合检索 + 查询扩展**（HyDE：先用模型生成假设答案再做向量检索）
4. **引用约束**："仅依据以下资料回答，资料中没有则回答'不知道'"

---

## 六、工具与外部能力

- **Function Calling / MCP**：让模型调用 API、查数据库、跑代码 →补齐计算、精确性、时效性短板
- **代码执行优先**：数值、字符串、SQL 类任务，让模型写代码并执行而非直接心算
- **结构化校验 + 自动重试**：解析失败时把错误回传给模型修复

---

## 七、模型路由与降级（成本与性能双赢）

```
简单请求 → 小模型(GPT-4o-mini / Qwen-Lite / Llama-3.1-8B)
复杂请求 → 大模型
```
- **级联（Cascade）**：小模型先答，置信度低/校验失败再升级到大模型 → 大幅降本且保精度
- **专用模型路由**：翻译/摘要/分类/代码各用其擅长的模型
- 开源侧：按场景换更匹配的基座（数学用 Qwen-Math，代码用 Qwen-Coder，中文用 Qwen/GLM）

---

## 八、自动提示优化（Auto-Prompt Optimization）

手工调提示是低效的，用工具自动迭代：
- **DSPy**：把 prompt 变成可优化模块，用评测集 + MIPRO/GEPA 自动搜索指令与示例
- **TextGrad / OPRO / PromptWizard**：自动改写提示
- **FlowGPT / Promptfoo**：批量 A/B 测试提示变体，用真实评测集选最优

> 只要有 100–300 条评测样本，就能自动化省下大量人力，且效果往往超过手工 prompt。

---

## 九、推理与部署侧优化（降低延迟/成本，间接提升体验）

开源模型自部署时：
- **量化**：AWQ / GPTQ / FP8 — 显存与吞吐提升数倍，精度损失通常<1–2%
- **vLLM / SGLang**：连续批处理、PagedAttention → 吞吐 5–20×
- **Prefix Cache（KV Cache复用）**：系统提示词固定时，前缀只算一次 → 显著降本- **Speculative Decoding**：小模型草稿 + 大模型验证，延迟降 2–3×
- **语义缓存**：相似问题命中缓存直接返回

---

## 十、评测先行（最重要的一步）

没有评测，以上所有优化都是盲改。

1. 建 **100–500 条黄金评测集**（含边界与失败案例），固定指标（准确率 / F1 / EM / 人工胜率）
2. 建立 **回归测试**，每次改动跑分
3. 用 **LLM-as-a-Judge** 做主观质量的自动评测（配对比较比打分更准）
4. 分层诊断：能力问题 → 换模型；知识问题 → RAG；格式问题 → 提示；推理问题 → CoT

---

## 落地优先级建议```
1. 评测集（无评测不优化）
2. 提示结构化 + 输出格式约束 + few-shot（bad case 驱动）
3. 补齐上下文（检索/过滤/位置调整）
4. RAG + Reranker
5. 工具调用（代码执行/API）
6. Self-Consistency / Verifier 反思
7. 模型路由降本
8. 自动提示优化 DSPy
9. 部署优化（量化、缓存、批处理）
```

**预期效果**：只做 1–4 项，通常可获得 30%–100% 的端到端提升，而无需任何训练；配合 7–9 项，成本还能下降 50%–90%。

---

## 明确无效的做法（省时间）
- ❌ 反复堆砌形容词式 prompt（"你是一个世界级专家…"）而无示例- ❌ 不做评测就换模型
- ❌ 上下文塞满所有可能相关文档
- ❌ 只调 temperature反复试
- ❌ 在无评测集的情况下做复杂架构改造---

**一句话总结**：不训练要提升 LLM，靠的是 **更好的提示 + 更好的上下文 + 测试时多算几次 + 外部工具与检索 + 路由评测**，把"参数里的能力"换成"系统里的能力"。
