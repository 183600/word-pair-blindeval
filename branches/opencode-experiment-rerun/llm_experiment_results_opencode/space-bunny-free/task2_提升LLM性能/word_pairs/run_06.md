## 第二部分：怎么低成本、不额外训练，大幅提升现有 LLM 性能

核心判断：**模型权重不动，但围绕它的"系统"可以动**。实测中，prompt 工程 + 推理期计算 + 工具/RAG + 评测闭环，通常带来 30%~数倍的端到端提升，而训练成本几乎为零。下面按"收益/成本比"从高到低排。

### 层级0：地基——先把评测建起来（1~2 天，最高杠杆）
- 没有评测集，后面所有优化都是盲改。**先攒 100~300 条真实失败/边界 case**，标注期望答案，作为回归集。
- 指标至少三个：任务正确率、格式合规率、平均成本（token+延迟）。**只看准确率会把你优化成又贵又慢。**
- 把评测脚本化，改一版 prompt/流程就跑一次，形成"提示词版本化 + A/B"。

### 层级 1：Prompt 工程（当天见效）
1. **结构化提示模板**：角色/目标 → 上下文（用分隔符隔离）→ 约束规则 → 输出格式（给 JSON Schema 或范例）→ 示例。分隔符（XML标签、`---`）能显著降低指令串扰。
2. **少样本示例3~8 条**，覆盖"易错模式 + 正例 + 一个反例"。比纯文字描述有效得多。示例要用**动态检索**（从示例库里挑最相似的几条），比固定示例强。
3. **位置偏差治理**：最关键指令放**开头和结尾**（lost-in-the-middle 效应）；长文档别硬塞中间，改成摘要或检索片段。
4. **明确"不要做什么"**：加"若信息不足，回答'无法确定'并说明缺什么"，比让它硬编好得多。
5. **强制思考**：在需要推理的任务上加"先列已知事实/分步推导，再给结论"，或用简短分隔的推理块。简单任务则**关闭** CoT 以省钱。
6. **输出约束**：要 JSON 就用结构化输出/grammar 约束解码；不要模型自由发挥格式。

### 层级 2：推理期计算（不加训练，最强增益）
- **Self-consistency / Best-of-N**：同一问题采样 k 次（温度 0.7~1.0），用多数投票或外部打分器选最优。数学、代码、多解问题提升常在 **+10~30 个点**。成本是 k 倍延迟，可并行 + 早停（部分一致就返回）。
- **Verifier模式**：生成 N 个候选 → 用规则/单元测试/另一个便宜的模型/大模型当裁判打分重排（LLM-as-a-Judge + pairwise 比较比绝对打分稳）。适合代码、数学、结构化抽取。
- **分解难题**：复杂任务拆成子问题，每步用更简单的 prompt 做对，最后汇总。避免一次性要求模型"想清楚所有事"。
- **反思/修订**：让模型对自己的输出做一次"逐条检查清单核对 → 只改错的地方"。一轮通常就能修掉大部分低级错误；做2~3 轮收益递减。
- **路由**：难度分级，简单问题走小模型/缓存，难的走大模型。这是成本与效果同时优化的关键手段。

### 层级 3：给模型外挂知识和工具（提事实准确率的关键）
- **RAG 做好这几点，比换 RAG 框架有用**：
  - 分块按语义/结构切，不要固定 512 token 硬切；每块带**标题+来源+时间**。
  - **混合检索**（稠密向量 + BM25）再做 **cross-encoder 重排**，通常 top-5 效果翻倍。
  - **查询改写/多查询扩展 + HyDE**（先让模型生成假设答案，再去检索）。
  - 强制"**只依据给定材料回答 + 逐句标注引用**"，把幻觉从"编造"降级为"误引"，可核查。
- **工具调用优先于模型记忆**：计算 → Python/计算器；查询 → API/SQL；逻辑枚举 → 规则引擎；数学证明 → 符号引擎。让模型写代码执行，比让模型心算可靠一个量级。
- **代码执行做验证闭环**：生成代码 → 沙箱跑测试 → 把报错回灌给模型修。这一步在代码类任务上的收益比任何 prompt 技巧都大。
- **时效与权威**：知识库条目带时间戳和来源优先级，冲突时显式告诉模型"以最新/最权威为准"。

### 层级 4：上下文与记忆管理（控成本又不掉效果）
- **KV/前缀缓存**：固定的开头（系统提示 +少样本示例）放最前，让服务端复用 KV cache，延迟和成本直接降。
- **提示压缩 / 递归摘要**：长对话用分层摘要（滚动摘要 + 关键事实清单），只把相关记忆放进当前上下文。
- **语义缓存**：相似问题直接返回历史答案（相似度阈值 + 置信校验），对 FAQ 类场景省钱立竿见影。
- **上下文"垃圾回收"**：明确告诉模型哪些信息已过期、可以忽略。

### 层级 5：工程与系统层（把上面几条真正跑起来）
- 工作流编排：ReAct / Plan-and-Execute / 多智能体分工（一个做、一个查、一个审）。**注意：多智能体不是免费的**，任务不适合时反而更差，要用评测证明值得。
- 流式输出 + 提前终止 + 超时/重试 + 幂等，降低感知延迟。
- 结构化输出校验（Schema 校验失败自动重试一次并把错误回灌）。
- 安全护栏：输入过滤、输出检查、防提示注入（把外部文档当"数据"而非"指令"处理），这属于"性能"的一部分——一次严重失败抵消所有优化。

### 层级 6：持续改进闭环
- 线上采样 →错误归因分类（知识错 / 推理错 / 格式错 / 检索错）→ 针对根因改对应那一层 → 回归测试 → 灰度发布。
- **合成难例**：用模型自动生成边界 case 并自动判分，持续扩大评测集。
- 记录 prompt/流程的版本、血缘和指标对比，避免"优化 A弄坏 B"。

### 优先级建议（如果只有一周）
1. 建100 条评测集 + 指标面板2. Prompt 模板化 + 少样本 + 输出约束（预期 +10~20 点）
3. 加 Best-of-N + verifier（数学/代码类 +15~30 点）
4. RAG 重排 + 引用约束（事实类提升最大）
5. 难度路由 + 缓存（成本降 30~60%）
6. 反思修订轮、工具执行验证

### 明确不值得做的
- 为了小提升去做全量微调（数据+算力成本远高于上述手段）。
- 无评测就换模型/换框架。
- 在简单任务上堆 CoT 和多智能体（纯烧钱）。

**一句话**：不训练模型，就用"**提示词工程 + 推理期采样与验证 + 外部知识与工具 + 上下文与缓存管理 + 评测闭环**"这五件事，把能力和性价比一起提上去——这也是目前工业界性价比最高的路径。
