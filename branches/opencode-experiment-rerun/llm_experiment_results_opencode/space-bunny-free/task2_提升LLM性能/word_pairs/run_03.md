## 从这些词里长出来的思路：零训练提升 LLM 的「组合拳」

### 一、上下文工程（收益最大、成本最低）
- **上下文工程 > 提示词工程**：把「角色+任务+约束+示例+工具+输出契约+自检清单」拼成结构化模板，一次投入全场景复用（第 1、6、27、40 组）。
- **预填 / 引子**：让模型自己续写开头，强制它进入正确模式（代码、JSON、推理链）。
- **长上下文压缩**：超长历史用「分层摘要」折叠（短期→情节摘要→长期事实），腾出预算给真正相关的证据（第 16、17、94–97 组）。
- **动态少样本**：示例不再是固定 3 条，而是按当前 query检索最相似的 k 条（第 22、23 组）——这一步常比换模型更有效。
- **反例/边界示例**：加入「这样不行」的样例，几乎零成本地压住格式违规与幻觉。

### 二、推理时计算（不加参数，只加推理）
- **自我一致性 / 采样集成**：采样 n 条，投票或取多数结论；数学、抽取、分类类任务立竿见影（第 42、43 组）。
- **最佳-of-N + 验证器**：生成 n 个候选，用规则/单测/小模型打分筛选（第 44、61–64 组）。
- **分治 + 草稿-打磨**：先便宜地产粗解，再让强模型只做批判与修正，避免全程用最贵模型（第 49、55、65、66 组）。
- **辩论 / 多智能体陪审**：一个写、一个挑错、一个裁判，只在难题上触发（第 57–60 组）。
- **树搜索（ToT/GoT）**：对组合、规划类问题展开分支并剪枝，把「算力」花在搜索而非参数上（第 45–54 组）。

### 三、检索与记忆（把参数里的知识搬到上下文里）
- **混合检索**：BM25 + 向量双路召回，再交叉重排（第 82–84 组）。
- **语义缓存**：把相似 query 的结果复用，直接砍掉重复调用成本（第 139、140 组）。
- **会话状态外置**：用结构化「事实台账」代替翻历史，模型只读相关行（第 90–97 组）。
- **新鲜度加权 + 冲突仲裁**：多源信息冲突时按来源权威度与时间戳裁决（第 109、110 组）。
- **工具化**：能用检索、正则、API精确解决的，就别让模型「猜」（第 100–106 组）。

### 四、解码与系统层（同样的模型，更快更便宜）
- **约束解码 / 结构化输出**：用 grammar限定可选 token，消灭 JSON 解析失败与格式返工（第 7、25、26 组）。
- **投机解码**：小模型出草稿，大模型一次并行验证，吞吐 2–3 倍且输出分布无损（第 117、118 组）。
- **KV/前缀缓存**：系统提示与长文档前缀跨请求共享，是「复用」带来的复利（第 91、92、128 组）。
- **连续批处理 + 早停 + 令牌预算**：把并发延迟和成本压下来（第 119、123、131、132 组）。
- **模型级联**：简单请求走小模型，拿不准再升级到强模型，最后人工兜底（第 134–138 组）。

### 五、路由与成本感知（把钱花在刀刃上）
- **难度分类器 + 自适应路由**：零训练也能做——用规则、长度、置信度、logprob熵来判断该不该升级（第 72、73、76、133、193 组）。
- **硬门控**：模型先自评把握度，低于阈值就转人工/转工具，比事后返工便宜得多（第 71、161 组）。

### 六、评估先行（不然无法知道有没有变好）
- **建 100–300 条黄金集 + 自动回归**：每次改提示/换检索/调参数都跑一遍，防止「优化了一个，崩了两个」（第 141–145、153 组）。
- **LLM-as-judge + 人工抽检**：注意位置/长度偏置，并做顺序对调消偏（第 146–148 组）。
- **可观测性**：记录完整轨迹（检索命中、提示版本、每步输出），失败才能归因到具体环节（第 154–157 组）。

### 七、组合与复利
真正管用的不是单点技巧，而是**管道**：检索给证据 → 结构化约束输出 → 验证器打分 → 反思修正 → 缓存复用 → 失败样本入评测集 → 回流成新示例与新提示。这条链每加一环都近乎免费，且互相放大（第 171、189、192、195、199、200 组）。

**优先级建议（按投入产出比排序）**
1. 上下文/提示模板化 + 动态少样本
2. 评测集与回归门禁
3. 结构化输出/约束解码
4. 检索质量提升（混合召回 + 重排）
5. 自适应路由与小模型兜底
6. 自一致性 / 验证器筛选
7. 缓存与投机解码（成本优化）

这七步都不需要任何梯度更新，却通常能吃掉新模型一半的差距。
