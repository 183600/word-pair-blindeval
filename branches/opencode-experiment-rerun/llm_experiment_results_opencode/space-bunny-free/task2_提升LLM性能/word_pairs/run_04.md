# 低成本、不训练，大幅提升现有 LLM 性能

## 核心公式不训练的前提下，性能提升几乎全部来自这六个乘法因子：

> **效果 ≈ 上下文质量 × 解码策略 × 外部工具/检索 × 流程编排 × 校验反馈 × 引擎效率**

微调只是"把写在提示词、检索库、外部流程里的东西搬进权重"。搬不搬得动，先看外面这六项做得多好。

---

## 一、第 0 步：先建仪表盘（1 天，零成本）

没有评测就改提示 = 玄学。最小可行方案：

| 项目 | 做法 |
|---|---|
| 评测集 | 100–300 条真实 case，人工写好"标准答案/判分要点" |
| 指标 | 任务成功率、格式合规率、平均 token、P95 延迟、单次成本 |
| 判分 | LLM-as-judge（强模型打分）+ 20% 人工抽检校准 |
| 资产 | 失败案例库（每条记录：输入、错误类型、根因） |

这张表后面每一步都用来验证是否真的变好。

---

## 二、上下文工程（ROI 最高，24小时内见效）

### 1. 提示骨架：五段式
```
[角色]你是资深 X，负责 Y
[任务]      目标 + 输入 + 边界
[约束]      禁止事项 + 长度/语气/领域术语
[输出契约]  精确 schema（字段、类型、枚举、示例值）
[失败处理]  信息不足时输出 {"status":"need_more_info","missing":[...]}
```

### 2. 指令位置
关键约束**再强调一次放在最后**（中间注意力衰减）。系统提示尽量**静态化**——既提效果，又让 prefix/KV cache 能命中。

### 3. 少样本示例：动态优于静态
- 用 embedding 做 **kNN 检索**，每次挑最相似的 3–8 条示例，而不是一套写死的。
- 示例要**覆盖边界情况**（不只是典型 case）。
- **顺序有讲究**：最关键的那条放最后（近因效应）。
- 示例数不是越多越好，超过 10 条收益递减且吃成本。

### 4. 思维链：给模板，不给口号
"一步一步思考"效果一般。给它**推理骨架/检查清单**：
```
步骤1：识别用户意图 → 步骤2：抽取关键实体 → 步骤3：套用规则 → 步骤4：自检是否违反约束 → 输出
```
复杂推理任务要求"先输出中间结构化计划，再给结论"，结论前置会让模型跳过推理。

### 5. 提示压缩
- 删除重复表述、统一变量名替代长句。
- 文档只放**相关片段**，长文先做层次化摘要（分块→摘要→再摘要），保留关键事实清单。
- 示例去重、片段按"与问题的相关性"排序而非原文档顺序。

### 6. 澄清机制
输入信息不足时，让模型**反问**而不是猜。用一个极廉价的小模型/分类器判断"信息是否足够"，不足才走澄清分支。

## 三、解码层：不改权重，白捡的算力

| 任务类型 | 建议参数 |
|---|---|
| 分类 / 抽取 / 结构化 | temperature=0 或 greedy |
| 问答 / 推理 | 0.3–0.7，配合自洽性 |
| 创作 / 多样性 | 0.8–1.0，top_p 0.9–0.95 |
| 长文本生成长任务 | repetition_penalty 1.05–1.15 抑制循环 |

**三个高性价比技巧：**

1. **自洽性（Self-Consistency）**：同一问题采样 k=5~20 次（温度 0.7），对最终答案做**归一化后多数投票**。数学、逻辑、多步推理上通常是 +5~15 个点，单次成本 ×k 但远比"换模型/训练"便宜。
2. **Best-of-N + 打分器**：生成 N=4~8 个候选，用**重排器 / 规则校验 / 小模型判分 / 单元测试**选最优。这是拒绝采样的在线版，效果常常比单纯升温采样强得多。
3. **置信度阈值 → 分流**：利用 `logprobs` 或多次采样一致率作为置信代理；低于阈值就**升级到更强模型**或**转人工**。这把成本集中在少数难题上，平均成本下降、准确率上升。

## 四、把"算"和"查"交给确定性系统

这是消除幻觉**投入产出比最高**的一步。

- **代码解释器 / 计算器**：数学、单位换算、日期、统计、字符串与表格处理。凡是"精确"需求，一律走代码。让模型写代码 → 执行 → 读结果，比让它心算可靠一个数量级。
- **检索增强（RAG）完整闭环**：
  1. 查询改写 / 多查询扩展（同义词、拆解）
  2. 混合检索：BM25（稀疏）+ 向量（稠密）
  3. **cross-encoder 重排**（这一步常被省略，但它是精度的关键）
  4. 上下文装配：去重、按相关性排序、控制在预算内
  5. 强制"**逐句给引用**"，无引用不许下结论
  6. **答案后验核验**：把答案拆成 atomic claim，逐条检索/蕴含判断（可再用一次 LLM 调用 + NLI 模型）
- **工具调用**：清晰的函数 schema、参数类型校验、失败重试与错误信息回灌。
- **实时 API / 联网搜索**解决时效性问题——LLM 权重里的知识永远有一块过期。

## 五、输出约束 + 自修复循环

- **grammar / schema 约束解码**：用引擎侧能力（llama.cpp GBNF、XGrammar、outlines 等，或 API 的 structured output）把生成限制在合法语法内 → 格式合规率直接到 ~100%。
- **解析失败自动修复**：把报错原文回灌让模型修，最多 2–3 次。
- **测试驱动生成代码**：让模型同时写实现和 assert，跑测试，失败则定向修。代码生成的正确率提升通常比换模型明显。

## 六、从"一次调用"升级为"一个系统"（编排）

- **Plan–Executor**：先规划产出结构化计划（可被程序执行），再逐步执行。子任务可并行、失败可单独重试。
- **分治 / Map-Reduce**：长文档摘要、批量分类，用 map 出中间结论 → reduce 汇总。比一次性塞进去稳得多。
- **反思 / Refine 循环**：生成 → 批评者（拿检查清单挑漏洞：漏了约束？数字对不上？证据不足？）→ 修订。给 2–3 轮并设停止条件，防止无限自我重复。
- **多智能体辩论**：决策类任务，生成 2–3 份独立方案 + 互相反驳 + 裁判汇总。注意：简单任务用辩论是浪费。
- **级联路由**（双模型架构）：
  ```
  请求 → 轻量分类(难度/意图)
        ├─ 简单 → 小模型 + 简短提示
        └─ 复杂 → 大模型 + 完整 CoT + 工具 + 反思
  ```
  平均成本可降 50–70%，准确率不降反升。

## 七、记忆与个性化

- 会话历史用**结构化状态**（已确认的事实、已做的决策）替代全量回放。
- 滚动摘要 + **关键事实单独维护一份清单**，避免摘要丢失硬约束。
- 用户画像/偏好显式注入系统提示。
- 相同或语义相近的请求走**语义缓存**（embedding 相似度超阈值直接返回）。

## 八、同一份权重，部署层还能榨出 30–100%

| 手段 | 收益 |
|---|---|
| **投机解码**（小模型 draft 或同模型草稿 + 主模型验证） | 接受率高时吞吐 1.5–3×，输出分布完全不变 |
| **前缀/KV 缓存复用**（静态系统提示 + 稳定示例前缀） | 显著降首 token 延迟与成本 |

| **算子融合 / FlashAttention** | 降延迟、降显存 |
| **INT8 / INT4 量化**（GPTQ、AWQP） | 部署成本骤降，能力损失可控 |
| 批处理 embedding、结果缓存、限流调度 | 工程侧直接省钱 |
| 长上下文用**滑动窗口 + 摘要**而非无限塞 | 既省钱又提效 |

## 九、可靠性与防幻觉

- **唯一事实源原则**：数字、ID、状态、库存、价格一律走工具/数据库，模型不自由发挥。
- 强制引用 + claim 级核验。
- 开一个 `UNKNOWN / 无法确定` 的合法通道，并要求输出置信度字段。
- 多次采样一致性作为置信代理。
- 外部文本（网页、文档）与指令严格隔离，防提示注入。

## 十、闭环飞轮：让它越用越好，且仍然不训练

```
线上失败样本 → 每周人工标注 → 补进评测集 → 定位根因
   ├─ 提示词没说清 → 改提示/加约束/加示例
   ├─ 缺知识        → 补检索/加工具
   ├─ 格式错        → 上 schema 约束
   ├─ 推理错        → 上自洽性/反思/分解
   └─ 判不准        → 上置信路由/转人工
→ A/B 灰度 → 回归测试护栏 → 全量
```
配合提示词版本管理与消融实验，每次改动都有据可依、不会悄悄退化。

## 十一、优先级路线图

| 时间 | 动作 | 预期 |
|---|---|---|
| **第 1 周** | 评测集 + 五段式提示 + 结构化输出 + 温度调优 + 失败案例库 | 立竿见影，成本最低 |
| **第 2–4 周** | 动态 kNN 少样本 + 自洽性/Best-of-N + 代码执行器 + 置信路由 | 主要指标明显跃升 |
| **第 2–3 月** | RAG 完整闭环（含重排与 claim 核验）+ Plan-Executor + 反思循环 + 投机解码/量化 | 稳定高质量 + 成本下降 |
| **之后** | 提示词持续迭代 + 合成数据；**只有在上下文/检索/流程都吃透了仍有明显瓶颈时**，才考虑 LoRA | 训练成为"最后一步"而非"第一步" |

## 常见坑

1. **提示越写越长**——边际递减，还会稀释注意力。先删，再加。
2. **无脑自洽性 ×k**——简单任务上是纯浪费成本，必须配难度判断。
3. **只做检索不做重排和核验**——RAG 提不上去多半卡在这两环。
4. **不建评测就改提示**——90% 的改动是无效甚至负向的。
5. **什么任务都上多智能体/反思**——简单问题上它显著变慢变贵。
6. **把训练当唯一出路**——在把上面六项做到位之前，训练带来的边际收益远小于系统优化。

---

**一句话总结**：不训练的最大杠杆不是"更聪明的提示词"，而是**把模型从"单次自由发挥"改造成"有上下文、有工具、有约束、有校验、有重试、可分流"的系统**。工程收益通常远超换模型或做微调。
