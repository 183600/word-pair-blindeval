## 二、不训练模型，也能大幅提升 LLM 性能的完整方案

核心判断：**不微调 ≠ 不改造**。模型权重是固定的，但"模型的输入、可用工具、推理时算力、输出校验、上下文组织方式"全都可以改，而这些地方往往藏着 60%~90% 的提升空间。

### 1. 提示层：投入产出比最高，先做这个

**① 结构化提示模板（提示词工程 + 模板填充）**
把"玄学提示词"变成可版本管理的工程资产：
```
[角色] 你是……
[任务] 一句话说明交付物
[约束] 只能依据<资料>回答；不确定时输出"需核实"
[格式] 输出严格 JSON：{"answer":..., "sources":[...], "confidence":0-1}
[示例] 2~3 个少样本示例（覆盖正常/边界/拒答三类）
```
每个变量用模板引擎填充，提示词进 Git，做**版本比对 + 回归测试**，改一版就跑一次基准集。

**② 示例挑选（示例选择 / 相似度选取 / 动态检索）**
少样本示例不是越多越好。做法：把历史 query 过 embedding，为每次请求**动态召回 k 个最相似的高质量示例**注入提示。这叫"即时学习 /动态检索示例"，对分类、意图识别、槽位填充类任务的提升常常比换模型还大。

**③ 采样调参（温度 / 顶P / 重复惩罚 / 停止条件）**
- 抽取、分类、单答案问答：temperature 0~0.3，强制 JSON/正则约束；
- 创意、多方案生成：0.8~1.0 + 多路采样；
- 长文本：调高重复惩罚并设明确 `stop`，避免复读退化。
这一步零成本，但很多团队从未系统做过 A/B。

**④ 反脆弱设计（位置偏置 / 长度归一 / 格式鲁棒）**
同一问题换序重问，答案是否一致？长输入是否仍关注末尾？把这些"提示敏感度"做成体检项。

### 2. 推理时计算：不改权重，加算力就变强

这是当前性价比最高的"免费午餐"：

- **思维链 + 任务分解**：复杂任务先"计划先行"，拆成子问题逐个解决再合并（子问题拆解）。
- **自我一致采样**：同一问题跑 5~20 次（可并行），投票/取多数答案；对推理类任务提升显著。
- **束搜索 / 宽度搜索 / 启发式剪枝**：需要过程正确率时，用推理路径评分做剪枝，控制成本。
- **反思迭代（草稿→修订→编辑反馈）**：让模型自己列检查清单批判上一版输出，改2~3 轮。
- **多智能体 / 批评者代理**：生成者 + 批评者 + 仲裁（裁判模型 / 成对比较），用不同视角（专家视角）互相纠错。
- **早退推理（置信度阈值 + 级联）**：简单问题小模型或短链直接答，只在不确定（不确定度估计 / 日志概率低 / 分布外检测）时才升级到大模型 + 长链。这让"平均成本"下降而非上升。

**关键工程点**：把上面这些做成**统一的可插拔推理管道**，而不是散落在业务代码里。

### 3. 上下文工程：把上下文当"稀缺资源"管理

- **提示压缩 / 记忆压缩**：长对话用层次摘要做滚动折叠，保留原始细节在外部存储，需要时检索回来。
- **位置引导**：关键指令放首尾（对抗位置偏置），中间插入"🔍重点"标记（注意力引导）。
- **引用溯源**：所有事实性结论必须带原文片段编号，便于核查与自动幻觉检测。
- **会话状态 + 个性化档案 + 偏好记忆**：把用户长期偏好存外部结构化存储，按需注入，而不是硬塞进系统提示。

### 4. 检索增强：让知识可更新、可溯源

低成本 RAG 提效四件套：
1. **混合检索**（BM25 关键词 + 向量语义），专治"精确词/编号/型号"召回失败；
2. **查询改写 / 多查询扩展 / 同义扩展**，以及指代消解、歧义消解后的二次检索；
3. **分块策略 + 重排序精排**：切块按语义结构（标题/表格），召回20 条再用 cross-encoder 精排 top 5；
4. **接地证据约束 + 幻觉检测**：答案必须落在引用片段里，否则输出"资料不足"。

文档侧先做好 **OCR / 表格解析 / 文档解析**，很多"模型不行"其实是输入是脏的。

### 5. 工具化与程序化验证：把"会说"变成"会做"

LLM 最弱的是算术、大规模枚举、精确格式。对应做法：

- 给模型挂**工具调用 / 函数声明**接口；
- 让它**写代码执行**（代码沙箱 +单元测试验证），代码跑不通就让模型根据报错自修复；
- 纯计算交给**计算器校验 / 符号求解**；
- 输出经**正则抽取 / 模式匹配 / 语法约束（约束解码）**落地成结构化对象，必要时**后处理修正**；
- 业务规则用**断言检查 / 契约不变式 / 边界情况**做自动门禁。

有工具 + 有验证回路，幻觉率可下降一个量级，而这是纯提示无法做到的。

### 6. 结构化输出与降级兜底

- 全链路 **JSON Schema / 模式约束**，用约束解码从 logits 层保证格式合法，杜绝解析失败；
- 输出后接**后处理修正**（字段补全、单位归一、日期格式）；
- 解析失败有**兜底策略 / 降级方案**（重试一次 → 换解析器 → 人工确认环节）。

### 7. 多模型编排：小成本拿大效果

- **路由选择**：按任务类型、难度、语言分流（翻译回译做跨语言一致性检查）；
- **级联管道**：大模型产出 → 小模型审核（**神经符号**结合，轻量校验）；
- **集成融合**：同任务跑多个模型投票，或"最强模型出方案、小模型批量执行"。

前提是先有**评估基准**，否则无法判断该路由到谁。

### 8. 评估闭环：没有度量就没有提升

建四件套：
1. **评估基准集**：100~500 条真实样本，含难例与已知坑（**极端输入 / 边界情况**）；
2. **自动裁判**：用大模型做成对比较 / 胜率评判，配合正则与单测做硬校验，形成综合指标体系；
3. **回归测试 + 消融实验**：每次改提示/检索/管道都跑一遍，看提升幅度；
4. **误差分析 + 失败归因**：把错分四类（检索错 / 推理错 / 格式错 / 知识缺失），只修占比最大的那一类；
5. 上线后**漂移检测 + 回归监控 + 灰度发布 + 快速迭代**，用户**反馈闭环**回灌成新示例与基准。

用**弱监督/主动学习**把人工标注量压到最低。

### 9. 部署与性能优化（降本+提速，反过来支撑上面所有花招）

- **提示缓存 / 前缀共享**：把长系统提示与 few-shot 前缀固定，命中缓存，token 成本与首字响应时间大降；
- **连续批处理 / 批处理合并 / 流式输出**：吞吐提升数倍，直接让"多路采样 + 反思迭代"从"不可行"变"可接受"；
- **投机解码**：小模型起草、大模型并行验证，延迟接近小模型、质量接近大模型；
- **量化压缩 / 剪枝稀疏**：显存降下来，采样条数就能翻倍；
- **成本记账 / 预算分配 / 边际收益 / 瓶颈定位**：按任务设置 token 与调用预算；**剖析工具 + 追踪可视化**定位真实耗时点。

### 10. 安全与可靠性（不做这步，前面所有提升都可能被一次事故抹平）

- 输入净化、**提示注入防御**（把用户内容与指令隔离、加哨兵标记）；
- 输出**护栏过滤**、敏感信息**隐私脱敏**、**权限控制**、**审计日志**；
- **拒答边界**与"资料不足"的诚实降级；
- 对抗鲁棒性测试。

### 落地优先级建议（两周内可完成80%收益）

| 阶段 | 动作 | 预期 |
|---|---|---|
| 第1周 | 建 200 条评估集 + 锁定基线；提示模板化 + 采样调参；输出改结构化 | 准确率 +5~15pt |
| 第2周 | 上自检/反思回路 + 计算器/代码工具 + 单元测试校验 | 幻觉率显著下降 |
| 第3-4周 | 混合检索 + 重排 + 引用溯源；提示缓存 + 连续批处理 | 成本降 50%+，延迟降 60%+ |
| 第2月 | 自我一致采样 + 早退级联路由；多模型编排 | 复杂推理 +10~20pt |

**一句话总结**：不训练也能变强，路径是"**提示工程 → 上下文工程 → 检索增强 → 工具与验证 → 推理时计算 → 多模型编排 → 工程与评估闭环**"。按上面七层依次加固，通常可以在**零训练成本**的前提下，把一个现成 LLM 从"能演示"推到"能上线"；而**评估基准 + 回归测试**是让这所有改进可持续、不回退的唯一保障。
