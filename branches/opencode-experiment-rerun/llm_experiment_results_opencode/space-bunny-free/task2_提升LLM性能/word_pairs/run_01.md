# 低成本、不训练模型、大幅提升现有 LLM 性能的完整手册

**核心判断**：不训练模型时，性能上限来自**"给模型更好的输入"+"给它更好的验证回路"+"让它少做重复劳动"**。下面按 ROI 从高到低排。

---

## 一、提示与上下文工程（投入最低，收益最大，通常 +20~50 分）

|手段 | 做法 | 典型收益 |
|---|---|---|
| **结构化系统提示** | 角色 + 任务 + 约束 + 输出格式 + 失败处理，写成分节模板 | 格式遵循率 60%→95% |
| **少样本示例（动态选）** | 不写死示例，从示例库里按语义检索最相似的 3~8 条 | 分类/抽取任务 +10~20 分 |
| **思维链 + 分步** | 复杂任务强制"先列步骤再执行"，可配合分隔符隔离思考与答案 | 推理任务 +10~30 分 |
| **任务分解（Decompose）** | 大任务拆成结构化子任务串行执行，而非一口气问 | 成功率 +20% 以上 |
| **输出约束** | JSON Schema / 正则 / 枚举 / 类型化结构，让下游可解析 | 消除80% 后处理成本 |
| **指令排序与隔离** | 系统>用户>文档>示例，把易被忽略的约束放在**结尾**（近因效应） | 指令遵循显著改善 |
| **上下文预算化** | 显式分配令牌预算：示例 ≤15%、文档 ≤40%、留15% 给输出 | 降本30%+ 且质量不降 |
| **上下文压缩** | 递归摘要 / 分层摘要 / 地图归约，去掉历史冗余 | 长会话不掉点 |
| **元提示 / 自检** | 在提示里要求"输出前自查一遍：是否满足所有约束" | 明显减少漏项 |

**反模式**：堆3000 字"你是一个世界级专家…"的 fluffy 提示。先量化提示长度对效果的影响，几乎总是**短而结构化 > 长而泛化**。

---

## 二、解码层：几乎零成本的白菜

1. **低温度/贪心**：抽取、分类、代码、SQL → `temperature=0` 或 0.1，`top_p=1`。这是最快见效的一步。
2. **Self-Consistency（自我一致性）**：同一问题采样5~8 次，投票/取众数。数学、推理类任务 **+15~30 分**，成本 ×5~8，用分级策略只对难题开。
3. **束搜索 / 多候选 + 重排**：生成 N 个候选，用规则或小模型打分选最优。适合文案、命名、方案。
4. **约束解码（Constrained Decoding）**：语法/正则/JSON 约束，把非法输出概率直接置零——**格式正确率 100%**。
5. **停止条件与长度惩罚**：明确终止符，控制冗余重复。
6. **置信度门控**：读取 token 概率/logprobs，低于阈值时自动升级到大模型或走人工/检索。

---

## 三、检索与外部知识（把"记忆"外置）

**RAG 质量公式：召回 > 排序 > 提示**

- **混合检索**：BM25（稀疏）+ 向量（稠密）双路召回，RRF融合 → 召回率通常 +10~15 分
- **重排层（Cross-Encoder Reranker）**：召回 50 条精排到 5 条，是投入产出比最高的组件- **查询改写/扩展**：多问题分解、HyDE（先生成假设答案再检索）、指代消解
- **分块策略**：按语义/标题切分而非固定 512 token；给每块加元数据（前缀路由到小块）
- **引用溯源**：要求每条结论带来源片段 →幻觉下降，且可自动校验
- **知识更新零成本**：改知识库即改模型能力，不用重训
- **别忽视自带长上下文**：如果上下文装得下并且模型检索能力好，直接塞原文可能优于朴素 RAG；但要配合"地图归约/索引式提示"避免"迷失在中间"

---

## 四、工具与代理：让模型做它擅长的

模型天生弱于**算术、查库、执行、验证**——把这些外包给工具：

- 代码执行沙箱（Python/SQL/浏览器）：数学、统计、爬取、表格处理一次到位
- 结构化函数调用 + 严格 schema
- **代理循环**：ReAct 式 plan→act→observe→critic，加**最大步数/超时/预算上限**
- **外部验证器（Verifier）**：编译通过、单测通过、schema 校验、规则校验——不通过就带着错误信息重试
- **多代理辩论/交叉检查**：双模型独立作答再互评，成本换准确率，只在关键路径启用
- **合成数据**：让强模型生成难例/边界例/反例，作为评测集或 few-shot 素材（生成 ≠ 训练）

---

## 五、路由与级联（同时提质 + 省钱）

```
请求 → 难度判别（规则 + 小模型 + logprob）
        ├─ 简单 → 小模型 / 缓存 / 直接返回（占流量 50~70%）
        └─ 困难 → 大模型 + CoT + 自检 + 工具
```

- **级联（Escalation）**：小模型先答，置信度低才升级——**质量接近大模型，成本降50~80%**
- **降级链**：主模型超时/限流 → 备用模型 → 缓存答案 → 规则兜底（熔断、幂等）
- **按 SLA 分级服务**：对外高价强配置，内部批处理走低配
- **缓存三层**：① 提示/前缀缓存（KV cache 复用）② 精确语义缓存（embedding 命中）③ 记忆化（用户偏好/历史结论）
  - 前缀缓存可省 50~90% 预填充成本，是最被低估的优化

## 六、系统与推理引擎优化（同样不需要训练模型）

| 手段 | 效果 |
|---|---|
| 投机解码（小模型起草 + 大模型验证） | 1.5~3× 解码加速，质量**无损** |
| 量化（INT8/FP8/INT4） | 显存降 50~75%，吞吐2~4×，质量损失 <1~2% |
| 连续批处理 + PagedAttention | 吞吐 3~10× |
| 前缀/共享缓存、结果复用、批任务 | 直接降本 |
| 异步/流式 + TTFT 优化（预填充调度） | 首字延迟大幅改善，体验即性能 |
| 分布式并行 + KV 预算管理 | 长上下文不爆显存 |

> 注意：这些优化**降低单位成本**，从而让你能负担"自检 ×5""重试 ×3""辩论 ×2"等**质量手段**——这是杠杆的关键。

---

## 七、安全与鲁棒性（不训练也能加护栏）

- 提示注入检测 + 上下文隔离（把外部文档当"数据"而非"指令"）
- 输入输出双向校验器（正则、分类器、规则引擎）
- 越权防护、敏感信息过滤、审计日志
- **拒答/转人工策略**：不确定就明确说不确定，比硬编更"准"

---

## 八、闭环：让提升可持续（这是最容易被忽略的杠杆）

1. **先建评测集**：从真实日志抽 200~1000 条，人工标注金标准。这是所有优化的前提。
2. **离线回归**：每次改提示/换模型/调参数都跑回归，防止"改一处坏三处"。
3. **在线观测**：追踪链路 +质量指标（接受率、修正率、重试次数、幻觉投诉、成本/请求）
4. **A/B + 影子测试 + 灰度**：提示版本化、配置外置、可回滚
5. **用户反馈即标注**：点赞/点踩一键回流，人工复核后进评测集
6. **提示自动优化**：用 LLM 搜索提示变体（如 OPRO/APO 思路），自动迭代——无需训练权重

## 九、优先级路线图（两周可落地）

**第 1 周（纯提示，零成本）**
1. 改结构化提示 + JSON schema 输出
2. 温度归零 + 明确停止条件
3. 加 CoT 与"输出前自检"

**第 2 周（工程化）**
6. 上前缀缓存 + 语义缓存
7. RAG 混合检索 + 重排
8. 接代码执行/SQL 工具 +验证器重试
9. 难度路由（级联到大小模型）
10. 上可观测面板与 A/B 框架

**第 3~4 周（规模化）**
11. 量化 + 投机解码 + 连续批处理
12. 多代理交叉检查（关键路径）
13. 提示自动优化闭环
14. 记忆系统与会话摘要

## 十、一句话总结

> **不训练模型时，性能 = 上下文质量 × 检索质量 × 验证回路 × 采样策略 × 系统效率 × 迭代速度。**
> 前五项来自"给模型更好的输入和工具"，第六项来自"别让钱白花"——真正拉开差距的不是某个技巧，而是**"有评测、有回归、有观测、有闭环"这套工程体系**。
