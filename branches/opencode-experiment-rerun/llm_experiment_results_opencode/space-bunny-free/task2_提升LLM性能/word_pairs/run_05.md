# 二、正题：不训练，大幅提升现有 LLM 性能

## 0. 核心认知

微调只是把"每次都要教一遍的知识/格式/习惯"固化进权重。**不训练也能拿到的收益，来自三个杠杆**：

> 实际效果 ≈ 模型能力 × 提示质量 × 上下文质量 × 解码策略 × 外部工具 × 校验反馈

其中后五项都是**零训练成本、可当天上线**的。经验上，提示+上下文+解码这三项重做一遍，常见任务能提升 **10%~40%**；加上检索/工具/自检，可再提升一档。

**第一原则：先建评测，再动任何东西。** 拿 30~100 条真实失败样本当"黄金集"，否则你无法判断改完是变好还是变坏。

按错误类型分流（决定该用哪招）：

| 失败类型 | 典型症状 | 对应零训练解法 |
|---|---|---|
| 知识缺失 | 不知道贵司内部信息 | RAG / 工具调用 |
| 指令漏执行 | 说得很清楚却没按要求做 | 提示重写、位置强调、分隔符 |
| 格式错 | JSON坏、字段缺 | Schema约束解码 + 自动修复 |
| 推理错 | 逻辑跳步、算错 | CoT、分解、自洽、委派计算 |
| 幻觉 | 编造事实/引用 | 证据注入 + 强制引用 + 核查 |
| 截断 | 回答半截就停 | max_tokens / stop / 分段输出 |
| 能力不足 | 硬知识任务 | 模型路由 / 级联 / 换更强模型 |

---

## 1. 提示工程（ROI 最高，48小时内见效）

**a) 用六段式重写每个提示**
角色与目标 → 明确任务 → 输入数据（用明确分隔符包裹） → 约束与禁止项 → 输出格式（给模板） → 示例。含糊的形容词（"专业""简洁"）一律换成可判定的规则（"不超过 3 句""必须含日期"）。

**b) 位置技巧**
- 关键指令**放最前 + 结尾再重申一次**（对抗 lost-in-the-middle）。
- 输入数据用 `###`、XML 标签或明显分隔线隔开，降低指令与数据的混淆。

**c) Few-shot 是最高杠杆之一**
3~5 个例子即可：要**包含边界情况与反例**，教模型"什么情况下该拒答/该输出 null"。示例要**按输入相似度动态挑选**，比固定示例强。

**d) 让模型先规划再执行**
"先输出你的解题计划，等我确认后再给答案"或"先列要点清单，再逐条展开"——把隐式推理外显，错误率明显下降。

**e) 提示作为代码资产**
参数化模板 + Git 版本管理 + 回归测试 + 灰度切换。**一次投入、无限复用**，这是"复利"型收益。

---

## 2. 上下文工程（长上下文的生死线）

- **只放相关信息**：删除无关历史、重复内容、噪声文档；用摘要压缩长会话。
- **长文处理**：按段落打标（"下面每段前面是 [来源ID]"，禁止编造），并要求"只依据给定内容回答，缺失就说不知道"。
- **动态示例**：把待处理样本 embedding 与示例库检索，只注入最相似的 k 个。
- **位置偏置纠偏**：要求模型"先在开头复述关键约束，执行完后在结尾自查是否违反约束"。

---

## 3. 解码参数（真正的"免费午餐"）

| 参数 | 建议 |
|---|---|
| temperature | 抽取/分类/代码 → 0~0.2；创意/文案 → 0.8~1.0 |
| top_p / top_k / min_p | top_p≈0.9；min_p 比 top_p 更稳 |
| repetition / frequency penalty | 摘要、长文生成为防复读调 1.05~1.1 |
| stop / max_tokens | **最常被忽略**：截断会让模型"变笨"，务必给足并配 stop |
| n / best-of | 生成 n 个候选，用规则或评判模型选最优 |
| **自一致性（self-consistency）** | 同一问题采样多次、投票取多数。数学/推理类**单题可提升 5~20 个百分点**，不加任何训练，只需延迟换准确率 |

---

## 4. 结构化输出 + 校验修复回路（把60% 的格式错清零）

1. 用 JSON Schema / function calling / grammar 约束解码，**从源头消除格式幻觉**。
2. 输出后做**程序化校验**：字段完整性、枚举、数值范围、单位、正则。
3. 校验失败 → 把错误信息回灌，让模型**自己修复**（repair loop），最多重试 2 次。
4. 仍失败 → 走兜底模板或转人工。**"LLM 负责模糊判断，代码负责严格把关"**是最稳的架构。

---

## 5. 用工具替代训练（能力外挂）

- **RAG**：混合检索（向量 + BM25）+ **重排（rerank）** 是提升最明显的两步；再做 query 改写/多路召回；切块按语义而非固定长度；强制带引用编号。
- **工具调用**：算数字交给计算器/SQL，代码交给解释器，实时信息交给搜索 API。**LLM 不该心算**。
- **工作流 / Agent**：规划 → 执行 → 反思，关键节点由**确定性代码接管**（状态机、规则引擎），只把模糊环节交给模型。
- **模型路由与级联**：简单问题走小模型或语义缓存，难题才上大模型；同时成本降50%+、平均质量反而升。

---

## 6. 推理时扩展（"不训练也能变强"的第二曲线）

- **分解**：大任务拆成子任务，每步独立验证，最后汇总。
- **反思 / 自检**：生成后追加"请找出上述回答中的错误并修正"，或引入独立 Critic / Reviewer 角色。
- **多角色辩论**：让模型分别扮演正反方，再由裁判收敛。
- **LLM-as-judge**：用于难自动评测的场景，配少量人工抽检校准。
- **输出多样性与集成**：同一提示写 3 个变体投票，或对不同片段用不同子提示。

---

## 7. 工程与成本侧（同时提质 + 省钱）

- **前缀缓存**：把长且固定的提示放最前并缓存 KV；**语义缓存**命中相似问题直接复用。
- **批处理 / 并行 / 投机解码**：降延迟与成本。
- **统一网关**：限流、重试退避、超时熔断、降级兜底、灰度与回滚。
- **全链路日志与可观测**：线上失败样本每周回流到黄金集 → 提示迭代 → 回归测试。**这条飞轮才是长期复利。**

---

## 8. 评估闭环（决定你能不能持续提升）

1. 黄金集 50~200 条（真实分布 + 已知答案）。
2. 指标：抽取/分类用 EM/F1/规则通过率；生成用 rubric + LLM-judge；代码用单测通过率。
3. 每次改动跑**离线回归**，防止"改 A 坏 B"。
4. 上线走 A/B + 灰度，带自动回滚阈值。

---

## 9. 优先级路线图

**第 1 周（成本最低、收益最大）**：建黄金集 → 六段式重写提示 → 调解码参数 → 上结构化输出与修复回路 → 推理任务加自一致性。
**第 2~4 周**：RAG + rerank、工具调用、模型路由、前缀/语义缓存、反思与评审角色。
**第 1~3 月**：领域词典与术语表、提示资产化与 CI回归、全链路可观测、成本-质量联合优化、必要时再做 LoRA 微调（有了前面的数据，微调才有意义）。

---

## 10. 常见坑

- 只调参数不改提示（顺序反了）。
- 没有评测集就改提示 → 过拟合到几个例子。
- 提示越堆越长（信息密度下降反而变差）。
- 忽略 `max_tokens` 截断与 stop 配置。
- few-shot 里没给负例，模型不知道何时该拒答。
- 换模型后不重新校准提示（不同模型对措辞敏感度差异很大）。
