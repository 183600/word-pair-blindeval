## 二、从中诞生的 Idea

### Sift（筛子）——把任何日志/命令输出变成"可查询、可降噪、可复盘的时间切片"

**一句话**
> `sift app.log` → 它自动看懂格式、折叠重复行、找出异常突增，并把 10 万行噪音压成一页能贴进 issue 的报告。

### 为什么这个组合词指向它从上面200 组词里反复出现的簇：**时间戳·墓碑 / 尾流 / 爆发·干旱 / 沉积·岩层 / 化石·琥珀（快照）**（流与时间）＋ **模式·骨架 / 键值·对话 / 字段·拼图 / 颜色·语义**（结构）＋ **噪声·去重 / 离群·簇群 / 异常值·灯塔 / 洞察·透视**（降噪与洞察）＋ **单点200：终点·新起点**（复盘与交接）。这四簇正好是一个 CLI 的四个动作：**看懂 → 折叠 → 报警 → 复盘**。

### 核心功能（按优先级）

| 命令 | 作用 |
|---|---|
| `sift app.log` | 自动识别 JSONL / logfmt / 纯文本 / CSV / 多行堆栈，推断 schema 并渲染对齐表格 |
| `sift q "level=error and dur>200"` | 零配置迷你查询语言（字段比较 + 数值阈值 + 自由文本），自动走 DuckDB，任意规模文件秒级 |
| `sift q --sql "SELECT ..."` | 要 SQL 就给 SQL，不挡路 |
| `sift top` | 默认动作：**重复行折叠**——"12,480 行其实只有 7 种"，按次数 / 首次 / 末次 / 示例 展示 |
| `sift spikes` | 时间桶速率突增检测（Pettitt / 简单 CUSUM），标出"14:07 错误率突然 ×40" |
| `sift novel` | 离群模式挖掘：找出**从未出现过的新错误类型**（关键降噪） |
| `sift around :842 --lines 30` | 任意一行展开上下文，多行堆栈自动对齐、跨行归并成一条记录 |
| `sift snapshot -o incident.txt` | 生成自包含的终端风格报告（颜色+ASCII迷你图），可直接粘贴进 GitHub Issue /邮件 |
| `sift watch` | tail +实时突增告警（终端 beep / 桌面通知），可 `--fail-on` 用于 CI 门禁 |

### 差异化（为什么不只是又一个 grep / bat）
- **grep 看行，Sift 看时间**：所有分析都是时间感知的（速率、突增、首次出现）。
- **不重不等于不重要**：折叠 + 计数是它的招牌动作，其他工具都把3 万条重复 INFO 糊你一脸。
- **零配置但可逃生**：开箱即用，同时永远留 `--sql` 和自定义 extractor 插件的口子。
- **可分享的产物**：`.siftq` 查询文件 + `snapshot` 报告 = 团队里天然可 code review 的协作单元（`if error_level == "ERROR" and svc =~ /^pay/` 写进仓库，而不是记在某人脑子里）。
- **本地优先、单二进制、无账号**：`brew install sift` / `curl | sh`，数据不出机器——这是当下最硬的卖点。

### 技术栈与工程量（独立开发者可承受）
- **Go 或 Rust** + `clap` + `ratatui`（表格/迷你图）+ **DuckDB**（查询引擎，白嫖了列存与 SQL）+ 自写 5 个 extractor（JSONL / logfmt / plain / CSV / stacktrace）。
- MVP 只做三件事：`sift`（渲染+折叠）、`sift q`（查询）、`sift snapshot`（报告）。**约 2–3 周可发 v0.1**，纯本地、无插件系统、无 TUI 花活。
- 性能路径：mmap + 列式投影 + 只解析用到的字段；超大文件自动降级为采样模式并明确告知。
- 可选 AI：`sift q --ai "找出支付超时突增的时间点"` → 生成本地查询语句（用用户自己的 API key，默认关闭）。

### 商业化（开源核心 + 本地付费）
- **MIT 免费**：渲染、查询、折叠、报告。
- **Pro（一次性 $29 或 $3/月，纯本地无订阅绑架）**：加密归档后端（保留 90 天历史、zstd 列存、秒级回溯）、多文件/多服务时间轴对齐、`--ai` 查询生成、CI 门禁与断言规则。
- 后续可选：团队共享的查询模板市场（抽成 15%），或干脆做成"调试工作流"全家桶（sift-log / sift-trace / sift-cost）。

### 主要风险与对策
1. **日志格式千奇百怪** → 只承诺5 种；其他格式一律退回"按行折叠 + 正则字段抽取"，永不崩、永不装懂。
2. **和 rg/bat/jless 正面撞车** → 定位语必须死扣"**时间维度 + 降噪 + 复盘产物**"，把通用文本浏览让出去。
3. **一次要做的太多** → 严格执行"三个命令原则"，v1.0 前不碰 TUI、不碰插件、不碰云。

### 里程碑
- **Week 1–3 · v0.1**：格式识别 + `top` 折叠 + 表格渲染（这已经能替代80% 的 `sort | uniq -c | sort -rn`）
- **Week 4–6 · v0.2**：`q` 查询语言 + DuckDB + `snapshot`
- **Week 7–10 · v0.3**：`spikes` / `novel` / `around` + shell补全 +10 种配色主题
- **Week 11–12 · v1.0**：brew/nix 分发、`.siftq` 规范、AI 查询、Pro 授权、Show HN 发文

**一句话立项理由**：这是一个"痛点确定、技术栈成熟、范围可控、分发天然、代码量小、还能开源建立口碑"的项目——它正好是 200 组词里那条从 *沉积·岩层* 到 *终点·新起点* 的路径：把别人留下的混乱，重新整理成可以被下一个人接手的东西。
