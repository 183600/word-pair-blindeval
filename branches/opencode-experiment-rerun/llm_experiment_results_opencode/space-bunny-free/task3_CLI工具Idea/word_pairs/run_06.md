# Idea：`ghost` —— 给命令行的"事故现场录像机"

**一句话**：把任何一条命令的运行变成一个**可比较、可二分、可分享的对象**；`ghost bisect` 在**没有 git 历史**的情况下也能帮你找出"到底哪个改动把输出翻盘的"。

### 痛点（独立开发者真实高频）
昨天还好的构建今天挂了。你在这期间改了 12 个地方，但它们没提交、或者散落在 `.env`、`~/.zshrc`、`node_modules`、系统版本、远端 API 返回里。
- `git bisect` 救不了你——因为**没有一个干净的 commit 序列**，也没有可靠的自动化判定。
- 你只能手动注释、逐个撤销、重试、猜。**平均 15～40 分钟，且经常复现不出来**（"残影"没了）。
- 这是**纯个人痛点**，但每个人都会遇到——所以付费意愿不一定高，所以要靠传播和效率。

### 核心洞察（从上面的词里提炼）
日志是**时间序列**，但归因要的是**对比**。
把"一次运行"抽象成 `run.json`（一份**语义化指纹**），那么"这次和上次哪里不一样"就变成了一个可以 `diff`、可以被二分搜索的**普通数据问题**。

### 工作流（三个命令，不多不少）

```bash
# 1) 录：包裹任意命令 → 一份可比较的运行指纹
ghost wrap npm run build
ghost wrap pytest -q tests/auth/    # 一个 run.json，几 KB~几 MB，压缩存储

# 2) 比：语义级差异，不是字节级
ghost diff last.run.json prev.run.json
# + env FOO2 → 7
# + 首次读取 ./config/local.toml
# + 少了一个 spawn: node-gyp rebuild
# + exit 0 → 1   stderr hash 3f2a →9b81

# 3) 二分：把"因子"当维度，自动找最小翻转组合
ghost bisect --fingerprint exit_code -- "npm run build"
# 搜索 6 个因子：env / config 文件 / 依赖版本 / PATH / 缓存目录 / 随机种子
# → culprit: NODE_OPTIONS=--max-old-space-size=2048  (exit 1 → 0)
```

### MVP 范围（一个人3～4 周能做完）
只捕获 **5 个因子**，刻意少即是多：
1. 环境变量读取（谁读了这个 key，值是什么）
2. 关键配置文件的内容 hash
3. 子进程树（spawn 列表 + 各自动作）
4. 文件系统访问（路径集合 + 读写的 hash）
5. exit code + stdout/stderr hash + 各阶段耗时

**技术路径**：Linux 用 `ptrace + seccomp-bpf` 做**纯用户态 trace**（不依赖内核模块、不是 root-only 那种 strace 噪音），只对**被测进程树**生效；macOS/Windows 先降级用「`LD_PRELOAD`/`DYLD_INTERPOSE`」或「包一层伪文件系统 + 快照 diff」的兜底方案，别一开始就追求跨平台全量。

### 为什么不是别的工具
| 工具 | 它回答的问题 | 缺口 |
|---|---|---|
| `strace` | 系统调用级发生了什么 | 太底层、太啰嗦、不可二分、不可版本化 |
| 快照测试 | 我写的期望对不对 | 要你先写测试，不解决"哪次改动导致的" |
| CI artifact | 那次流水线留下了什么 | 太重、太晚、只覆盖 CI 里的东西 |
| **ghost** | **"这次运行 vs 那次运行，语义上差在哪；哪个因子翻转了结果"** | **在任意命令上、即拿即用、无需 commit 历史** |

### 商业化（独立开发者友好的形态）
- **本地 CLI 完全免费、开源** —— 这是获客入口。
- 付费点放在**协作层**：`ghost share` 生成一个**单文件 HTML"现场复盘报告"**（时间轴 + 因子差异 + 终端回放），发到 issue / 群里就能复现别人的 bug。团队版：私有 run 库、CI 集成、"上次是谁把 exit code 从 0 改成 1 的"审计、按月定价。
- 传播点：报告链接里带 `ghost run <hash>`，别人点开就能在本地"下载并重放这次失败的因子供体"。**这是天然的病毒式载体。**

### 第一版界面应该长这样
```
$ ghost bisect -k exit_code -- npm test
● 记录 6 个因子… ⟳ 探测27/32 次
● 收敛：exit_code 由 NODE_OPTIONS 决定

  culprit   NODE_OPTIONS
  before    (unset)                  → exit 1
  after     --max-old-space-size=4096 → exit 0

  最小复现：
  $ NODE_OPTIONS=--max-old-space-size=4096 npm test   # ✅
  $ npm test                                            # ❌

$ ghost diff prev.run.json    # ⤓ 3 分钟前那次正常的
```

**为什么选它**：技术纵深足够（ptrace、语义 diff、因子归因、搜索），但表面积极小——三个命令、五个因子、一个 `run.json` 格式。对一个人来说是**可完成的挑战**，对用户来说是**当天就能省下半小时的痛点**，而且每次使用都会自然产出可分享的产物。
