## `faultline` —— 契约断层扫描仪（CLI 工具）

**一句话**：给你的 CLI / 库 / API 立一份"快照契约"，每次提交自动扫描：你这次改动有没有在地基上制造断层（breaking change）？

### 问题
独立开发者最痛的时刻不是写代码，是**发布**。你改了：
- 一个 flag 名（`--out` → `--output`）
- 一个默认值（`--depth 3` → `depth 0`）
- 一行 stdout 文案（用户脚本在 `grep "Success"`）
- 一个退出码（0 → 2）
- 一个 JSON 字段名

这些都**不会让编译失败**，却会让所有下游脚本在深夜炸掉。TypeScript 有 `tsc` 帮忙，CLI 和 HTTP API 完全没有守门员。

###核心机制（3 条命令）
```bash
faultline init                 # 抓取当前行为，生成 .faultline/contract.json（快照）
faultline check # 在工作区跑一遍，与契约对比，输出"断层地图"
faultline accept --deprecate --for1.x # 承认是过渡，生成兼容层 + CHANGELOG 条目
```

### 它到底检查什么（可自动推断，无需声明式 schema）
| 类别 | 检测对象 |
|---|---|
| flag/参数 | 新增、删除、改名、默认值变化、是否必填变化 |
| 退出码 | 出现/消失的退出码集合变化 |
| 输出文本 | stdout/stderr 的行级 diff（可配置为"关键行"） |
| 结构化输出 | JSON key 的增删改类型、枚举值增减 |
| HTTP路由 | 路径、方法、状态码、字段 |
| 行为 | 排序/分页/时区/字符编码等"沉默的行为变更" |

### 断层分级（对应"地质学"语言）
```
◆ 断层（breaking）    删 flag、改字段名、改退出码 → 阻断合并
● 摩擦（deprecated）  标记弃用，附替代方案 → 警告
○ 移位（cosmetic）    文案微调 → 通过
```

### 为什么适合独立开发者做
1. **零 AI、零服务依赖**：核心是「跑二进制 + diff 文本」，技术栈 Go 或 Rust，交叉编译单文件丢出去就能用，CI 上 `curl | sh` 30 秒接入。
2. **痛点真实且尖锐**：每一个发过库/发过 CLI 的人都栽过，"版本发布 = 一次小地震"。
3. **范围可控**：MVP 只需支持 **自己的 CLI 自身**（跑 `--help` 解析 flag 表 + 跑 fixture 比对输出），一周能出可用版本；再做 HTTP API 插件扩展。
4. **开源 + 托管双收**：CLI 开源（MIT）冲 star；托管版卖「**契约年轮**」——历史版本契约快照的时间线、破坏性变更统计、影响的下游包列表、团队预算告警。
5. **天然可分享**：每次 PR 自动在评论里贴一张"地质剖面图"，用户爱截图传播。

### 差异化护城河
- 别人做的是 **你的代码** 的兼容性；`faultline` 做的是 **你的用户**（脚本、CI、其他包的调用）看到的**表面**。
- 契约文件进版本库 = 你的 API 有了"法律条文"，团队协作与外包交付都受益，付费意愿高。
- 可组合成生态：`faultline` 输出被其他工具（生成文档、写 changelog、做 SDK）复用。

### 落地路径
- **第 1 周**：flag 解析 + fixture 输出比对 + 终端里的断层地图渲染- **第 2 周**：契约文件 schema、GitHub Action、`--deprecate` 兼容层生成
- **第 3 周**：HTTP API 插件、契约年轮页面、文档站- **变现**：CLI 免费；托管 $5/开发者/月（年付 $49），团队版加 SSO 与审计日志

### CLI 体验小细节（决定口碑）

```bash
   ◆  --output-file  →  --out-file        flag 改名      [断层]
   ◆退出码 3 消失                       行为变更      [断层]
   ●  --depth 默认3 → 0                   默认值变更    [摩擦]
   ○  文案 ×2 处 微调          [移位]

 建议：faultline accept --deprecate --out-file --for 1.x
  文档：faultline why --id=3──────────────────────────────────────────────
```
