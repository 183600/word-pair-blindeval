## Idea：`tt`（Time Travel）—— 给任意命令加上「撤销键」的 CLI

**一句话**：`tt wrap <任意命令>`，把这次运行对文件系统的所有修改录制成一个可回放、可 diff、可撤销的「时间胶囊」。

**核心命令**

| 命令 | 作用 |
|---|---|
| `tt run -- npm install` | 记录一次运行，生成快照胶囊 |
| `tt diff` | 显示这次运行到底改了什么（新增/修改/删除，带内容 diff） |
| `tt undo` | 把工作区回滚到运行前的状态（原子性操作，先预览再确认） |
| `tt replay` | 在沙箱里重放这次运行（干跑演练，不碰真实环境） |
| `tt scrub` | 把胶囊里的密钥/令牌自动脱敏后再分享 |
| `tt share` | 导出成一个 `.ttcapsule` 文件，发给同事一键复现 |
| `tt --json \| jq` | 所有输出支持结构化，方便接管道和 CI |

**为什么这个组合有意思**

- 「快照 / 时间旅行 / 溯源 / 幂等 / 守卫 / 预览 / 撤销」这些词天然构成一个叙事：*Git 管的是代码历史，tt 管的是"命令历史"*。
- 真实痛点：`rm -rf`、`pip install`、格式化工具、代码生成器、迁移脚本——这些操作没有 undo，开发者心里永远不安。
- 契合 CLI 美学：管道友好、有退出码语义、有 `--json`、有补全脚本、有 `--no-color` 无障碍开关、单二进制零依赖。

**独立开发者可行的技术路径（按难度递进）**

1. **MVP（1~2 周）**：只做「快照 + diff + undo」。用 Git 内部的 plumbing（`git init` 一个影子仓库 + `git hash-object`/`write-tree`）记录目标目录的文件树，不拦截任何系统调用，纯事后扫描。
2. **v2**：加 `LD_PRELOAD` 拦截层（或 Windows 上用 `Minifilter`），实现真正的写时复制，只记录变化过的文件，性能大幅提升。
3. **v3**：加网络抓包（记录所有出站 HTTP 请求并脱敏），胶囊变成完整的"环境复原包"，支持离线 replay。

**差异化定位**：不与 `git stash`、`direnv`、`nix` 竞争，而是做「命令级事务」这一个小切口；目标用户是每天靠 CLI 干活、又不敢随手跑危险命令的人（也就是用户自己）。

**变现方向**：免费本地版 + 付费的团队共享胶囊库 / CI 集成插件。
