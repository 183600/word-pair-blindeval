# 二、主推 Idea：**Reforge（炉火重铸）**

> 一句话：**专门给 AI 编程代理（Claude Code / Cursor / Copilot CLI）当"质检员 + 记忆库"的本地 CLI**——在 AI 改完代码后，自动发现"看起来能跑、其实会烂"的痕迹，并把每一次 AI 犯错的模式沉淀成本地规则，越用越准。

## 为什么是这个方向

| 观察 | 含义 |
|---|---|
| 现在所有人都在用 AI 写代码，但几乎没人给 AI 的产出做**系统性验收** | 有缺口 |
| AI 的失败模式高度**重复且可检测**：幻觉 API、重复造轮子、吞异常、隐式类型转换、硬编码密钥、改了不兼容的依赖 | 规则可工程化 |
| 代理是**无状态**的：每次都重新犯同样的错 | 需要"记忆层"，而记忆层目前只有人脑 || 开发者仍然住在终端里，浏览器仪表盘是负担 | CLI 是正确形态 |

## 核心功能（MVP 只做前三个）

1. **`reforge scan`** — 在 diff 上跑 40+ 条规则，每条规则输出：问题位置、可点击跳转、为什么危险、一行修复建议。
 - 关键差异：**规则按语言生态分层**（Go / Rust / TS / Python），不是通用 lint。
2. **`reforge why`** — 对任意一行 AI生成的代码，解释"这段引用了这个包的哪个版本、哪个函数签名；如果你的依赖是旧版，这里会崩"。解决"幻觉 API"最痛的一类。
3. **`reforge remember`** — 本地账本（纯 JSON + SQLite，无服务器）：记录每次 AI 改动踩了什么坑，生成属于**这个仓库**的 `.reforge/rules.md`，下次会话自动注入给代理。
4. `reforge diff --last3` — 跨会话对比，输出"这次 AI 引入的技术债债务总额"。
5. `reforge fix` — 对高置信度问题自动改（开/关预检、收敛浮点、加超时、抽取重复函数）。
6. `reforge init` — 检测项目类型，预置合理规则集，30 秒上手。

## 技术选型（独立开发者友好）

- **Go**（单二进制、启动< 20ms、跨平台零依赖）或 **Rust**；分发只需一个文件- 解析层：**tree-sitter**（四种语言一套实现）
- 依赖事实层：读 `package-lock / go.sum / Cargo.lock / uv.lock`，不做在线解析- 数据存储：SQLite（`modernc.org/sqlite`，纯 Go，免 CGO）
- 输出：终端 TUI + `--json`，能被 CI 和其他代理管道消费
- 差异化护城河：**跨会话记忆** 是最难被复制的一点，因为它需要真实使用积累

## 定价

- **Free**：本地全功能，40 条规则，单机
- **Pro $8/月**：AI 解释（用便宜的模型，只在 `why`/`remember` 时调用）、团队共享规则库、CI 集成、跨仓库记忆同步（端到端加密）
- 商业模式的关键：**不留用户代码**，本地优先是卖点也是信任卖点

## 冷启动路径

1. 做成 **Claude Code / Cursor 的 skill + hook**，直接在代理最痛的时刻出现（代理刚改完代码那一刻）
2. 在几个热门开源仓库上跑一遍，把"AI 高频错误 Top 20"发成公开文章 —— 这是天然的增长素材
3. 与模板/脚手架作者合作，把 Reforge 规则内置进 starter kit

## 备选（如果想更小更快）

- **Paper Trail**：把任意文档/网页/Notion 抓成**带行号出处引用的 Markdown 包**，一条命令喂给任何 LLM CLI，专门解决"AI 编造引用"。
- **Shellsmith**：把成功的 shell 调试过程固化成**带版本校验的参数化脚本**，升级后自动提示哪个 flag过期了。
