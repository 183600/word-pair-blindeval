# 第二部分：设计一门全新的函数式编程语言

## 名字

**Vela**（船帆座）· 文件后缀 `.vl` · 命令行工具 `vela` · 语法高亮名 `Vela`

取"船帆"之意：函数式语言里最具争议的正是**副作用**——而帆，正是让船在风中**可控地产生动力**的那片布。Vela 的核心命题是：**让副作用变成可测量、可组合、可解释的风**。

---

## 一、六条设计信条

| # | 信条 | 具体含义 |
|---|---|---|
| 1 | **纯度是默认，不是枷锁** | 全部值不可变；一切副作用必须写在类型里，且自动推断 |
| 2 | **每个程序自带航海日志** | 任意表达式求值同时产生一条"效果轨迹（Trace）"，可打印、可回放、可断言 |
| 3 | **没有异常，只有失败** | 错误是普通的和类型值，`try` 只是 handler 的语法糖 |
| 4 | **没有循环，只有递归；没有类，只有模式** | 控制流 = 结构匹配 + 代数效应；不存在 `while`/`for` |
| 5 | **并发是效果，不是库** | `spawn`/`chan`/`await` 属于类型系统的一部分，可静态推理死锁风险 |
| 6 | **类型即文档，编译器即 IDE** | 行多态 + 类型洞 `_`，编译错误直接给出可粘贴的补全代码 |

---

## 二、语法概览

Vela 采用**缩进敏感**语法（Python 家族），但把 `=>` 保留给函数与分支，`—` 风格注释。核心只有 9 个保留字：
`type  effect  match  with  let  do  handle  use  module`。

```vela
module Shapes

use std/math
use std/list

type Shape
  | Circle Float
  | Rect   Float Float
  | Point

area : Shape -> Float
area = fn s => match s with
  Circle r      => math.pi * r * r
  Rect w h      => w * h
  Point         => 0.0

total : List Shape -> Float
total = fn shapes => sum (map area shapes)
```

要点：
- **箭头分层**：`A -> B`（纯函数）、`A ~ E -> B`（带效应 E 的函数）、`A! -> B`（可能失败的函数）。一眼看出一个函数"会不会做坏事"。
- **`fn` 与 `=` 分离**：`f = fn x => ...` 显式 lambda；单参数可省略 `fn`：`map f xs = ...`。
- **模式即语法糖展开**：`Circle r` 编译为 `case s of Circle r -> ...`。

## 三、类型系统

**HM + 行多态 + 和类型 + 可选性 + 渐进边界**

```
Vec Float ~ {Read, Log} -> Int          -- 行多态：只声明"至少"这些效应
Result Vec String IOException          -- 内建和类型（Ok | Error）
Opt a  = Some a | None                 -- 语法级 sugar
t : Vec _                               -- 类型洞，编译器回填并给出修复建议
foreign puts : CString -> (Int ~ FFI)   -- 渐进：FFI 逃逸口，调用者需 handle
```

三个自研亮点：

1. **完整性（Totality）检查**：编译器穷尽所有分支，未覆盖的和类型构造器 = **编译错误**（不是警告）。所有函数保证终止，无 `⊥`。
2. **空洞驱动开发（Hole-Driven）**：写 `_` 后，类型检查通过，编译器把"这里应该是什么类型/模式"打印在诊断里：
   ```
   ⚠ 12:5  vec.map(_) : Float -> Float ~ {Read}
      你想写：vec.map(fn x => x * 2.0)
   ```
3. **效应可推断**：你不必手写 `~ {Log, Read}`，像类型一样自动推断并泛化。

## 四、效应系统：Vela 的真正主角

### 4.1 效果是值，不是魔法

```vela
effect Log
  note  : String -> Unit
  debug : String -> Unit

effect State s
  get : Unit -> s
  put : s -> Unit
```

### 4.2 Handler 即解释器

```vela
silence : (a ~ {Log, Read} -> b) -> a -> b
silence prog input =
  handle prog input with
    Log.note m  k => resume k ()
    Log.debug m k => resume k ()
    Read.get   k => resume k (blank)
    Read.put s k => resume k ()
```

`handle` 的三段式：`效果操作` `续延` `处理体`。这就是一个**解释器**，和代数效应论文里一模一样，但语法上足够短，普通用户能读懂。

### 4.3 轨迹：免费得到的可观测性

任何程序都可包一层 `narrate`：

```vela
narrate : (a ~ e -> b) -> a -> (b, List Event)
```

于是"这个纯函数到底偷偷读了文件几次"变成一个可以断言的类型安全事实：

```vela
check : Unit -> Bool
check _ =
  let (result, events) = narrate pipeline ()
      reads = events |> filter isRead
  in  match reads.count with
        0 => true
        n => false   -- 编译器会补上 _ 分支提示你穷尽 Int
```

> 这一条灵感来自 **053 承诺/兑现、052 回溯/快照、098 痕迹/使用**：
> *承诺* 写在类型里，*兑现* 由 handler 保证，*痕迹* 由运行时白送。

### 4.4 失败不是异常

```vela
readFile : Path -> (Str ~ {Read, Fail} -> Str)
tryRead : Path -> (Result Str Error)     -- handle Fail 后得到纯函数
```

**所有错误处理都是显式的、局部的、可组合的**。没有栈回溯噪音，没有 `Error` 泄漏到 20 层调用之外。

## 五、模式匹配：语言的消化器官

Vela 的匹配是**统一的**：代数数据类型、元组、列表、Map/Set、字符串、字节、数字区间、对象，全部用同一套 `match ... with`。

```vela
classify : Http -> Route
classify req = match req with
  (GET, "/"           )          => Home
  (GET, "/u/" ++ id  )          => User id
  (GET, "/u/" ++ id, q)         => UserQuery (id, q)
  (_, p) where p |> startsWith "/static/" => Static (drop 8 p)
  _                             => NotFound
```

匹配**不保证顺序正确**，编译器拒绝不可达分支（对应"沙漏/漏尽"：漏掉的是**漏斗**那一端）。

## 六、并发：一等公民的"船帆"

```vela
chan : Int -> Chan Int                  -- 有界通道，自带背压
send  : Chan a -> a -> Unit ~ {Chan}
recv  : Chan a -> Unit -> a ~ {Chan}

worker : Chan Job -> Unit ~ {Chan, Log}
worker jobs = match recv jobs with
  Job{x} => do send (resultChannel) (solve x)
              worker jobs

pipeline : List Job -> List Result ~ {Chan, Log}
pipeline js = do
  spawn (worker (chan 4))          -- 4 = 背压上限
  spawn (worker (chan 4))
  mapM (recv resultChannel) js     -- 通道即流，惰性取用
```

因为 `Chan` 是行多态的**效应**，编译器能静态检查"某个通道被两个 worker 争抢"这类错误（通过线性化的 `Chan!` 变体）。

**活性检查器（liveness pass）** 在类型检查后运行，用效应集合的偏序关系检测**确定性的死锁**：`send` 与 `recv` 组合在循环中若顺序不一致，直接报错。这一特性在其他语言中尚属空白。

## 七、编译期计算：让"宏"不再是一个绕过类型系统的洞

```vela
comptime fact : Int -> Int
comptime fact n =
  if n <= 1 then 1 else n * comptime fact (n - 1)

factorial : Int -> Int
factorial n =
  let table = comptime (list 1 .. 20 |> map fact)   -- 整表在编译期算好
  in  if n in 1..20 then table[n-1] else 0
```

宏以 `macro` 声明，接收与产出都是**普通的、已类型化的语法树**：

```vela
macro unless : Cond -> Then -> Else -> Term
macro (Unless c t e) = (Match c [True -> t, False -> e])
```

宏展开发生在类型检查之前，展开结果仍需通过全部检查 → **宏无法写出类型错误的代码**。

## 十、一段完整示例（"帆与风"）

```vela
module Sail

use std.base
use std.effects
use std.list
use std.net

effect Trace
  step : String -> Unit

-- 纯逻辑：如何规划一条航线。零效应，可单元测试，可形式化验证。
plan : Wind -> Route ~ {Log}
plan w = match w with
  Wind{ dir, speed }
    | speed < 3        => do effects.note "too calm — 停泊";  Ok (stay put)
    | abs (dir - target) > 180 => do
        note "顶风 — 折角"
        Ok [zig (dir + 90), zig (dir + 270), sailTo target]
    | otherwise        => Ok [sailTo target]

-- 不纯的外壳：读传感器、写日志、发网络请求
sense : Unit -> Wind ~ {Read, Net, Trace, Fail}
sense _ = do
  t = effects.read Sensor.Temp
  w = net.get "/wind" |> parseWind
  trace.step "sensor ok"
  Ok Wind{ dir = w.dir, speed = w.speed }

main : Unit -> Unit ~ {Read, Net, Trace, Fail}
main _ =
  match sense () with
    Error e => do trace.step ("abort: " ++ e.msg); effects.write (red e.msg)
    Ok w    => plan w >>= launch >> trace.step "sailed"
```

**注意这里没有一行 `try`、一个 `if err != nil`、一个 `panic`。** 整条流水线的所有不确定性都写在类型右侧的 `{Read, Net, Trace, Fail}` 里，谁调用 `main` 谁就必须交代这些效果的处置方式。这是"可控的副作用"。

## 十一、编译器实现

| 阶段 | 技术 |

| 前端 | 用 **Vela 自己写**（自举），手写递归下降 + Alex/Lex 风格词法 |

| 中间表示 | **CPS + ANF + 显式续延机器（continuation-passing style）**——因为代数效应天然编译成 CPS，语义零损耗 |

## 十二、样例对比感受

**Scala/Java 写法（Vela 中被禁止的东西）**
```java
try { var xs = list.stream().filter(p).map(f).toList();
      log.info("got " + xs.size()); return xs; }
catch (Exception e) { log.error("fail"); return List.of(); }
```

**Vela 写法**
```vela
process xs = handle (do xs |> filter p |> map f) with
  Log.info m k => (log.write (m ++ "\n"); k xs)   -- 效果被显式捕获
  Fail      k => k []
```

行数相同，但**没有隐藏的控制流**，没有 `var`，没有被吞掉的异常。

---

## 十三、一句话总结

> **Vela 是一门"函数式语言 + 天生的航海日志"**：
> 它不禁止副作用，而是要求你把副作用**写成类型、交给 handler、留下轨迹**。
> 灵感取自上面 200 组词里那些最本质的对立统一——*回声/延迟、迷宫/递归、苔藓/孢子、承诺/兑现、痕迹/使用*——
> 把它们翻译成一句编译器可以检查的话：
>
> **「你写下的每一点 impure，都必须被命名、被捕获、被记录。」**
