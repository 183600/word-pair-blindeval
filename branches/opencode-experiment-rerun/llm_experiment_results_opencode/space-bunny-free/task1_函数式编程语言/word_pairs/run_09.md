# 第二部分 · 语言设计：**榫（SU N）**

> `榫卯`：两块木，一凸一凹，不用一根钉子，咬合千年。
> 榫语言的全部野心：让**模块之间的接口严丝合缝**，让**错误在编译期暴露**，让**副作用被写在明处**。

* 名字：榫 / **Tenon**（短名 `sun`）
* 源文件：`.sun`　包：`tenon`　命令行：`su`
* 标语：**无 null，无异常，无循环，无钉子。**

## 1. 六条原则

1. **纯度是默认值，效果是类型。** `Int` 的加法不可能打印东西。想打印？那你的函数就返回 `IO Unit`，调用者看得见。
2. **所有缺席都显式。** 没有 `null`，只有 `Option[T]`；没有"可能抛出的调用"，只有 `throws E`；没有隐式转换。
3. **资源是线性的。** 文件句柄、锁、连接、随机数发生器、端口：类型带 `!`，只能被消费一次。编译器审计，无需靠命名约定。
4. **错误是值，不是控制流。** `Result[T, E]`、`Option[T]`、`throws E` 声明，全部可被模式匹配、被组合、被测试。
5. **没有循环，只有管道。** 递归必须结构化；编译器保证尾调用优化，模式匹配穷尽性检查保证无隐藏的"什么都不做"。
6. **接口即榫头。** 模块导出的类型即接口，实现者必须**穷尽地**匹配所有构造子；不允许"未来新增构造子时下游悄悄变哑"。

## 2. 词法与布局

* 缩进敏感（2 空格或 1 制表符，不可混用）。`{ }` 仅用于 record 字面量与显式分组。
* `//` 行注释，`/* */` 嵌套块注释，`/** */` 文档注释。
* 标识符允许 Unicode 与 `'后缀'`。
* 运算符：`+ - * / % ** == != < <= > >= && || ++ |> <| ~> :: := => -> \ . .. ? !`（`!` 后缀仅用于 `!x` 线性消费标记）

```
// 这是注释
/* 可 /* 嵌套 */ 的注释 */
/** 文档：形状是只读的，area 是它的面积。*/
type Rect = { w: f64, h: f64 }
```

## 3. 值模型

| 种类 | 记号 | 语义 |
|---|---|---|
| 普通值 | `T` | 不可变，可无限复制、跨线程共享 |
| 线性值 | `!T` | 不可变，但**有且只有一次**消费机会（移动语义 + 无隐式复制） |
| 计算 | `F[A]` | 一次求值得到 `A`，可被多次读取（如 `lazy` 列表的尾巴） |

```
type Handle  = !Fd          // 线性资源
type Stream<T> = F[Option[T]]  // 惰性流
```

**线性规则（编译器强制，违反即编译失败）：**

* 线性变量必须恰好被消费一次：要么传给以 `!T` 为参数的函数，要么 `drop`（显式泄漏并产生警告），要么闭包捕获。
* 线性值不可放入数组、字典、闭包的重复字段；捕获它的闭包自身变为线性。
* 函数若参数为 `!T`，返回类型可携带 `!U`（"状态机"风格传递），但不可同时返回 `!T` 本身（防双花）。

```sun
// 好：把句柄交出去
readAll : !Fd -> IO Int
readAll h = io.read(h)

// 坏：
bad : !Fd -> (Int, !Fd)
bad h = (io.read(h), h)      // ❌ 线性检查：h 被用了两次
```

这让"谁负责关闭"成为**类型级问题**，而不是运维文档问题。

## 7. 列表与流

```
xs   = [1, 2, 3]
ys   = [x * x | x <- 0..10, x % 2 == 0]      // 推导式
pairs= for x <- xs, y <- ys yield (x, y)
```

**惰性流**（尾巴默认惰性）：

```
primes : Stream Int
primes = sieve (from 2)

sieve : Stream Int -> Stream Int
sieve s = match s
  []          => []
  [x, ..rest] => cons x (sieve (skip (multiples x) rest))   // rest 惰性，不算完
```

对应 `fib`、`iterate`、`takeWhile`、`zip`、`interleave`。流是 `F[Option[T]]` 的别名，因此可以自由混合严格/惰性计算。

## 8. 代数效应（"天气系统"）

**声明效果：**

```
effect Log = {
  emit : Str -> ()
}

effect Store = {
  get : () -> Int
  put : Int -> ()
}
```

**处理（Handle）与运行：**

```
run : Log Program -> IO ()
run p = handle Log
  emit m = io.print m
  ()
in p

main : IO ()
main = run (do
  emit "hello"
  emit "world")
```

**内置效果的语法糖**（编译后等价展开）：

```
// 线程局部状态：等价于 handle Store { get = id; put = \s _ -> () } e
counter = with state 0:
  let n = get()           // get :: () -> Int
  put(n + 1)
  n

// IO
prog = with io:
  io.print("running")

// 随机：必须显式，效果被线程局部
r = with sample (seed 42):
  rand.f64()

// 并发（结构化，自动 join，子任务不能逃逸父作用域）
handle Par { spawn = par.run } do
  a <- spawn(compute1)
  b <- spawn(compute2)
  a + b
```

**运算符：`?`（抛出）与 `?!`（提供默认值）**

```
loadConfig : throws[IoErr] Path -> Config
loadConfig p = do
  txt <- io.read(p)?                    // 失败则从本函数返回 Err
  parse txt?                            // do-notation 自动串联
```

**自定义 effect 例子：数据库事务（前后各一个操作）：**

```
effect Tx = {
  begin  : () -> TxId
  commit : TxId -> ()
  abort  : TxId -> Str -> ()
}

atomic : Tx a -> Result[a, Str]
atomic prog = handle Tx
  begin()   = pure (TxId next())
  commit(id)= void (db.commit(id))
  abort(id, why) = void (db.rollback(id)) *> throw Err why
in prog
```

这就是"雨 / 伞 / 天气"：**同一个程序，在不同处理器下是纯函数、状态机、测试桩或数据库会话。**

## 9. 线性资源的真实用例

```
// 线性资源 + 状态机传递：编译器保证 handle 一定被 close
compile : ![Text] -> !Report -> IO ()
compile src out =
  let ast = parse(src)?            // src 被消费
  in codegen ast |> writeTo(out)   // out 被消费

// 作用域结束时会插入隐式 close；若你已手动 close，编译器消除它（零开销 RAII 风格的编译期版本）
```

标准库中标记为线性的：`!Fd`、`!Socket`、`!Mutex`、`!Rng`、`!Cursor`、`!Timer`、`!Channel`。

## 11. 宏（卫生、可读、不可误用）

```
macro while(cond, body) =
  `let rec loop () =
     if (quote cond) then do { (quote body); loop() }
  loop()`

macro trace(expr) =
  `let v = (quote expr)
   in Log.emit("var " ++ nameOf v ++ " = " ++ show(v)) *> pure v`
```

* 卫生：捕获变量自动重命名，用户标识符不可被捕获。
* 宏展开可观测：`su expand file.sun`。
* 宏不能定义类型，不能逃逸作用域（除了 `macro_export` 显式标记）。

## 12. 完整示例（一）：带状态 + 错误 + 线性 IO 的账本

```
module ledger

use std.text
use std.list
use std.io

effect Ledger = {
  post : Account -> Money -> ()
  total: Account -> Money
}

type Account = { id: Text }
type Money  = { cents: Int }

money(c) = { cents = c }

atom : !Fd -> Ledger Unit -> IO (Result[Unit, Str])
atom logfile prog =
  with state (Map.empty), throws[Str]:
    let ls = handle Ledger
      post a m = do
        cur = get()
        when (balance cur a < m) *> throw ("透支: " ++ a.id)
        put (credit cur a m)
        io.writeln(logfile, format("%s +%d -> %d", a.id, m.cents, balanceOf cur a))
      total a = balance get() a
    do
      res = prog
      io.flush(logfile)               // logfile 被消费 → 自动 close
      pure (res?)

transfer : Money -> Account -> Account -> Ledger Unit
transfer m from to = do
  post from m
  post to (money (-m.cents))

main : IO ()
main = atom (io.open "ledger.log") do
  transfer (money 500) { id = "alice" } { id = "bob" }
  transfer (money 200) { id = "bob" }   { id = "carol" }
```

读法：全程没有异常、没有 `mutate`、没有 `null`、没有手写 `close`、没有未检查的字典访问（`get()` 返回 `Option`，处理器里对 `get()` 的读取被 `throws`+穷尽匹配保护）。

## 13. 完整示例（二）：JSON 解析器（~40 行）

```
module json

use std.text

type Json = Null | Bool(bool) | Num(f64) | Str(Text) | Arr([Json]) | Obj([(Text, Json)])

parse : Text -> Result[Json, Str]
parse t = match tokenize t
  []        => throw "空输入"
  ts        => do
    (v, rest) <- value(ts)?
    match rest
      []    => pure v
      _     => throw "尾部垃圾: " ++ rest.head?

tokenize : Text -> [Token]
tokenize = chars |> filter (not . isSpace) |> lex Numbers, Strings, Symbols, Names

value : [Token] -> Result[(Json, [Token]), Str]
value ts = match ts
  [Null,     ..r] => pure (Null, r)
  [True,     ..r] => pure (Bool true, r)
  [False,    ..r] => pure (Bool false, r)
  [N n,      ..r] => pure (Num n, r)
  [S s,      ..r] => pure (Str s, r)
  [LBracket, ..r] => do
    items <- many(r) (value)                // 递归解析列表（无 while）
    match items
      (_, [RBracket, ..rest]) => pure (Arr(map fst items), rest)
      _ => throw "缺 ]"
  [Name n, ..r] => do
    pairs <- many(r) (pair)
    ...
```

"无循环"在这里并非负担：递归天然给出终止性证明的可能，也让 `?` 错误传播成为一行语法。

## 14. 编译管线

```
源码
 │ 1. 词法 + 布局算法（禁止缩进歧义，禁止 Tab/空格混用）
 │ 2. 递归下降解析 → AST
 │ 3. 展开：宏（卫生重命名）→ 推导式 desugar → do-notation desugar → 效果 sugar
 │ 4. 类型检查：HM 推断 + 单态化 + 行多态 + **线性（oneshot）检查器** + 穷尽性
 │ 5. 消去：类型类 → 字典调用；内联记录 → 移/复；闭包 → lambda lifting
 │ 6. 模式匹配 → decision tree（行/列去重，最小 case 数）
 │ 7. ANF + CPS（仅在 effect 需要时）→ defunctionalize 续延（one-shot 快路径）
 │ 8. 后端：LLVM IR（LLVM 15+），或 Wasm / 自研解释器
 ▼
运行时：3 KB（调度器、GC 钩子、I/O 事件循环）
```

* **效应实现**：one-shot 效果零成本（内联成状态机的直接调用）；multi-shot 效果才分配续延对象。编译器自动判定。
* **GC**：默认引用计数 + 代际晋升（不可变 + 结构共享 ⇒ RC 无循环）；`--gc=mark-sweep` 可切换。
* **尾递归**：所有 `tail` 位置识别，包括经由 `fold`/`zip` 的库函数；无栈溢出。
* **诊断**：错误信息带"路径"，例如 `here → in fold → in render`，像一张地图（对应"脚注 / 索引 / 地图"）。

## 15. 语法概要（EBNF 精简）

```
Program    = { Decl }
Decl       = TypeDecl | FunDecl | ValueDecl | InstanceDecl | EffectDecl | ModuleDecl
FunDecl    = Ident { Ident } [ ":" Type ] "=" Expr
TypeDecl   = "type" Ident [TypeParams] "=" Constr { "|" Constr }
Constr     = Ident [TupleArgs] [RecordFields]
Expr       = Lambda | Match | Do | If | Let | Pipe | BinOp | App | Lit | Ident | "(" Expr ")"
Match      = "match" Expr Newline Arms
Arm        = Pattern [ "if" Expr ] "=>" Expr
Do         = "do" Newline (Stmt Newline)+        Stmt = Pat "<-" Expr | Expr
EffectDecl = "effect" Ident "=" "{" { OpSig } "}"
Handle     = "handle" Effect Arms "in" Expr
Modality   = Type [ "!" ]                          // 线性标注
```

## 19. 一段宣言

> 编程是一场装配。
> 我们用循环造出会散架的机器，用异常掩盖会出错的地方，用命名约定代替类型证明，用 `null` 换取"看起来简洁"的三行代码。
>
> 榫语言相信另一种工艺：**每个值都不可变，因此可以随意复制；每个资源都线性，因此必然有唯一的归属；每个副作用都是类型，因此可以被读、被审、被替换成测试；每个模式都穷尽，因此未来新增一种形状时，编译器会替你喊出所有需要修改的地方。**
>
> 不需要一根钉子。不需要一次运行时惊吓。
> 只要接口对得上，木头自己会咬住木头。
