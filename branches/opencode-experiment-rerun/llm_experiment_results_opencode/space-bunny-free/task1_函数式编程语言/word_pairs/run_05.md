# 语言设计：**涟（Lian）**

> 编译器 `ripplec` · 包管理器 `tide` · 运行时 `Stratum`
> 一句话：**一门"效果写进类型、流动写进语法、资源写进线性"的纯函数式语言。**

## 0. 灵感溯源

## 1. 六条设计原则

1. **纯度是默认，效果是显式的**：`pure` 不可做 I/O；一切副作用必须出现在类型的效果行里。
2. **全性（totality）默认开启**：穷尽匹配 + 终止性检查由编译器保证；逃生舱需显式标注。
3. **可组合优于可配置**：没有宏副作用、没有运算符重载歧义、没有隐式转换。
4. **零成本抽象有名字**：每个特性都标注"它编译成什么"（表驱动 / defunctionalize / state-passing / LLVM intrinsic）。
5. **能力即安全边界**：模块签名里的 `!{Net}` 就是沙箱许可。
6. **活代码（live coding）是一等公民**：REPL 重编译保留状态。

## 3. 核心特性

### 3.1 效果行（Effect Rows）—— `!{Net | Time | ρ}`

```lian
//            参数        返回值         所需能力
fetch : Url -> Body ! {Net, Log}

mean : [Float] -> Float ! { }
```

* 效果集合是开放行多态：`!{Net | ρ}`，行多态变量可被特化。
* 效果 = 能力 = 安全边界。模块头声明 `needs !{Net, Fs}`，调用方看得见。
* **无异常**：失败建模为 `!{Throw}`；可被 handler 转成值、可被序列化、跨线程可传递。
* **可升可降**：effect weakening/subtyping 是行包含关系，因此 `pure` 可以在任何地方。

### 3.2 代数效果 + 深度 Handler

```lian
effect Emit { emit :: a -> Void }

log : a -> Void ! {Emit a}
log x = emit x

// 截流：把日志收集成列表，且对 log 递归透明
collect : (Emit a => b) -> b -> [a]
collect, k = handle effect { emit a => k [a] } ()
```

```lian
// 状态：编译器把 ! {St s} 消解为 (s -> (a, s))
run_state : S -> (S -> A ! {St S} -> A) -> A
```

### 3.3 流式为一等公民（Stream）

`Stream a` 是尾递归函数 `() -> Step a` 的语法糖；`<>` 是流拼接，`yield` 是发射。

```lian
fibs : Stream Nat
fibs = go 0 1 where
  go a b = yield a <> go b (a + b)

// 管道：中间流不做 list，不做闭包链，只做状态机融合
pipeline : Stream Nat
pipeline = fibs
        |> filter (\n -> n % 2 = 0)
        |> map (\n -> n * n)
        |> take 10
        |> fold 0 (+)
```

**背压内置**：`Stream` 与异步 handler 组合时自动获得背压与取消（`!{Cancel}` 效果）。

### 3.4 线性 / 仿射类型 —— 资源不泄漏

```lian
type File =^ 1            // "恰好用一次"的线性类型

withFile : Path -> (File -> a ! {Fs}) -> a ! {Fs}
withFile, p, k = do
  h <- open p             // h : File（线性）
  defer (close h)         // 保证被消费
  k h
```

* 支持 `0`（任意丢弃）、`1`（恰好一次）、`n`（至多 n 次）多重性。
* 缓冲区、句柄、锁、Pin、线性内存全部免 GC（`Ptr` 为仿射，直接映射到 LLVM 分配）。
* 借用检查器（borrow checker）风格诊断：`buffer` 被移动后再次使用 → 精确报错位置。

### 3.5 双向类型推断 + 渐进类型

```lian
load : Text -> Any          // 动态边界
load = read_unchecked _
```

* 推断方向由使用点引导（bidirectional），模式匹配驱动细化。
* 模糊量词 `_?`；`Any` 的每个操作在编译期插入**契约检查点**（运行时零成本移除，编译期可证明时永不移除）。
* 效果行推断与类型推断**同步进行**：错误信息直接告诉你要补哪个能力。

### 3.6 编译期求值与 Quotation（活体宏）

```lian
quotation [ | expr | ]          // 语法树作为一等值
splice  e                        // 插入

constFold : Expr -> Expr
constFold, e =
  match e with
  | Bin + , Lit a, Lit b -> Lit (eval a + eval b)
  | _                    -> e

main : Unit ! {Log}
main = print (constFold [| 1 + 2 * 3 |])   -- 常量折叠在编译期完成，运行时不产生代码
```

* 编译期求值 sandbox：`stage` 函数可把一段程序当宏执行（纯效果子集 `!{}` 保证无副作用）。
* 库可提供 `[| match x with ... || ]` 式的宏，**不破坏任何类型安全保证**。

### 3.7 视图（Views）—— 双向更新的免费午餐

```lian
view (user :: addr.city)     // 生成 get/set 一对纯函数，无闭包层级爆炸
```

### 3.8 量纲与单位

```lian
dist : Dim 1 -> Dim 1 -> Dim 1
speed = dist / time           // 类型检查器推出 Dim (1/-1)
fps : Dim (-1)                // 帧率就是"每秒 N 次"
```

### 3.9 并发即效果

```lian
worker : Job -> Result ! {Net, Chan}

main : Unit ! {Chan, Net}
main = do
  q <- chan 64                        // 带容量 → 自然背压
  spawn (worker q)                    // 效果自动传播到子任务
  for j <- jobs do q.send j
  await q.recv
```

* 无 `async/await`，无线程 API：`spawn` / `chan` / `select` 都是效果组合子。
* Work-stealing 调度器；结构化并发（`scope`），不允许孤儿任务。

## 4. 类型与效果语法（BNF 摘录）

```
τ  ::=  tcon | α | τ -> τ ! ρ
     |  { l : τ .. τ, .. }            -- 记录（可带 .. 开放字段）
     |  μ α . τ                        -- 递归类型
     |  Any                             -- 渐进边界

ρ  ::=  ε                              -- 纯
     |  E | ρ                          -- 具体效果
     |  α                              -- 开放行变量
     |  ν.ρ                            -- 行约束（α ⊆ ρ）

λ  ::=  (τ, τ, ...) -> τ ! ρ          -- 参数级效果标注（可选）
```

子类型规则（行包含 + 多态）：
`! {Net, ρ} <: ! {ρ'}` 当 `ρ ⊆ ρ'`（通过 row-leaving / unification 求解）。

## 5. 运行时与编译管线

```
源文件 → 解析(缩进) → 名字解析 → 双向推断(类型+效果行)
     → 全性检查(覆盖性 + 终止性) → 线性检查
     → quotation 展开(编译期求值) → 优化 → 中间表示
```

| 阶段 | 关键技术 |
|---|---|
| **函数表示** | 闭包转换 → **defunctionalization 的 handler**，再 **state-passing style** 消解 `St` / `Writer`，得到可优化的一等 CPS |
| **模式匹配** | 决策树 + 跳转表 + 字符串 switch；穷尽性在编译期证明 |
| **流** | 环形缓冲区 + 迭代器融合（fuse pass），中间流零分配 |
| **线性数据** | LLVM arena / 栈区分配，绕过 GC |
| **后端** | LLVM 17 → 原生；Wasm 后端（保留效果与 handler 语义） |
| **REPL** | 增量 GC 代码补丁，`reload` 保留堆上状态 |

**性能目标**：手写优化基线（`unsafe partial` 局部）100%，纯 handler 开销在特化后 < 5%，Fibonacci 1e8 项单线程 < 1.2s。

## 8. 一段完整示例

```lian
module Ripple.Demo

import Stream, IO, Sys

type Sensor = { id: Nat, temp: Dim 1 }

effect Alarm { alarm :: Sensor -> Void }

monitor : [Sensor] -> Stream Nat ! {Alarm, Log}
monitor, ss = ss
  |> filter (\s -> s.temp > 30)
  |> tap   (\s -> alarm s)
  |> map   (\s -> s.id)

-- 效果处理器：把 alarm 转成日志，并保证异常转为值
safe : Stream Nat ! {Alarm, Log, Throw} -> [Result Nat]
safe, st = handle effects
  handle effect { alarm s => log s.id >> resume }
  handle effect { Throw e => yield (Err e); resume }
  st |> to_list

-- 线性资源 + 并发
collect : [Sensor] -> [Result Nat] ! {Net, Chan, Fs, Log}
collect, ss = do
  scope $ do
    r <- chan 32
    spawn (fetch_all ss >>= r.send)
    for s <- r.recv do log s
  withFile "log/alarms.txt" \h -> write h (render (safe (monitor ss)))
```
