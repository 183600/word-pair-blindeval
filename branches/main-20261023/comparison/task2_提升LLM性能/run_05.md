## 回答 A（cleaned_word_pairs）

# 从这些词获得的灵感：零训练成本提升LLM性能的方法

**1. 回声-验证 / 复盘-反思 → Self-Consistency 与自反思**
让模型对同一问题采样多次，投票取多数答案；或让模型先作答再自我批判修正。纯推理时计算，零训练。

**2. 脚手架-支撑 / 阶梯-递进 → 提示工程升级**
- Chain-of-Thought（思维链）：要求"逐步推理"
- Few-shot 示例：给3~5个"乐谱-规范"式范例
- 角色设定（"棋子-角色"）：赋予专家身份
- 结构化输出模板（"模板-复用"）

**3. 陪审团-裁决 / 合议-共识 → 多模型/多角色集成**
让一个模型扮演生成者、批评者、裁判（辩论-交锋），或并行调用多个模型互相评审，取共识答案。

**4. 索引-检索 / 图书-分类 → RAG检索增强**
外挂知识库，把"试错"变成"查表"。低成本解决幻觉和知识过时问题，是性价比最高的手段之一。

**5. 滤网-净化 / 筛子-过滤 → 输入输出前后处理**
- 输入端：清洗、去噪、补充上下文（"高汤-底蕴"）
- 输出端：规则校验、格式检查、二次过滤（"校对-纠错"）

**6. 阀门-控制 / 火候-掌控 → 解码参数调优**
temperature、top-p、repetition penalty、max tokens 的精细调节——零成本，效果立竿见影。事实性任务调低温度，创作类调高。

**7. 分解-棱镜 / 刀工-精细 → 任务拆解（Agent化）**
把复杂任务拆成子任务流水线，每步单独提示、单独验证（"滴灌-精准"），远好于一次性提问。

**8. 缓存-蓄电池 → 结果缓存与复用**
相似查询直接命中缓存，既降成本又保证一致性。

**9. 体检-筛查 / 审计-核查 → 评测驱动迭代**
建立小型评测集，用数据定位短板，针对性改提示词——"把脉-诊断"后再"药方-对症"。

**10. 杠杆-撬动 → 换用更强的API/开源模型**
不训练≠不换模型。直接升级到更新的开源权重（如蒸馏版大模型），往往是最便宜的"性能提升"。

**核心思想**：像"催化剂"一样——不改变自己的参数，而是通过**更好的输入、更聪明的推理流程、外部知识与工具、多重验证机制**来放大现有模型的能力。

## 回答 B（baseline）

# 不训练、低成本提升 LLM 性能的实用方法

## 一、提示词工程（成本最低，收益最直接）

**1. 思维链（Chain-of-Thought）**
- 加上"让我们一步一步思考"（Let's think step by step）
- 对推理、数学、逻辑任务提升非常明显

**2. Few-shot 示例**
- 在 prompt 中给 2~5 个输入输出示例
- 让模型"照猫画虎"，格式和风格立刻稳定

**3. 角色设定 + 明确指令**
- "你是一位资深XX专家"
- 明确输出格式、长度、约束条件（如"只输出 JSON"）

**4. 任务分解**
- 复杂任务拆成多步，分多次调用
- 例如：先提取要点 → 再分析 → 最后总结

## 二、推理时计算（Inference-time Scaling）

**1. 自洽性（Self-Consistency）**
- 同一个问题采样多次（temperature>0），取多数投票的答案
- 成本：多调用几次 API，但准确率提升显著

**2. 自我反思/验证**
- 让模型生成答案后，再问一次"请检查上述答案是否有误并修正"
- 简单的"生成→批评→修正"循环

**3. 提示模型先复述问题**
- 减少理解偏差，"请先复述你对任务的理解，再作答"

## 三、外部知识增强

**1. RAG（检索增强生成）**
- 把相关文档检索出来塞进 prompt，解决知识过时、幻觉问题
- 不需要微调，只需向量数据库 + embedding

**2. 提供上下文而非依赖记忆**
- 直接把参考资料、数据、代码贴进 prompt
- 模型"开卷考试"远好于"闭卷考试"

## 四、参数调优

| 参数 | 建议 |
|------|------|
| temperature | 事实/代码任务设 0~0.3；创意任务 0.7~1.0 |
| top_p | 与 temperature 二选一调整 |
| max_tokens | 给足空间，避免答案被截断 |
| 系统提示词 | 充分利用 system role 设定行为规范 |

## 五、工程层面

**1. 结构化输出**
- 用 JSON schema / function calling 约束输出，减少解析错误

**2. 路由策略**
- 简单问题用小模型，难问题用大模型（成本降 80%+，性能不降）

**3. 缓存**
- 相同/相似请求命中缓存，省钱又提速

**4. 评估驱动迭代**
- 建一个小评测集（哪怕 50 条），每次改 prompt 都跑一遍，用数据说话而不是凭感觉

## 性价比排序（我的建议）

1. ⭐⭐⭐ 思维链 + Few-shot（几乎零成本）
2. ⭐⭐⭐ RAG（解决知识类问题最划算）
3. ⭐⭐ 自我验证 + 任务分解
4. ⭐⭐ 参数调优 + 模型路由
5. ⭐ Self-consistency（有效但成本成倍）

**核心思想：把"让模型一次猜对"变成"给模型好条件、好工具、多次机会"。** 大多数场景下，精心设计的 prompt + RAG + 简单验证流程，效果可以逼近甚至超过微调。
