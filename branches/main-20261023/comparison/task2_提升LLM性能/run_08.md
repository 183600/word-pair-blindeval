## 回答 A（baseline）

# 不训练也能大幅提升 LLM 效果的实用方法

## 一、提示词工程（成本几乎为零，收益最大）

**1. 结构化提示词**
- 明确角色、任务、约束、输出格式
- 用分隔符（```、XML 标签）区分指令和数据，避免注入混淆

**2. Few-shot 示例**
- 给 2~5 个高质量输入输出示例，效果常超过微调小模型
- 示例要覆盖边界情况，格式严格一致

**3. 思维链（Chain-of-Thought）**
- 加一句"让我们一步步思考"，推理类任务准确率可提升 10~30%
- 或明确要求"先分析，再给结论"

**4. 输出格式约束**
- 要求输出 JSON/表格，配合 schema 说明，减少解析错误

## 二、推理时计算（Inference-time Scaling）

**1. Self-Consistency（自一致性）**
- 同一问题采样 5~10 次（temperature 调高），投票取多数答案
- 数学、逻辑题效果显著

**2. 任务分解**
- 复杂任务拆成多步调用，每步输出作为下步输入
- 比单次长提示更稳定

**3. 自我反思/验证**
- 让模型生成答案后，再发一轮"检查上面的答案是否有误并修正"

## 三、RAG（检索增强生成）

- 把知识库/文档切块，用向量检索召回相关片段塞进上下文
- 解决幻觉和知识过时问题，无需重新训练
- 低成本方案：BM25 关键词检索 + 简单重排即可起步

## 四、参数与系统工程

| 手段 | 说明 |
|---|---|
| 调低 temperature | 事实性任务设 0~0.3，减少胡编 |
| 系统提示词兜底 | 写明"不知道就说不知道"可显著降幻觉 |
| 上下文管理 | 关键信息放开头或结尾（模型对中间内容容易遗忘） |
| 缓存 | 相同前缀/重复查询用缓存，省钱又提速 |
| 路由策略 | 简单问题用小模型，难题用大模型 |

## 五、工具增强（Agent 化）

- 计算交给代码执行器，搜索交给搜索引擎
- 模型只做规划和判断，绕开其算术/实时信息短板

## 性价比排序建议

1. **先做**：优化提示词 + few-shot + CoT（零成本，见效最快）
2. **再做**：RAG（解决知识类问题）
3. **最后**：self-consistency、多步分解、工具调用（成本略高但效果强）

需要的话，我可以针对你的具体场景（比如客服、代码生成、文档问答）给出更具体的方案。

## 回答 B（cleaned_word_pairs）

低成本、不额外训练就能明显提升现有 LLM 的核心思路是：**把“模型能力”改成“系统工程”**。优先级建议如下：

1. **先立输出契约**：系统提示写清角色、边界、格式、拒答条件、引用要求；用 JSON Schema/正则/枚举做硬校验，不合格自动重试。  
2. **RAG 做扎实**：查询改写 + HyDE + BM25/向量混合召回 + 重排 + 去重 + 引用约束；上下文只放证据，不放垃圾。  
3. **动态 few-shot**：按当前问题相似度选 2-5 个黄金示例，比固定提示更稳。  
4. **解码调参**：事实任务低温、低 top_p；创意任务再放开；设 stop、max_tokens、重复惩罚；能种子复现就固定种子。  
5. **把计算外包**：数学、日期、单位、代码、SQL、正则交给工具/解释器；模型负责理解与表达，不负责硬算。  
6. **两遍生成法**：草稿 → 规则/清单校验 → 最小修订；只校验关键错误，成本远低于全量重生成。  
7. **路由与级联**：小模型/规则先处理简单请求，难例再上大模型；设置置信度、成本、延迟阈值。  
8. **缓存与记忆**：语义缓存相似问题；会话历史做摘要；长期记忆只存可复用事实和偏好。  
9. **评估闭环**：建 100-500 条黄金集，记录错误分桶；每次只改一个变量，A/B 验证，防止“提示玄学”。  
10. **安全与合规前置**：注入防御、脱敏、权限、来源与置信度标注；减少返工和事故成本。

最快落地顺序：**输出契约 + 校验重试 → RAG 上下文治理 → 工具化计算 → 动态 few-shot → 缓存路由 → 黄金集回归**。通常不改模型权重，就能在准确率、稳定性、成本和延迟上同时拿到收益。
