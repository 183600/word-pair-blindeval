## 回答 A（baseline）

# 不训练模型，低成本提升LLM性能的实用方法

## 一、Prompt工程（成本最低，见效最快）

1. **Few-shot示例**：给2-5个输入输出样例，效果常提升10-30%
2. **Chain-of-Thought（思维链）**：加一句"让我们一步步思考"，数学/推理任务显著提升
3. **角色设定**："你是一位资深XX专家"，明确任务边界和输出格式
4. **结构化输出**：要求输出JSON/XML，减少解析错误和跑题
5. **自我反思**：让模型先回答，再"检查你的答案是否有误并修正"（Self-Refine）
6. **任务分解**：复杂任务拆成多个简单子任务分步执行

## 二、推理时计算（Inference-time Scaling）

1. **Self-Consistency**：同一问题采样多次，取多数投票答案，简单有效
2. **Best-of-N**：生成多个候选，用规则/另一个模型/打分prompt选最好的
3. **Tree of Thoughts**：对复杂问题做搜索式推理
4. 代价是推理token变多，但不需要任何训练

## 三、RAG（检索增强生成）

- 把知识库/文档向量化，检索相关内容塞进prompt
- 解决幻觉、知识过时、私有数据问题
- 关键点：**分块策略、混合检索（关键词+向量）、重排序（rerank）**比换模型提升更大

## 四、上下文优化

1. **重要信息放开头或结尾**（模型对中间内容注意力弱，"lost in the middle"）
2. **清理无关上下文**：减少干扰信息比堆更多信息更有效
3. **长对话定期总结压缩**，避免超出有效上下文

## 五、系统层面技巧

1. **温度调参**：事实性任务temperature=0，创意任务调高
2. **输出校验+重试**：格式错误自动重试，加约束解码（如JSON schema约束）
3. **模型路由**：简单问题用小模型，难问题用大模型，省钱又提效
4. **缓存**：相似问题命中缓存，降本提速
5. **工具调用**：计算交给计算器/代码执行，搜索交给搜索引擎——LLM不擅长的别让它硬算

## 六、组合策略（性价比最高的实践路径）

```
Prompt优化（CoT + few-shot）
    + RAG（解决知识问题）
    + 输出校验重试（解决稳定性）
    + Self-consistency（关键任务加投票）
```

这套组合通常能让GPT-3.5级别的模型在很多任务上逼近更大模型的表现，成本只有API调用费的少量增加。

**建议优先级**：先优化prompt和RAG（免费），再加校验重试（便宜），最后对关键任务加self-consistency（按价值付费）。需要针对你的具体场景细化哪个方向吗？

## 回答 B（cleaned_word_pairs）

# 低成本、无需训练大幅提升LLM性能的方法

从上面词组中提炼出几条核心路径，按性价比排序：

## 一、提示工程（成本≈0，收益立竿见影）
- **思维链（CoT）**：让模型"分步推理"，数学题、逻辑题准确率可提升20-40%
- **少样本示例（Few-shot）**：给3-5个高质量示例，格式遵循和领域表现大幅改善
- **系统提示+角色设定**：明确任务边界、输出格式、语气风格
- **结构化输出**：强制JSON Schema，减少解析失败

## 二、推理时计算扩展（Test-time Compute，不训练只多花token）
- **自洽性（Self-Consistency）**：采样多次取多数投票，简单有效
- **反思/自我修正**：让模型先生成、再批判、再改进
- **思维树/规划分解**：复杂任务拆成子问题逐个求解
- **验证器筛选**：用规则、单元测试或另一个模型当"评委"选最佳答案

## 三、RAG检索增强（解决幻觉和知识过期）
- 查询改写 + 混合检索（关键词+向量）+ 重排序
- 好的分块策略和元数据过滤比换大模型更有效
- 引用溯源强制模型"有据可依"，抑制幻觉

## 四、工程与系统优化
- **提示缓存/KV复用**：相同前缀不重复计算，降本又提速
- **模型级联**：小问题走小模型，难题才调大模型，成本降50-90%
- **工具调用**：计算交给计算器、代码交给解释器，避开LLM弱项
- **输出校验+重试**：格式错误自动重试，成功率接近100%

## 五、数据飞轮（长期复利）
- 收集失败案例 → 归因分析 → 转化为Few-shot示例或评估集
- 用A/B测试和自动评测持续迭代提示词版本

**核心结论**：大多数场景下，"好提示 + RAG + 多次采样投票 + 验证重试"的组合，可以让一个中等模型达到接近更大模型的效果，成本只是API调用的零头。
