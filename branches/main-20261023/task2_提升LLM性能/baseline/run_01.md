# 低成本提升 LLM 性能的实用方法

## 一、提示工程（零成本，收益最大）

**1. 思维链（Chain-of-Thought）**
- 加上"让我们一步步思考"，推理任务准确率可提升 10-30%
- Few-shot CoT：给 2-5 个带推理过程的示例效果更好

**2. 结构化提示**
- 明确角色、任务、输出格式、约束条件
- 用 XML/Markdown 标签分隔指令与内容（如 `<context>...</context>`）

**3. 自我反思与验证**
- 让模型先回答，再"检查你的答案是否有误并修正"
- Self-Consistency：采样多次取多数投票（成本略增但效果显著）

## 二、检索增强（RAG）

- 把相关知识塞进上下文，解决知识过时和幻觉问题
- 低成本方案：向量库（FAISS/Chroma）+ BM25 混合检索
- 关键优化点：chunk 切分策略、重排序（rerank）、查询改写

## 三、解码策略调优（完全免费）

- 事实性任务：temperature 调低（0~0.3）
- 创意任务：适当调高
- 重复问题：调 repetition_penalty / frequency_penalty
- 长输出：合理设置 max_tokens 避免截断

## 四、上下文工程

- **信息放对位置**：关键信息放开头或结尾（模型对中间内容易"迷失"）
- **减少噪声**：删掉无关上下文，长上下文≠好效果
- **Prompt Caching**：重复的系统提示用缓存（如 Claude/DeepSeek 支持），省 50-90% 成本

## 五、任务拆解与流程设计

- 复杂任务拆成多步调用，每步简单明确
- 用"生成→评审→修改"的多轮流水线替代单次生成
- 简单任务用小模型，难任务用大模型（路由策略降本）

## 六、输出约束

- 用 JSON Schema / 正则约束输出格式（如 vLLM、Outlines 的 guided decoding）
- 减少解析失败导致的下游错误

## 优先级建议

| 方法 | 成本 | 典型收益 |
|------|------|---------|
| 优化提示词 | 零 | ⭐⭐⭐⭐ |
| 解码参数调优 | 零 | ⭐⭐ |
| RAG | 低 | ⭐⭐⭐⭐（知识类任务） |
| 任务拆解 | 低 | ⭐⭐⭐ |
| Self-consistency | 中（多次调用）| ⭐⭐⭐（推理任务）|

**一句话总结**：先从提示词和上下文工程入手（免费且见效最快），知识类问题加 RAG，推理类问题用 CoT + 多采样投票。
