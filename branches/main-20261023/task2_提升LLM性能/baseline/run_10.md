# 不训练、低成本提升 LLM 性能的实用方法

## 一、提示词工程（成本最低，见效最快）

1. **Few-shot 示例**：给 2~5 个高质量输入输出示例，效果常胜过微调
2. **思维链（CoT）**：加"让我们一步步思考"，数学/推理任务提升显著
3. **角色设定 + 明确约束**：指定角色、输出格式、评分标准
4. **自我反思/自我批评**：让模型先输出，再让它检查并修正自己的答案
5. **任务分解**：复杂任务拆成多步，分多次调用，每步单独验证

## 二、推理时计算（Test-time Compute）

1. **Self-Consistency**：同一问题采样多次（temperature>0），多数投票取答案，推理任务可提升 5~15%
2. **Best-of-N**：生成多个候选，用规则/另一个模型/奖励模型选最好的
3. **Tree of Thoughts / 多路径探索**：适合规划、逻辑类任务
4. **验证器筛选**：能用代码验证的任务（如数学、代码），直接跑测试用例过滤错误答案

## 三、RAG（检索增强生成）

- 把领域知识、文档放入向量库，检索相关片段注入上下文
- 解决幻觉、知识过时、私有数据问题，**性价比极高**
- 优化点：chunking 策略、混合检索（关键词+向量）、重排序（rerank）

## 四、解码参数调优（零成本）

- 确定性任务：temperature 设为 0 或接近 0
- 调整 top_p、repetition_penalty
- 设置合理的 max_tokens 和 stop 序列
- 结构化输出：用 JSON schema / 约束解码（如 outlines、guidance）保证格式正确

## 五、系统层面优化

1. **模型路由**：简单问题用小模型，难问题用大模型（省成本且整体效果更好）
2. **提示词缓存**（prompt caching）：重复的系统提示可省 50~90% 费用
3. **输出后处理**：正则校验、格式修复、规则兜底
4. **集成多个模型**：不同模型答案互相验证/投票

## 六、上下文管理

- 关键信息放在开头或结尾（模型对中间内容注意力弱，"lost in the middle"）
- 精简上下文，去掉无关内容，长上下文反而降低性能
- 多轮对话中适时总结压缩历史

## 优先级建议

| 方法 | 成本 | 收益 | 适用场景 |
|------|------|------|----------|
| 提示词优化 | 极低 | 中高 | 所有 |
| 解码调参 | 零 | 中 | 所有 |
| RAG | 低 | 高 | 知识密集型 |
| Self-consistency | 中（多倍推理） | 高 | 推理/数学 |
| 自我反思 | 中 | 中高 | 写作/代码 |
| 模型路由 | 低 | 中 | 混合负载 |

**一句话总结**：先用好提示词 + 解码调参（免费），再加 RAG（解决知识问题），最后用多次采样+投票（解决可靠性问题），通常能榨出模型 80% 以上的潜力。
