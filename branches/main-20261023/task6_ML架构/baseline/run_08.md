# 分形记忆 Transformer(Fractal Memory Transformer, FMT)

## 核心动机

现有 Transformer 的两个瓶颈:
1. **KV Cache 线性增长** —— 长上下文推理成本爆炸
2. **静态参数** —— 训练完成后知识固化,无法在线学习

FMT 通过**分形结构的层级记忆**解决这两个问题。

---

## 架构设计

### 1. 分形记忆层级(Fractal Memory Hierarchy)

模仿人脑记忆的时间尺度分层:

```
层级 L0:工作记忆(标准注意力窗口,如 4K tokens)
层级 L1:短期记忆(压缩摘要块,每个块代表 16 个 token)
层级 L2:长期记忆(再压缩 16 倍)
层级 L3:情景记忆(可学习的"记忆槽",类似向量数据库)
```

关键创新:**每一层本身是下一层的"缩小版"**(分形自相似),用同一套注意力机制处理不同粒度,无需为每层单独设计模块。

### 2. 压缩-检索双通路

- **压缩路径(写入)**:超出 L0 窗口的 token 通过一个轻量"压缩器"(cross-attention 到少量摘要 token)写入 L1;L1 满了再压缩进 L2,递归进行。
- **检索路径(读取)**:当前查询同时对各层做注意力,用**可学习的路由门控**决定从哪个时间尺度取信息:

$$y = \sum_{k=0}^{3} g_k \cdot \text{Attn}(q, M_k), \quad g = \text{softmax}(W_g q)$$

### 3. 慢速权重更新(Slow Weight Adaptation)

借鉴 Test-Time Training 思想:L3 情景记忆槽在推理时通过**单步梯度下降**更新,让模型在部署中持续积累经验,且更新幅度受信任门控限制,防止灾难性遗忘。

### 4. 复杂度分析

| | 标准 Transformer | FMT |
|---|---|---|
| 注意力复杂度 | O(n²) | O(n·log n) |
| 内存占用 | O(n) | O(log n) 活跃 + 压缩存储 |
| 在线学习 | ✗ | ✓ |

---

## 训练策略

1. **多尺度重建损失**:要求每一层的压缩表示能重建下一层内容,保证信息保真
2. **课程式上下文扩展**:从短上下文开始,逐步拉长,让压缩器学会分层抽象
3. **记忆回放正则化**:防止慢速权重更新导致遗忘

## 潜在应用场景

- 百万级 token 的文档/代码库理解
- 终身学习的对话智能体
- 边缘设备上的低内存推理

## 主要风险

- 压缩是有损的,精确检索(如"第 3 页第 2 个数字")可能退化 → 可混合稀疏精确索引缓解
- 慢速权重更新的稳定性需要大量消融实验
