## 回答 A（baseline）

# 不训练模型、低成本提升 LLM 表现的实用方法

## 一、Prompt 工程(成本最低,收益最直接)

1. **思维链(CoT)**:加一句"让我们一步步思考",数学/推理任务提升显著
2. **Few-shot 示例**:在 prompt 里给 2~5 个输入输出示例,比零样本稳定得多
3. **角色与约束明确化**:明确角色、任务边界、输出格式(如"只输出 JSON")
4. **结构化 prompt**:用分隔符、XML 标签、Markdown 分节组织上下文
5. **让模型先规划再执行**:先输出计划/大纲,再生成正式内容

## 二、推理时计算扩展(Test-time Compute)

1. **Self-Consistency**:同一问题采样多次(温度>0),多数投票取答案,推理任务可提升 5~15%
2. **Best-of-N**:生成多个候选,用规则/另一个模型/模型自评挑最好的
3. **自我反思(Reflexion 式)**:让模型检查并修正自己的输出("请检查上述答案是否有误")
4. **分解复杂任务**:拆成多步调用,每步简单任务准确率更高

## 三、RAG(检索增强生成)

- 把领域知识、最新文档塞进上下文,解决知识过时和幻觉问题
- 低成本方案:embedding + 向量库(FAISS/Milvus),无需微调
- 注意 chunk 切分策略和召回质量,往往比换模型收益大

## 四、解码与工程优化

1. **调参数**:事实性任务用低 temperature(0~0.3);创意任务调高
2. **输出格式约束**:用 JSON schema / 正则约束解码(如 outlines、guidance),杜绝格式错误
3. **任务路由**:简单任务用小模型,难任务用大模型,成本降一半以上
4. **缓存**:相似查询命中缓存直接返回,省钱又提速
5. **工具调用**:计算交给计算器/代码解释器,搜索交给搜索引擎,别让模型硬算

## 五、组合策略(性价比最高的实践)

```
好 Prompt + Few-shot + RAG + 输出校验 + 失败重试/多采样
```

这套组合通常能把任务准确率提升 **20%~50%**,远超换一个大一档模型的收益,且零训练成本。

---

**建议优先级**:先优化 prompt 和加示例(1天见效)→ 加 RAG(解决知识问题)→ 加输出校验和重试(解决稳定性)→ 最后考虑 self-consistency 等推理时扩展(成本换质量)。

## 回答 B（cleaned_word_pairs）

# 低成本、无需训练大幅提升LLM性能的方法

从上面词对中提炼的核心思路：**杠杆、集成、反思、检索、分解、校准**。

## 一、Prompt工程（零成本，收益最快）

1. **思维链（CoT）**：加一句"让我们一步步思考"，推理任务提升显著
2. **少样本示例（Few-shot）**：给3~5个输入输出样例，对齐格式与风格
3. **角色设定**："你是一位资深X专家"，激活对应能力域
4. **结构化指令**：分点列出任务、约束、输出格式（如JSON schema）
5. **自我反思**：让模型先回答，再"检查上述答案的错误并修正"（反思/回声）
6. **先分解再执行**："先列出解决此问题的子步骤，再逐一完成"（分解/阶梯）

## 二、解码策略调优（只改参数）

7. **调低temperature**（0~0.3）用于事实/推理任务，减少胡言乱语
8. **Self-Consistency**：同一问题采样5~10次，投票取多数答案（投票/共识），数学题准确率可提升10%+
9. **调整top_p / 重复惩罚**，减少循环输出

## 三、检索增强（RAG）——性价比之王

10. 外挂知识库：向量检索+注入上下文，解决知识过时和幻觉（索引/检索）
11. 检索后**重排序（rerank）**提升上下文质量
12. 给模型"参考资料+要求引用来源"，强制有据可依

## 四、系统集成（脚手架/编排）

13. **多轮辩论/多智能体**：两个模型互相质疑，输出更稳健（辩论/陪审团）
14. **工具调用（Function Calling）**：计算器、代码解释器、搜索——把不擅长的外包
15. **路由分发**：简单问题走小模型，难问题走大模型，降本增效
16. **验证器兜底**：用规则/小程序校验输出（如代码能否运行），失败则重试（熔断/重试）

## 五、输出后处理

17. **多数投票集成**：多个prompt变体生成，取一致结果（冗余/容错）
18. **格式校验+自动修复**：JSON解析失败自动让模型修复
19. **缓存常见问答**：命中缓存直接返回，零成本零延迟（缓存/复用）

## 六、数据侧"免费午餐"

20. **清洗评测集**，很多时候"模型不行"其实是评测噪声
21. **动态few-shot**：根据当前问题检索最相似的历史样例注入prompt

---

**优先级建议**（投入产出比排序）：
> Prompt优化（1天）→ 解码参数+Self-Consistency（1天）→ RAG（1~2周）→ 工具调用/多智能体编排（按需）

核心思想一句话：**不改动模型权重，而是给模型配"镜子（反思）、地图（检索）、脚手架（编排）、陪审团（投票）"，用系统智慧替代训练成本。**
