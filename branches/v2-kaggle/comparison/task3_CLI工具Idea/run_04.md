# CLI 工具 Idea：`devlog` —— 开发者工作日志自动生成器

## 核心概念
一个命令行工具，自动从你的开发活动（git commits、分支切换、编辑的文件）中生成每日/每周工作日志和周报。

## 解决的痛点
- 开发者经常忘记记录自己做了什么，写周报/日报很痛苦
- 自由职业者需要给客户汇报工作内容和工时
- 准备绩效评估、面试时需要回顾自己的贡献

## 核心功能

```bash
devlog today          # 生成今天的工作摘要
devlog week           # 生成本周周报
devlog report --from 2024-01-01 --to 2024-03-31  # 自定义时间段
devlog init           # 初始化配置
```

## 实现思路（MVP）
1. **数据源**：扫描指定目录下所有 git 仓库的 commit 历史（按作者邮箱过滤）
2. **智能分组**：按项目、按类型（feat/fix/docs）归类 commits
3. **可选增强**：接入 LLM API，把零散的 commit messages 改写成通顺的工作总结
4. **输出格式**：Markdown / 纯文本，方便粘贴到任何地方

## 为什么适合独立开发者
- ✅ **技术门槛低**：核心是调用 `git log` + 文本处理，单文件脚本就能起步
- ✅ **自己就是用户**：dogfooding，需求理解深刻
- ✅ **可渐进增强**：从本地脚本 → 支持多数据源（GitHub API、Jira）→ LLM 润色
- ✅ **有变现空间**：基础功能免费开源，Pro 版提供 AI 总结、团队聚合、多格式导出
- ✅ **社区传播性好**：开发者工具容易在 HN、V2EX、掘金获得关注

## 差异化方向
- 支持中文输出（现有英文工具如 `standup` 类工具对中文支持差）
- 隐私优先：纯本地运行，数据不出本机
- 与主流 AI 编辑器/工具链集成

## 回答 B（cleaned_word_pairs）

**💡 CLI 工具 Idea：`devpulse` —— 开发者工作流健康仪表盘**

**灵感来源**：第3组（时间追踪）、第43组（提交统计）、第63组（TODO收集）、第101组（倒计时提醒）、第21组（番茄钟专注）

**一句话描述**：一条命令，汇总你本地开发环境的全景健康报告。

**核心功能**：
- `devpulse scan`：扫描当前项目，输出 Git 提交频率、未提交改动天数、积压 TODO/FIXME 数量、依赖过期情况、测试覆盖率变化趋势
- `devpulse focus`：内置番茄钟，自动记录每个项目的深度工作时间，与 Git 提交关联
- `devpulse stale`：找出本地超过 N 天没碰的"僵尸项目"和未推送的分支
- `devpulse report --week`：生成周报（Markdown），可直接粘贴到团队群或博客

**为什么适合独立开发者做 CLI**：
1. **纯本地运行**，无需服务器，零运维成本
2. 数据源都是现成的（Git 仓库、文件系统），不需要爬虫或第三方 API
3. 单机 MVP 一两周可完成，后续可加 TUI 界面、插件系统做差异化
4. 目标用户（开发者）就在终端里，获客渠道清晰（Hacker News、Reddit、掘金）
